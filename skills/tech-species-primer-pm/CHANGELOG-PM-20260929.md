# tech-species-primer-pm · v3.3-PM(2026-09-29)

由 tech-species-primer v3.2.0(用户 2026-09-29 上传的 .skill 包)派生,v3.2 的规格、脚本与数据纪律全部保留,在上面加一层白话。

## 起因:基金经理反馈

1. 「主要是少一些用简要通俗的语言来解释技术和技术变化路径的部分,一上来都是专业术语,没有基础背景的人可能比较难读明白。」
2. 「Palantir 那家公司也是一样,没看明白公司业务。」希望在报告里用一段通俗易懂的方式把业务讲清楚。

## 第二轮(同日,看过第一稿样例后)

反馈原话:「总结很不错,但是还需要重新排版一下,『白话』这样的标签不要直接写上去;另外还要说清楚这个技术和竞品的区别,比如 Palantir 的产品和普通的 SaaS 有什么区别,CPO 和可插拔、和 NPO 的区别。」

| 类 | 改动 | 文件 |
|---|---|---|
| 排版 | 零章改成加粗 lead + 问题式小标题(它像什么 / 一个真实的例子 / 和 XX 有什么不同 / 钱怎么来 / 技术怎么一步步变过来 / 最该盯的一件事);技术章改名「XX 是怎么回事、往哪走」 | `DESIGN_pm.md` §2–3,`assets/templates/` |
| 渲染器 | 通俗解释 / 类比 / 例子块不再显示「白话」「举个例子」徽标,只用底色区分;新增 `[!analogy]` 块;词典表头改为「是什么 / 可以理解成」 | `render_report_v32.py`、`render_assets_v32.py` |
| 验收 | 零章与技术章必须有「和 XX 有什么不同 / 差在哪」对比节且有表;页面上出现写作标签(段首「白话:」「打个比方:」等、标题含「白话」)即不通过;零章上限放宽到 2,200 字 | `pm_check` |
| 写法 | 新增「怎么讲清和竞品 / 替代方案差在哪」:选对比对象 → 先分类 → 结构对比图 → 每对方案的差别与代价 → 逐项对比表 → 投资含义;常用比较维度表;两组改写前后对照 | `plain_language_guide.md` §5、§7 |
| 样例 | Palantir:零章「和普通 SaaS 有什么不同」对比表;技术章 2.3「和普通 SaaS、数据平台、咨询外包比,差在哪」(分层图 + 四段差别 + 五列对比表)。CPO:零章「和可插拔光模块、NPO 有什么不同」;技术章 1.3「可插拔、LPO、NPO、CPO 到底差在哪」(四行结构对比图 + 三段差别 + 八行对比表) | `examples/pm/` |

## 第四轮(同日)

反馈原话:「人类在认知一个新技术的时候通常要和它的来源或者是老一代解决这个需求的技术进行对比和理解,所以类似 Palantir 做的事情就可以和 SaaS 作对比进行理解;一方面是用大白话简要讲明产品工作原理,然后再放一张产品的图,产品的图就不需要再用文字讲解(零部分)。」

| 类 | 改动 | 文件 |
|---|---|---|
| 结构 | 零章「先比后讲」:第一张卡片固定为「与 XX(前代 / 同类方案)的差异」,第二张「工作原理」一段通俗说明后直接放产品图,图下不写解释;原「业务本质」并入工作原理;产业链卡的「产品案例」改为「产业化进展」 | `DESIGN_pm.md` §2、模板、样例 |
| 产品图 | 规定来源顺序(官网 / 产品手册 → 发布会 → 招股书年报 → 研报原图 → 自绘示意)与自绘兜底的标注方式;零章卡片内产品图整行居中、按原尺寸显示 | `DESIGN_pm.md` §2、`render_assets_v32.py`、`data_sources.md` |
| 验收 | `--pm` 新增:零章第一个小节必须是差异对比;零章至少一张产品图;「原理」计入工作原理识别 | `pm_check` |
| 样例 | Palantir 零章:与普通 SaaS 的差异 → 工作原理 + 平台界面示意图(对象列表、关系视图、可执行动作、AI 助手审批);CPO 零章:与可插拔光模块的差异 → 工作原理 + 交换机俯视结构示意(可插拔与 CPO 对比) → 产业化进展。两张图为依据公开材料自绘的 SVG,已注明非截图 / 非实物照片(本次会话网络策略拒绝访问官网) | `examples/pm/` |
