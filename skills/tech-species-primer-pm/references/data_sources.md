# 取数路线(按市场与对象)

总原则:**一手原文是唯一的数字来源**,数据库和卖方只作线索或交叉核对;每个数回原文页码;机构冲突并列「口径分歧」;
缺的写「数据不可得」并写清查过哪些文件与页码。请求里不带用户邮箱;SEC 等要求 User-Agent 的,用非个人联系串。

## 1 各市场一手文件

| 市场 | 一手文件 | 取法 |
|---|---|---|
| A 股 | 招股说明书(必抓:工艺流程图、产品规格与图片、具名前五客户与供应商、产能与产能利用率、产销量、同行对比表、核心技术、风险因素)、问询回复与发行保荐书、各年年报、半年报、募集说明书、投资者关系活动记录表、重要公告(定增、募投、扩产、减持、质押、股权激励、关联交易、担保) | 巨潮:`scripts/cninfo_list.py list <代码>` 出全部公告清单 → `get --kw 招股说明书,年度报告,半年度报告` 下载并自动转按页文本。科创板问询回复在上交所审核系统:`query.sse.com.cn` 的 `sqlId=GP_GPZCZ_SHXXPL&stockAuditNum=<项目号>` 列全部回复 PDF(请求头要带 Referer `https://kcb.sse.com.cn/`);创业板在深交所发行上市审核信息公开网站 listing.szse.cn。互动问答:上证 e 互动 / 深交所互动易 |
| 港股 | 招股章程(写了后来年报不再写的东西:行业顾问数据、合约、供应商、门店、会员)、年报、中报、季度业务更新、公告 | 港交所披露易。可借 contradiction-library 的 `scripts/fetch_filings.py hkex --code 09992 --out <dir> --lang ZH`。港股公司常不发业绩演示 PDF,写明 |
| 美股 | S-1 及修订、SEC 意见信与回复(CORRESP / UPLOAD,相当于 A 股问询函)、10-K、10-Q、8-K 业绩稿与附带 Investor Presentation / Business Update、DEF 14A、Form 4、20-F(外国发行人) | EDGAR `curl --noproxy '*'`(走代理 SSL 会失败);XBRL 用 `data.sec.gov/api/xbrl/companyfacts/CIK##########.json`;IR 站页面常 403,但 `files/doc_financials/...pdf` 这类直链带浏览器 UA 往往能直接取到 |
| 日股 | 有価証券報告書、決算短信、決算説明会資料、統合報告書 | EDINET、公司 IR 页(往期列表常要加年份参数)。日文转述成简体中文,术语用 `references/glossary_jp_zh.json`;注意英文版误译(F&LC「340 店」是目标不是实绩) |
| 台股 | 年报、法说会简报 | MOPS 公开资讯观测站;繁体转简体 |
| 欧洲 | 年报、季报(Interim Report)、业绩演示、20-F | 公司官网 + EDGAR;按报告币种写,折算写汇率来源与期间 |

写进 materials.md:文件名、页数(或 Item / Note 号)、日期、来源 URL、取得日期。PDF 一律 `scripts/pdf2txt.py` 转成
`sources/text/*.txt`(页标记 `=== pN ===`),全卡统一写 **PDF 页码**(A 股招股书常见印刷页码 = PDF 页码 − 1)。

## 3 行业数据与卖方材料

- 行业规模、份额、价格:协会与第三方机构(按行业:Prismark / TPCA、LightCounting / Cignal AI / Omdia / Yole / Dell'Oro、
  BNEF / CNESA、欧睿 / Circana、卓创 / 百川盈孚 等)。多数只能经卖方原图获得:写机构、报告日期、页码、原图注;
  招股书行业概览章里的第三方数据各写各的机构。定义宽窄不同(如「潮玩」「CPO 是否含 NPO」)必须并列写口径。
- 卖方深度与点评:只作线索与〔卖方估计〕;卖方盈利预测、估值、评级、目标价不进卡。
- 研报原图:AlphaPai `image`(`scripts/ap_images.py`);`recall` 全文召回积分不足,不要调。
- 纪要与专家访谈(本机 corpus、进门财经、AlphaEngine 路演):管理层口径线索,标〔管理层口径〕;核不到原始出处的标〔卖方估计〕。
- 同行对照:各自年报、法说会、决算说明会中对应业务段落;比参数(厚度、功率、Dk/Df 等)要有来源才写。

## 4 对象不同时的范围写法

- **公司卡**:以最新年报分部 / 分产品为准分主业章(收入或毛利占比 ≥10%,或决定未来的新业务);两套分类口径并存时逐年对齐,对不齐的年份写明。
- **主题卡**(公司里的一块业务,如诺基亚 DCI):范围先写死(主体 / 并列讲清 / 只作对照 / 不在范围),公司披露口径不同(如按「AI 与云客户」统计)时在 materials.md 写明怎么对齐;非主题业务只在一章简述;股东治理只写与主题相关的事实。
- **产业链 / 技术物种卡**(如 CPO):对象是一条链而不是一家公司;范围写死并列出路线之争;厂商进度统一分「发布、出样、小批、量产、规模部署」五档;代表公司只用来说明站位,不做个股建议;章节按「是什么 → 为什么是现在 → 路线之争 → 产业链每一环(每环一章,六节照用)→ 谁付钱 → 对现有产业链意味着什么 → 跟什么走 → 正在变什么 → 来源与口径」组织。

## 5 网络环境(本机)

- Clash Verge 规则模式:国内站点直连;EDGAR、部分海外站 curl 要 `--noproxy '*'`;代理抖动时海外站可能间歇失败,失败如实报,不要把失败写成「数据不可得」前先重试一次。
- 内置浏览器面板打不开 `file://`;预览本地 HTML 用 `scripts/shots.py`(playwright)或无头 Chrome。

## 6 基金经理版:通俗层要的材料(第 1 步一起找)

- **真实客户案例**(零章「客户案例」、业务章开头的通俗解释):公司官网案例页与客户故事、客户自己的公告或年报、业绩会与投资者日里管理层举的例子、
  招股书「业务」章节的典型客户描述、行业媒体对客户的采访。每个案例记:客户名、时间、用之前怎么做、用之后改善了什么、出处与日期;
  效果数字是厂商宣称的标〔厂商口径〕。找不到公开的具体客户,就写行业里的典型场景并注明「典型场景,非特定客户」。
- **技术代际材料**(技术章路线图):厂商产品发布稿与技术白皮书、标准组织文件(如 OIF、IEEE、JEDEC、3GPP)、行业协会技术路线图、
  研报里的技术路线图原图(AlphaPai image 搜「XX 技术路线」「XX 演进」「XX 代际」)、招股书「技术水平与特点」「核心技术」章节。
  每一代记:大致时间、解决了上一代什么问题、代价、谁在推动、量产状态。
- **替代方案与同类产品**(零章与技术章的「与 XX 的差异」):同类产品的定价方式(按人头 / 按用量 / 按平台)、交付与上线方式、部署位置;替代技术的结构(零件放在哪、信号怎么走)、维修方式、量产状态与主导厂商。来源:各家官网与产品文档、10-K 业务描述、厂商发布稿、标准组织文件、采购顾问与行业媒体的公开分析。
- **产品图**(零章工作原理之后):公司官网产品页与产品手册截图、发布会 / 投资者日原图、招股书与年报的产品图、研报原图(AlphaPai image 搜「XX 产品 界面」「XX 实物」);都拿不到时自绘示意(SVG,标注关键部件),在 materials.md 记下查过的来源。
- **读者最容易套错的类别**:卖方深度的「公司定位」段、同业对比表、媒体标题里对公司的常见说法。
