# 单卡计划模板(= 用户「从 0 开始」prompt 的通用版 · 基金经理版)

主线在第 0 步按这个模板把本卡计划写成 `R/work/PLAN.md`,用户已经给了完整 prompt 的就直接存用户原文。
真实样例(v3.2 版,可直接改名复用;用时把下面「基金经理版」各条补进去):`examples/prompts/`
- `honghe_603256_ashare_main.md` 宏和科技(A 股主板、材料制造、两套分类口径)——最完整的一份
- `dekeli_688205_ashare_star.md` 德科立(A 股科创板、有问询回复)——第一张跑通的卡
- `popmart_09992_hk_consumer.md` 泡泡玛特(港股、消费品:流程写成从设计到上架)
- `pltr_us_software.md` Palantir(美股、软件与政府合同:ceiling vs obligated)
- `nokia_dci_theme.md` 诺基亚 DCI(主题卡:只聚焦公司里的一块业务)
- `cpo_industry_chain.md` CPO(产业链 / 技术物种卡:对象是一条链)

---

帮我从 0 开始给 **{公司}({代码})** 做一份**基金经理版**「业务认知」报告(tech-species-primer-pm)。读者是基金经理,懂财务和估值、不懂{行业}的技术,也会拿给领导看。目标是他读完能向别人讲清:
- **一句话:{公司}卖什么东西、帮谁解决什么问题**(零章,用类比和一个真实客户的前后对比讲);
- **{核心技术}的原理、与{替代方案 / 同类产品}的差异、技术演变与下一阶段的可能路径**(技术章,差异节写清差异与代价,路线图写清每一代的代价和受益、受损方);
- {产品}是什么、起什么作用、关键参数为什么重要;
- {公司}卖什么:按{行业物理尺子}分档,每档规格、用在哪、多大、毛利率差多少;
- 怎么做出来:工序,哪些自制、哪些外购,关键设备与耗材从哪来;
- 卖给谁:客户层级、认证链怎么走、要多久;
- 凭什么赚钱:和{主要对手}比,强在哪、弱在哪;
- 正在变什么。

用 workflow 按章并行。只建认知,不写估值。

## 二、范围与从 0 开始
- 新产出全部放 `~/Desktop/research-materials/{公司}-{代码}/primer_pm/`;目录里已有的文件只读。
- 本地已有材料(旧卡、一页纸、iFind/Wind 表、纪要)只作线索,结论、章题和数字不直接沿用,每个数回原文核对。
- 分类口径先对齐(两套分法并存时逐年对齐,对不齐的写明);口径主体(合并报表、子公司角色);币种与汇率来源。
- 主题卡 / 产业链卡:范围先写死(主体 / 并列讲清 / 只作对照 / 不在范围),进度分档口径写死。

## 三、先盘点材料,再写(第一步落盘 materials.md 与 questions.md)
- 一手:{招股书 / 问询回复 / 年报 / 半年报 / 投资者关系记录 / 重要公告;或 S-1 / 10-K / 10-Q / 8-K / DEF 14A;或披露易招股章程与年报}。
- 行情与财务:Wind 只取历史财务与细分业务,最多 1 次;iFind 不用;行情等走免费源;市值写收盘价 × 股本 × 日期。
- 行业与价格数据:{协会、第三方机构、价格源},多数经卖方原图,写机构、日期、页码;冲突并列「口径分歧」。
- 同行与对照:{海外 / 台湾 / 大陆同行、下游客户};外文材料转述成简体中文。
- 研报原图:AlphaPai image 搜图,候选检索词:{……}。含盈利预测、估值、评级、目标价的原图不用。
- 官方图:招股书 → 年报 → 官网 → 研报原图 → 自绘。
- 股权与治理:{第一大股东、实控人、减持、质押、解禁、股权激励、定增};企查查用统一社会信用代码查。
- 先列 20–35 个必答问题,每题写清放到哪一章、需要哪类图;其中至少 6 个是通俗层问题(一句话说它卖什么、客户原来怎么解决、读者最常拿它和什么比较且差异在哪、读者最容易误解成什么、技术每一代解决了什么、最真实的一个客户案例)。
- 找 2–3 个真实客户案例(官网案例、客户公告、业绩会、招股书)和技术代际材料(厂商发布、标准组织文件、研报技术路线图),给零章「举个例子」和路线图用。

## 四、结构(按设计规格 §2,按实际披露定章)
0. **零、业务速览**(主线最后写):加粗一句话定位 + 3–4 项关键数据 + 六个小节,先比后讲(与{前代技术 / 同类产品}的差异 + 对比表 / 工作原理 + 产品图,图下不写解释 / 客户案例 / 价值流向 + 价值流向图 / 技术演变 / 跟踪指标 + 指标表),渲染为研报首页式版式;用语买方化,页面上不写「白话」「打个比方:」这类标签,也不写「钱怎么来」「最该盯的一件事」这类口语化表述。全章汉字 400–1,200、导语 ≤90 字、每节正文 ≤160 字,英文缩写 ≤3;数字写精确值并注明期间,不写「约」。
1. 一、公司总览:本质一段 + 近况一段;KPI 5 个;分产品经营数据表;收入与毛利结构演变;境内外;产业链与商业模式结构图;产能或全球布局图;发展时间轴;客户类型。
1b. **二、技术与产品:原理、差异与演变**:要解决的问题 / 原理 / 与{替代方案}的差异(分类 + 结构对比图 + 每对方案的差异与代价 + 逐项对比表)/ 技术演变(roadmap 路线图)/ 下一阶段的可能路径与验证信号 / 对公司经营的影响。
2. 每个主要业务一章(建议 {N} 章:{……}),lead 之后先放一段**通俗解释**(不写标签前缀),再固定六节:行业规模 / 竞争格局 / 历史演变 / 具体产品 / 核心竞争要点 / 公司优势与短板。
3. 专题章(按需:上游与产能、客户与认证、IP 与渠道、大客户与合同……;节名不用业务章那四个词)。
4. 股东与治理;非主要业务简述。
5. UE与经营效率:单位经济(写算式)、定价权 2–3 条完整句、增量利润率一句、六张经营效率图(周转天数、净利润与经营现金流、总资产周转率、资本开支与经营现金流、资产负债率与有息负债率、在手净现金)。
6. 跟什么走:{2–7 个外部变量},每个一段加图,敏感性写数值,方向从数据推。
7. 正在变什么:6–8 条逐条完整句 + 「核心问题与验证点」表(3 行)。
8. 来源与口径:读过的报告清单;口径冲突与取舍表(必须覆盖:{……});数据缺口;声明。
9. **附录、术语小词典**:各章 NN_terms.md 自动合成(≥15 条:术语 / 含义 / 投资相关性);正文术语悬停可见解释。

## 五、硬门槛(不达标不交付)
- 图 55–70:交互 ≥30;官方 / 研报原图 / 实物 / 流程 / 示意 ≥20;每个主业章 ≥12 且有流程图、谱系或实物图、原理示意、应用场景、参数对标。不要堆图。
- 汉字 ≥10,000;表 ≥10;每张图表有来源行。
- 数字回原文页;先建统一数字底座;术语首现当场用一句话解释(不许用术语解释术语),每段新术语 ≤2 个;不写估值、目标价、评级、卖方盈利预测。
- 每个业务章开头有通俗解释;零章与技术章都有「与 XX 的差异」对比节与表;技术章有路线图;词典 ≥15 条(不计入篇幅);页面上无写作标签、无口语化表述;用语遵循 buyside-voice 的 voice-rules。
- `merge_card.py`(即 `--gate --pm --min-cjk 10000 --ref ref_text.txt`)通过;HTML 单文件离线可开、JS 报错 0。

## 六、流程与交付
1. materials.md、questions.md → work/facts_spine.md(六块,每个数标口径与原文位置)。
2. 改写 work/BRIEF.md;按章并行写 parts/(正文 + NN_facts.md + NN_gaps.md),写完就落盘;图片 images/cN_*,放进来前用 Read 看。
3. merge_card.py 合并渲染跑 gate。
4. 三路评审(版式深度 / 50+ 数字核对与口径混用 / 外行复述:扮演不懂技术的基金经理只读通俗层复述六件事(含与同类产品的差异)),写评审处理记录.md。
5. shots.py 截图验版式。
6. 交付:MD、HTML、materials.md、评审处理记录;HTML 另存「{公司}科普-基金经理版-YYMMDD.html」传飞书云空间根目录;一句话报图数(交互 / 图片 / 自绘)、表数、汉字数、通俗解释块数、词典条数、评审 C 结论和数据缺口。
7. 不要把用户邮箱放进任何网络请求;对用户已有文件只读。

## 七、上下文预算(主线 ≤18%)
主线只做:读规格、写 materials / questions / BRIEF、建数字底座、编排 workflow、合并渲染与汇总评审。取证、下载、写章、看图、评审全放进子代理;
子代理回主线 ≤300 字;大文件只 grep / head;主线接近 18% 时按「底座 → 各章落盘 → 合并 → gate 通过 → 飞书」的顺序保。
