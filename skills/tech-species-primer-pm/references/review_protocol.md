# 三路评审(A 版式深度 / B 数字核对 / C 外行复述)+ 截图验版式 + 评审处理记录

合并渲染、`--gate` 通过之后才评审。评审交给子代理(workflow 或 Agent),主线只汇总与分派修改。

## 1 评审 A:版式、深度、可读性、重复出图

对照物:`assets/reference/ref_layout_sungrow.html`(参考版式,只学结构写法)、`examples/sungrow/card_v32.md`(阳光电源样例)、
本机德科立卡 `~/Desktop/research-materials/德科立-688205/primer_v32/`(若存在)。逐章给意见,分 blocker / major / minor,查:

1. 结构:每个主要业务章六节齐全;章首 lead + 关键数;专题章没误用业务章节名;非主业、UE、跟什么走、正在变什么、来源与口径齐。
2. 深度:零基础读者能否讲清「卖什么、怎么做出来、卖给谁、凭什么赚钱、正在变什么」;术语首现有解释;术语词典 ≥15 条(由各章 NN_terms.md 合成)。
2b. 基金经理版结构:零章在最前,摘要面板(定位 + 关键数据)与六张卡片齐全且先比后讲(与 XX 的差异 + 对比表 / 工作原理 + 产品图,图下无解释文字 / 客户案例 / 价值流向 + 价值流向图 / 技术演变 / 跟踪指标);产品图优先官网或发布会原图,自绘示意须注明;技术章六节齐全,「与替代方案的差异」一节有分类、结构对比图、每对方案的差异与代价、逐项对比表,路线图每一代都写了代价;每个业务章开头有通俗解释、每节第一句是结论;通俗层与证据层的数对得上;**页面上没有「白话」「打个比方:」这类写作标签,也没有「钱怎么来」「最该盯的一件事」这类口语化表述**;用语符合 buyside-voice 的 voice-rules(警句只在结论位、语气随证据分层、至少一处明示不确定)。
3. 图:每张图一句话能说清它证明什么;图题写结论且不比数据说得满;同一信息不重复出图、跨章不复用原图、两三个数能说完的不画图;
   主业章有流程图、谱系或实物图、原理示意、应用场景、参数对标;比率折线、金额柱;半年数与预测年浅色;英文或日文原图有读图提示。
4. 写法:判断先行、证据跟上、推理看得见;加粗 1–3 处/段,警句式加粗和比喻不密;无空话;单期观测不写成稳定弹性;倍数写法统一。
5. 篇幅均衡:各主业章图数与字数大致对得上其重要性。
6. 照抄:与参考报告的定义、标签、句子是否近似改写(`--gate --ref` 的照抄检查之外,人工再看一遍导语和表的「定位」列)。

## 2 评审 B:数字核对(抽 50 个以上)

按各章 `NN_facts.md` 台账抽数,回原文页核对(`scripts/pgrep.py`),每个数记:数字 / 位置 / 原文 / 页码 / 一致或不一致 / 修正。专查口径混用:
- 两套分类口径(如按厚度 vs 按材质;主营分产品表 vs 附注「营业收入分解」;新旧分部口径改版);
- 年报 vs Wind / iFind / FMP;合并 vs 母公司;营业收入 vs 主营收入;
- 单位(万米 vs 吨、GW vs GWh、交流 vs 直流、发货 vs 确收、bookings vs revenue);
- 价格口径(第三方报价 vs 公司平均售价;含税 vs 不含税);币种与汇率;
- 合同上限(ceiling)vs 已拨付(obligated)vs 收入;目标 vs 实绩;半年数 vs 全年数;
- 页码(PDF 页码 vs 印刷页码);报告日期(封面 vs 入库日)。
结果写进 `review_numlog.json` 或评审处理记录第三节;不一致的逐条改正文、图表 JSON、底座和台账,全卡同一个数保持一致。

## 3 评审 C:外行复述(基金经理版新增)

目的:检验「没有技术背景的人读完能不能讲清业务和技术路径」。v3.2 的评审 A 由懂行的子代理做,它看得懂术语,所以查不出这个问题。

1. **人设**(写进子代理任务):「你是一位基金经理,懂财务报表、估值和行业比较,但对{行业}的技术一窍不通,也没读过这家公司的任何材料。」
   **禁止**子代理先读证据层、查外部资料或用自己已有的行业知识补全。
2. **只读通俗层**:零章全文;各章 `[!lead]` 与 `[!plain]` / `[!analogy]` / `[!example]` 块;技术章全文(含路线图 JSON 的 name / gist / solves / cost / who 与 fork)。
   主线用 `grep` 把这些段落抽成一个文件交给子代理,不要把整份 MD 给它。
3. **复述六件事**(不看原文,用自己的话,每件 ≤80 字):**与前代 / 同类产品或替代技术的差异**(如 Palantir 与普通 SaaS、CPO 与可插拔和 NPO);工作原理(只看文字和产品图能否说清产品怎么运作);客户与付费方;价值流向;技术演变与下一阶段的可能路径;跟踪指标。
4. **列出卡住的地方**:逐条写「位置 / 原文 / 为什么没看懂」——没解释的词、解释了但还是不懂的词、看不出因果的句子、类比让人更糊涂的地方,以及**读起来像模板标签、打断阅读的排版**。
5. **主线判定**:把复述与原文对照,每件事判「对 / 偏 / 错」,写进 `work/reader_test.md`。
6. **通过标准**:六件事无「错」、「偏」≤1;卡住的地方 ≤5 处。不通过就改通俗层(零章、各章开头的通俗解释、对比节、术语括注、路线图 gist),**换一个新子代理**重评(旧子代理已经「学会」了,不能再当外行)。
7. 高频问题:类比没说边界,读者把公司套错类别(Palantir 被理解成数据库或咨询公司);例子只有结果没有前后对比;对比节只列了本公司的优点,没写代价,或对比对象选成了读者不认识的细分对手;路线图只写了每代的好处,没写代价;零章夹带了证据层的精确数字和口径。

## 6 历次评审高频意见(写的时候就先避开)

- 照抄或近似改写参考报告的定义、标签和句子(blocker)。
- 单位经济的分母前后不一致(发货量 vs 确收量),要并列多种口径并写清各用在哪。
- 图题比图里的数据说得满;无证据的断言(「某某阵营找不到对应物」)。
- 行业规模只有一年、缺历史序列;份额表缺年份写「数据不可得」而不是空着。
- 图重复或凑数(同一数据换个图型再画一遍、两三个数画成图)。
- 零基础读者看不懂:缺名词表、术语没括注、英文原图没读图提示。
- (基金经理反馈 2026-09-29 第一轮)一上来就是术语;技术和技术变化路径没人用通俗的话讲;平台型公司(Palantir)读完不知道它到底卖什么。
- (第二轮)页面上写着「白话」这类标签像模板;没说清和竞品的区别(Palantir 和普通 SaaS、CPO 和可插拔、和 NPO)。对策见 DESIGN_pm.md。
- 单期观测写成稳定弹性;「七年涨 70 倍」这类年数与倍数算错。
- 卖方观点标题带情绪词进了来源行;美国收入占比这类公司未披露的数被当事实写。
- 加粗警句偏密、比喻偏多;某一新业务篇幅压过更重要的主业。
- 原图用了旧版数字(同一机构后来更新过),要找最新版并把旧版放进口径分歧。
