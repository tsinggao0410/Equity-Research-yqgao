# 业务认知卡 · 基金经理版(v3.3-PM)增量规格

> 本文件是 tech-species-primer-pm 的规格正本之一,只写**相对 v3.2 的增量**。v3.2 的结构、图表密度、MD 写法、视觉规范、数据纪律仍以
> `references/DESIGN_v32.md` 为准;两者冲突时**以本文件为准**。写法细则、类比库、竞品对比写法和改写正反例在 `references/plain_language_guide.md`。

## 0 为什么要有这一版

基金经理读完 v3.2 卡片后的反馈(原话):

**第一轮(2026-09-29)**

1. 「主要是少一些用简要通俗的语言来解释技术和技术变化路径的部分,一上来都是专业术语,没有基础背景的人可能比较难读明白。」
2. 「Palantir 那家公司也是一样,没看明白公司业务。」要求用一段通俗易懂的话把业务讲清楚。

**第二轮(2026-09-29,看过本版第一稿样例后)**

3. 「总结很不错,但是还需要重新排版一下,『白话』这样的标签不要直接写上去。」
4. 「还要说清楚这个技术和竞品的区别,比如 Palantir 的产品和普通的 SaaS 有什么区别,CPO 和可插拔、和 NPO 的区别。」

对照 v3.2 的规格和样卡,问题出在结构,不只在措辞:

| 现象 | 原因 | 本版的改法 |
|---|---|---|
| 一上来就是术语 | 总览第一段写「本质」,但写法是分析师口吻的定义;章首 lead 直接上「定义 + 关键数」 | 最前面加**零章「一分钟看懂」**,只用通俗说法、类比和一个真实例子;各业务章 lead 之后加一段**通俗解释** |
| 技术和技术变化路径没人讲 | 技术内容拆散在各业务章的 x.3 / x.4,以型号和参数为主 | 新增**技术章「XX 是怎么回事、往哪走」**,核心是一张**技术路线图**(每一代解决了什么、代价、谁受益谁受损、下一步分岔) |
| 说不清和竞品差在哪 | v3.2 的竞争格局讲份额和排名,不讲「做法有什么不同」;读者不知道 Palantir 和普通 SaaS、CPO 和 NPO 的区别 | 零章与技术章各有一节**「和 XX 有什么不同 / 差在哪」**:结构对比图 + 逐项对比表 + 每对相邻方案一段,验收硬查 |
| 术语首现有解释只是口号 | 没有验收;名词表放在最后一章 | 各章写**术语台账 NN_terms.md**,合成词典;正文术语**悬停即见解释**;`--pm` 查英文缩写首现有没有解释 |
| 页面像模板 | 第一稿样例用「白话」徽标和「打个比方:」「举个例子:」前缀标出每一块 | **页面上不写任何写作标签**:零章用问题式小标题(它像什么 / 一个真实的例子 / 和 XX 有什么不同 / 钱怎么来 …),类比和例子用块类型区分底色;验收查标签外露 |

读者画像:**基金经理**,懂财务报表、估值和行业比较,不懂这门技术;先花五分钟决定要不要往下读;读完要能向投委会或领导复述。
全卡分三层,读者可以在任一层停下(「层」是写作概念,**页面上不出现层名**):

1. **通俗层**(约 5 分钟):零章 + 各章开头的通俗解释 + 技术章的对比图表与路线图。只用通俗说法、类比、例子和少量取整后的数。
2. **结构层**:各章 lead、图题(写结论)、表。
3. **证据层**:v3.2 原有的全部正文、图表、来源与口径。

## 2 零章「一分钟看懂」

**位置**:页头 meta 盒之后的第一章,章号「零」,目录分组「先看这里」。**由主线在所有业务章写完、数字底座定稿后最后写**,章节 agent 不写本章。
**篇幅**:汉字 500–2,200(含表);英文缩写 ≤3 个(公司名、代码、读者熟知的词不算);数字 ≤5 个,全部来自数字底座,写成「约四分之三」「翻了一倍」这类说法。
**排版**:一段 lead + 六个**问题式小标题**(`###`,不编号,会进左侧目录)。**页面上不写「白话」「一句话:」「打个比方:」「举个例子:」这类标签**;类比放 `[!analogy]` 块、例子放 `[!example]` 块,块类型只决定底色。

| 位置 | MD | 写什么 | 不许写什么 |
|---|---|---|---|
| 开头 | `> [!lead] **…**` | ≤60 字加粗:卖什么东西、帮谁解决什么问题;再一句交代客户是谁 | 术语、产品型号、「领先的」「平台型」这类形容;「一句话:」前缀 |
| ### 它像什么 | `> [!analogy] …` | 用读者天天见的东西类比;先讲客户原来的麻烦,再讲产品怎么解决;用「不同的是……」说清类比在哪里不成立;最后把公司自己的叫法对上 | 为类比而类比;一段两个以上比喻 |
| ### 一个真实的例子:XX | `> [!example] …` | 一个真实客户或场景,前后对比(以前怎么做、花多久;现在怎么做、改善了什么),有出处 | 编造客户;把厂商宣称写成事实(要标〔厂商口径〕) |
| ### 和 XX 有什么不同 | 两三句 + 表 0-1 + 一两句 | 读者最容易拿来比的同类产品或替代方案(Palantir → 普通 SaaS;CPO → 可插拔与 NPO),逐项比 5–6 行;最后一两句说这些差别对投资意味着什么 | 只说好不说代价;用参数名当比较维度 |
| ### 钱怎么来 | 段落 + 图 0-1(chain 块) | 谁付钱、按什么收费、为什么重复买;收入最大的一块;成本大头在哪 | 估值、目标价、盈利预测 |
| ### 技术怎么一步步变过来 | 段落 | 3–5 步,每步一句「解决了上一代什么麻烦」;指向技术章 | 型号清单 |
| ### 最该盯的一件事 | 段落 | 最关键的一个不确定性,写成「看什么数、在哪看、多久能看到」 | 买卖建议 |

小标题措辞可以按本卡改,但要保留「像什么」「例子 / 案例」「不同 / 区别 / 对比 / 差在哪」这些词,验收靠它们识别。
骨架:`assets/templates/ch00_plain.md`;正例:`examples/pm/pltr_plain_sample.md` 零章(平台软件,对比普通 SaaS)、`examples/pm/cpo_tech_path_sample.md` 零章(产业链,对比可插拔与 NPO)。

## 3 技术章「XX 是怎么回事、往哪走」

**目标**:没有工程背景的读者读完,能复述「这门技术解决什么问题、原理一句话、和替代方案差在哪、一代代怎么变过来、下一步往哪走、对公司意味着什么」。
**篇幅**:汉字 1,800–3,200;图 ≥3(原理示意、替代方案结构对比、路线图);对比表必有;由一个章节 agent 在数字底座建好后写。
**章题**保留「是怎么回事」或「往哪走」(验收靠它识别),不写「技术白话」。**六节**(节名可改写成结论句,但不许用「行业规模 / 竞争格局 / 具体产品 / 核心竞争」):

1. **x.1 它要解决的问题**:先讲客户(或客户的客户)的麻烦,再讲旧办法为什么不够;一个 `[!analogy]` 块。
2. **x.2 原理:一张图看懂**:flow 块(按信号 / 物料 / 数据走的顺序)或 chain 块(分层),图题含「原理」;标出下一代技术要改动的环节(hot)。
3. **x.3 和 XX 比,差在哪**(**必有**,节题含「差在哪 / 不同 / 区别 / 对比」):
   - 先用一两句把几种方案**分类**(「LPO 只改模块里面;NPO 和 CPO 改的是光器件放的位置」「普通 SaaS 管一个部门;Palantir 架在各系统上面」);
   - 一张**结构对比图**:flow 块分泳道(每行一种方案,从左到右是信号 / 数据走的路)或 chain 块分层(各方案在客户 IT 里处在哪一层);
   - **每对相邻方案一段**,段首加粗一句「A 和 B 的差别在……」,再讲这个差别带来的好处和代价;
   - **逐项对比表**:行是「比什么」(做什么 / 放在哪、怎么上线 / 坏了怎么修、怎么收费 / 谁说了算、代价、今天到了哪一步),列是各方案,单元格用通俗短语;
   - 一个 `[!plain]` 块收尾:这些差别放在投资上意味着什么(价值落在谁手里、该看什么指标)。
4. **x.4 演进路线**:**roadmap 块必放**(3–6 代;每代 era / name / gist / solves / cost / who;当前主力标 now,未量产标 future;fork 写 2–3 个方向,各写赢的条件与看什么信号)。代际对比表可选(与 x.3 的表不要重复信息)。
5. **x.5 下一步的分岔与验证信号**:不下结论,只给判别方法与大致时间;roadmap 的 fork 已写清时可并入 x.4。
6. **x.6 对公司意味着什么**:技术变化怎么传导到公司卖的东西(量、价、形态)、份额与话语权、成本与毛利率;以一个 `[!plain]` 块收尾。

参数只保留读者判断需要的数量级(「十几厘米 vs 几毫米」「几个月 vs 5 天」),精确参数留在业务章 x.4 具体产品。
骨架:`assets/templates/ch_tech_plain.md`;正例:两份 `examples/pm/` 样例的技术章(Palantir 2.3 对比普通 SaaS / 数据平台 / 咨询外包;CPO 1.3 对比可插拔 / LPO / NPO)。

## 4 全卡写作纪律

1. **业务章开头的通俗解释**:每个主业章在 `[!lead]` 之后、第一个 `###` 之前放一个 `[!plain]`(或 `[!analogy]` / `[!example]`)块,≤200 字:这块业务用通俗的话讲是什么、类比或例子(二选一)、看这块业务关键看什么数。**不写「白话:」前缀**,直接从内容写起。验收硬查。
2. **每节第一句是通俗结论**,再上图和数据(评审 C 抽查)。
3. **竞品差别用通俗维度讲**:v3.2 的 x.2 竞争格局、x.5 核心竞争要点、x.6 优势与短板里,和对手比较时同样先说「做法差在哪」,再上份额和参数。
4. **术语**:首现当场一句话解释,格式「中文名(英文缩写,一句话解释)」;不许用术语解释术语;每段新术语 ≤2 个。每章登记 `parts/NN_terms.md`(表头 `| 术语 | 是什么 | 可以理解成 | 对投资意味着什么 |`,别名用「 / 」分隔),`merge_card.py` 合成「附录、术语小词典」;正文每章第一次出现的词典术语自动加虚线下划线,悬停或点按显示解释。
5. **类比**:只在零章、各章开头的通俗解释、技术章 x.1 用;每处一个;好类比三条件:读者熟悉、结构对得上、说清边界。
6. **例子**:真实、前后对比、有出处;厂商宣称标〔厂商口径〕,媒体报道标〔公开报道〕。
7. **数字**:通俗层用取整和倍数说法;精确值、口径、页码留在证据层;两层的数必须能对上。
8. **图题**用通俗话写结论(「光器件一步步往芯片靠,省电越多、维修越难」)。
9. **不写写作标签**:页面上(正文、标题、图题)不出现「白话」「大白话」「一句话:」「打个比方:」「举个例子:」「钱怎么来:」这类标签字样;要分块就用小标题或块类型。验收硬查段首前缀和标题。
10. 通俗不是营销腔:不许夸张、不许比数据说得满;「赋能」「一站式」「颠覆」照旧禁用。

## 6 渲染器语法(`scripts/render_report_v32.py` 文件头有全字段)

- `> [!plain] …`(浅灰蓝底)、`> [!analogy] …`(浅紫底)、`> [!example] …`(浅青底):**页面上不显示任何标签字样**,只用底色区分层次;首句若写了「XX:」会加粗,但按 §4 第 9 条不要写。
- ```` ```roadmap {JSON} ````:技术演进路线图,计入示意图(图表目录记为「路线图」);手机宽度自动竖排。
- ```` ```flow ```` 的 `lanes`(每行一种方案)适合画「几种方案的结构对比」;`"legend": false` 关掉自动图例(本图的橙框含义与默认图例不同时)。
- ```` ```chain ```` 的 `"legend"`:默认图例是「绿色虚线 = 钱的流向」;虚线表示别的东西(如「把决定写回原系统」)时写成自定义文字,或 `false` 隐藏。
- ```` ```glossary 术语 | 是什么 | 可以理解成 | 对投资意味着什么 ```` :词典表,行锚点 `gl-N`;正文悬停释义由此生成(离线 JS,无外部请求)。
- 语法样例:`assets/fixture/fixture.md` 末节;完整样例:`examples/pm/`。

## 7 评审 C:外行复述

在评审 A(版式深度)、评审 B(数字核对)之外加一路:子代理扮演「懂财务、不懂这门技术的基金经理」,**只读通俗层**(零章、各章 lead 与通俗解释块、技术章),不看证据层,用自己的话复述六件事(卖什么、卖给谁、怎么赚钱、**和最常被拿来比的同类产品差在哪**、技术怎么变、最该盯什么),并逐条列出卡住的词和句、以及页面上像模板标签的地方。主线对照原文判定复述「对 / 偏 / 错」;有「错」或卡住的地方 >5 处,改通俗层后换新子代理重评。协议见 `references/review_protocol.md` §3,记录写 `work/reader_test.md`,结论进评审处理记录。
