## 0 为什么要有这一版

基金经理读完 v3.2 卡片后的反馈(原话,2026-09-29 六轮):

1. 「主要是少一些用简要通俗的语言来解释技术和技术变化路径的部分,一上来都是专业术语,没有基础背景的人可能比较难读明白。」
2. 「Palantir 那家公司也是一样,没看明白公司业务。」要求用一段通俗易懂的话把业务讲清楚。
3. 「『白话』这样的标签不要直接写上去,重新排版一下。」
4. 「还要说清楚这个技术和竞品的区别,比如 Palantir 的产品和普通的 SaaS 有什么区别,CPO 和可插拔、和 NPO 的区别。」
5. 「第 0 部分的格式还是不太好看,需要再改一下 UI;一些 AI 化的表述需要更加买方化,『钱往哪里流』『技术怎么一步步变过来』改成『价值流向』『技术演变』。」
6. 「人类在认知一个新技术的时候,通常要和它的来源或者老一代解决这个需求的技术进行对比和理解,所以 Palantir 可以和 SaaS 作对比来理解;一方面用大白话简要讲明产品工作原理,然后再放一张产品的图,产品的图就不需要再用文字讲解(零部分)。」
7. 「字还是有点多,不够精炼、efficient;另外 UI 不够严肃,不够准确。」
8. 「案例部分可以稍微多放一点,尤其是典型案例;另外不要这么多线条,可以直接分行进行分隔,线条看上去有点乱。」

对照 v3.2 的规格和样卡,问题出在结构和用语,不只在措辞:

| 现象 | 原因 | 本版的改法 |
|---|---|---|
| 一上来就是术语 | 总览第一段是分析师口吻的定义;章首 lead 直接上「定义 + 关键数」 | 最前面加**零章「业务速览」**,用通俗说法、类比和真实案例讲清业务;各业务章 lead 之后加一段**通俗解释** |
| 技术和技术变化路径没人讲 | 技术内容拆散在各业务章的 x.3 / x.4,以型号和参数为主 | 新增**技术章「技术与产品:原理、差异与演变」**,核心是一张**技术演变路线图**(每一代解决的问题、代价、受益与受损方、下一阶段的可能路径) |
| 说不清和竞品的区别 | v3.2 的竞争格局讲份额和排名,不讲做法的差异 | 零章与技术章各有一节**「与 XX 的差异」**:结构对比图 + 逐项对比表 + 每对方案的差异与代价,验收硬查 |
| 术语首现有解释只是口号 | 没有验收;名词表放在最后 | 各章写**术语台账 NN_terms.md**,合成词典;正文术语**悬停即见解释**;`--pm` 查英文缩写首现有没有解释 |
| 页面像模板 | 第一稿用「白话」徽标和「打个比方:」前缀标出每一块 | **页面上不写写作标签**;验收查标签外露 |
| 读者没有参照物,产品长什么样也看不到 | 零章先讲业务本质再讲差异;全卡没有一张产品图 | 零章**先比后讲**:第一张卡片是「与前代 / 同类方案的差异」(Palantir → 普通 SaaS;CPO → 可插拔光模块),第二张是「工作原理」:一段通俗说明后直接放**产品图**,图下不再写解释文字;验收查对比节是否在首位、零章是否有产品图 |
| 零章字多、版式不严肃、数字不准确 | 零章每节两三百字,表后还有长段;卡片带圆角、阴影、底色和编号徽章,强调色用橙色;关键数据写「约 55 : 45」「约 3/4」「常年约八成」;产品示意图里画了虚构的界面和数据 | 零章正文**每节 ≤160 字、导语 ≤90 字、全章 400–1,200 字**(不含图内文字与来源),能进表的进表,跟踪指标写成表;关键数据写**精确值并注明期间与口径**,验收查「约」「常年」等模糊词和期间;版式改成**研报首页式**:三线表、细线分节、深蓝加灰、只留一处砖红强调,去掉圆角、阴影和底色;没有官方原图时只画**结构示意**,不虚构界面和数据 |
| 案例太少、线条太多 | 零章只有一个客户案例;分节线、表格行线、图框线、关键数据竖线、时间轴竖线同时出现 | 零章「典型案例」改为**一个详写案例 + 一张 3–4 行的案例表**(客户 / 时间 / 用途 / 规模或效果与出处),验收查 ≥3 个;版式**去掉大部分线条**,以分行和留白分隔:小节单栏排列、无分隔线,关键数据为浅灰底一行,表格只留三线,图、时间轴、路线图分岔、结构图列头都不加线 |
| 零章版式平淡、用语口语化 | 第二稿零章是一列提示块,小标题是「它像什么」「钱怎么来」「技术怎么一步步变过来」「最该盯的一件事」这类问句 | 零章改成**速览版式**:导语与关键数据 + 带序号的分节(第五、六轮再改,见上两行);小标题改用买方用语(业务本质 / 典型案例 / 与 XX 的差异 / 价值流向 / 技术演变 / 跟踪指标);正文按 voice-rules 写;验收查口语化表述 |

读者画像:**基金经理**,懂财务报表、估值和行业比较,不懂这门技术;先花五分钟决定要不要往下读;读完要能向投委会或领导复述。
全卡分三层,读者可以在任一层停下(「层」是写作概念,**页面上不出现层名**):

1. **通俗层**(约 3 分钟):零章 + 各章开头的通俗解释 + 技术章的差异对比与演变路线图。用通俗说法、一处类比、一个案例和少量关键数(精确值,带期间)。
2. **结构层**:各章 lead、图题(写结论)、表。
3. **证据层**:v3.2 原有的全部正文、图表、来源与口径。

「通俗」指讲清技术与业务的方式,不是口语化:用语仍是买方口吻(判断先行、证据平叙、语气随证据分层)。

## 2 零章「业务速览」

**位置**:页头 meta 盒之后的第一章,章题「零、业务速览:{公司}」,目录分组「先看这里」。**由主线在所有业务章写完、数字底座定稿后最后写**,章节 agent 不写本章。
**篇幅**:全章汉字 400–1,400(含表、结构图与时间轴,不含图片内部文字和来源行;典型案例表约占 200 字);导语 ≤90 字;每个小节的正文(不含表、图、来源)≤160 字;英文缩写 ≤3 个(公司名、代码、读者熟知的词不算)。能进表的内容进表,细节留给正文,同一信息不在零章重复。
**数字**:取自数字底座,写**精确值并注明期间与口径**(「19.35 亿美元(2Q26)」「51 : 49(2Q26,9.90 / 9.45 亿美元)」);不写「约」「常年」「接近」;厂商宣称写〔厂商口径〕并注明发布时间。
**版式**(渲染器自动生成,作者只写 MD):

- **摘要区**:章首 `[!lead]`(加粗一句话定位 + 一句变化),下接 `kpis` 块(3–4 项关键数据:收入与增速、收入结构、地区或客户占比、毛利率;产业链卡写厂商口径的性能数据与量产节点);关键数据为浅灰底一行、分栏横排、不加竖线,标签里写期间。
- **分节**:每个 `###` 小节带序号(1、2 …),单栏排列,**以分行和留白分隔,不加分隔线**。小节内的 `[!analogy]` / `[!example]` 块与正文同样式;「投资含义:」开头的 `[!plain]` 块为浅灰底。
- **视觉**(本版覆盖 DESIGN_v32 §5 的配色与线条):白底;深蓝(#1f3a5f)用于标题、数字与主结构,正文近黑,辅助文字灰;强调色只有一种砖红(#a4532e),用于「当前 / 下一代」环节;**线条从简**:表格只留三线(上下粗线、表头细线,行间不加线),章标题、图、图注、导语、通俗解释块、时间轴、路线图分岔、结构图列头都不加线,层次靠字号、字重、浅灰底和留白;图、卡片、标签直角或 2px 圆角,无阴影。

**小节顺序:先比后讲**。人理解一项新技术,通常先拿它和来源、或者上一代解决同一需求的技术作对比,所以零章第一张卡片固定是与前代 / 同类方案的差异,第二张才讲工作原理并配产品图。标题用买方用语,可微调措辞,但要保留关键词,验收靠它们识别:

| 小节 | MD | 写什么 | 不许写什么 |
|---|---|---|---|
| 开头 | `> [!lead] **…**` + `kpis` 块 | ≤90 字:加粗一句定位(公司做什么、为谁解决什么问题)+ 一句近两年最重要的变化;3–4 项关键数据,精确值,标签或注释写期间 | 术语、产品型号、「领先的」「平台型」这类形容;「一句话:」前缀;「约」「常年」 |
| 1 与 XX 的差异(**必须第一节**) | 一句点明参照物 + 表 0-1 + `[!plain] 投资含义:…` | 参照物选读者已熟悉的前代技术或同类产品(Palantir → 普通 SaaS;CPO → 可插拔光模块,NPO 作为折中一并列出);第一句写明「理解 X 最直接的参照是 Y」或「X 要替代的是 Y」;表比 5–6 个维度,单元格用短语;投资含义一句 | 表前后再各写一段复述表;只写优点不写代价;用参数名当维度 |
| 2 工作原理 | `> [!analogy] …` + 产品图 | 一段通俗说明(≤160 字):产品在客户那里做什么、关键环节怎么运作、与前代方案差在哪一步,对上公司自己的叫法;**紧接一张产品图,图下不写解释文字**(图题一句、来源一行) | 拟人化类比;在图下逐项解说图;示意图里虚构界面或数据 |
| 3 典型案例 | `> [!example] …`(详写一个)+ 表 0-2(再列 3 个左右) | 详写最有代表性的一个(时间、做法、可核对的效果与出处,≤160 字);表列其他典型客户或厂商:客户 / 时间 / 用途 / 规模或效果,政府与企业、不同行业尽量都有;产业链卡写代表厂商的发布、量产节点、客户验证与部署 | 编造客户;只列客户名不写用途和效果;把厂商宣称写成事实(标〔厂商口径〕) |
| 4 价值流向 | 段落 + 图 0-2(chain 块,公司卡必放) | 付费方、计费方式、扩容来源(用留存率等精确数);主要成本项。产业链卡写价值在各环节间如何分配、谁有定价权 | 估值、目标价、盈利预测 |
| 5 技术演变 | 一句话 + `timeline` 块(3–5 个阶段) | 每个阶段一句,年份写准(拿不准写「过渡方案」「研发阶段」,不写「前后」);指向技术章 | 型号清单 |
| 6 跟踪指标 | 表 0-3(2–3 行:指标 / 最新值或看什么 / 看点或来源)+ 一句反方 | 核心指标的最新值与期间;一句市场的主要担心、我们的把握程度与验证信号 | 买卖建议;把指标写成长段 |

**产品图**:图本身要让人看懂产品长什么样、关键部件或界面在哪里。图要准确:不虚构界面文字、客户数据或按钮;没有官方原图时画**结构示意**(部件、层级、信号或数据走向),alt 与来源行写明「示意」。来源顺序:公司官网产品页或产品手册截图 → 发布会 / 投资者日原图 → 招股书与年报产品图 → 研报原图(AlphaPai image)→ 自绘示意图。拿官方图用 `scripts/imggrab.py` 或 `scripts/visuals/fetch_visuals.py`,alt 前缀写「官网:」「官方图:」「实物图:」「研报原图:」;官方图拿不到时才自绘(SVG,标注关键部件,alt 写「示意图:」,来源行写明「依据 XX 公开材料绘制,非实物照片 / 非真实截图」,并在 materials.md 记下查过哪些来源)。图放进卡片前用 Read 看一眼,确认清楚、无估值评级。

骨架:`assets/templates/ch00_plain.md`;正例:`examples/pm/pltr_plain_sample.md` 零章(平台软件,对比普通 SaaS)、`examples/pm/cpo_tech_path_sample.md` 零章(产业链,对比可插拔与 NPO)。

## 3 技术章「技术与产品 / 技术解析」

**目标**:没有工程背景的读者读完,能复述这门技术解决什么问题、原理、与替代方案的差异、技术演变与下一阶段的可能路径、对公司经营的影响。
**篇幅**:汉字 1,200–2,400;图 ≥3(原理示意、替代方案结构对比、演变路线图;零章已有的结构图直接引用「见图 0-1」,不重画);对比表必有;每对方案的差异写一两句,细节进表;由一个章节 agent 在数字底座建好后写。
**章题**:公司卡「二、技术与产品:原理、差异与演变」,产业链卡「一、技术解析:原理、方案差异与演变路线」。**六节**(节名可写成结论句,但不许用「行业规模 / 竞争格局 / 具体产品 / 核心竞争」):

1. **x.1 要解决的问题**:客户(或客户的客户)的痛点与现有方案的不足;两三句,不必再放类比。
2. **x.2 原理**:flow 块(按信号 / 物料 / 数据的流向)或 chain 块(分层),图题含「原理」;标出下一代技术要改动的环节(hot)。
3. **x.3 与 XX 的差异**(**必有**,节题含「差异 / 区别 / 对比」):
   - 先用一两句把几种方案**分类**;
   - 一张**结构对比图**:flow 块分泳道(每行一种方案)或 chain 块分层(各方案在客户 IT 中所处层级);
   - **每对相邻方案一段**,段首加粗「A 与 B:差异在……」,再写这一差异带来的收益和代价;
   - **逐项对比表**:行是维度(功能 / 位置、上线或维修方式、收费方式或主导方、代价、产业化阶段),列是各方案;
   - 以 `[!plain] 投资含义:…` 收尾:价值归属与跟踪指标有何不同。
4. **x.4 技术演变**:**roadmap 块必放**(3–6 代;每代 era / name / gist / solves / cost / who;当前主流标 now,尚未量产标 future;fork 写 2–3 种下一阶段的可能路径,各写成立条件与验证信号)。
5. **x.5 下一阶段的可能路径与验证信号**:不下结论,只给判别方法与大致时点;roadmap 的 fork 已写清时可并入 x.4。
6. **x.6 对公司经营的影响**:产品形态与量价、份额与定价权、成本与毛利率;以 `[!plain] 投资含义:…` 收尾。

参数只保留读者判断需要的数量级,精确参数留在业务章 x.4 具体产品。
骨架:`assets/templates/ch_tech_plain.md`;正例:两份 `examples/pm/` 样例的技术章(Palantir 2.3 对比普通 SaaS / 数据平台 / 咨询外包;CPO 1.3 对比可插拔 / LPO / NPO)。

## 4 全卡写作纪律

1. **业务章开头的通俗解释**:每个主业章在 `[!lead]` 之后、第一个 `###` 之前放一个 `[!plain]`(或 `[!analogy]` / `[!example]`)块,≤200 字:这块业务做什么、一个类比或案例、关键跟踪指标。直接从内容写起,不写前缀。验收硬查。
2. **每节第一句是结论**,再上图和数据(评审 C 抽查)。
3. **竞品差异先讲做法**:x.2 竞争格局、x.5 核心竞争要点、x.6 优势与短板里和对手比较时,先说做法的差异,再上份额和参数。
4. **术语**:首次出现当场一句话解释,格式「中文名(英文缩写,一句话解释)」;不许用术语解释术语;每段新术语 ≤2 个。每章登记 `parts/NN_terms.md`(表头 `| 术语 | 含义 | 投资相关性 |`,别名用「 / 」分隔;旧的四列格式仍可渲染),`merge_card.py` 合成「附录、术语小词典」;正文每章第一次出现的词典术语自动加虚线下划线,悬停或点按显示解释。
5. **类比**:全卡少用;零章工作原理至多一处,业务章通俗解释可用一处;不用拟人化或生活化比喻(「翻译」「房租」「面包」),优先用读者熟悉的商业参照(「与报表工具的区别在最后一步」);词典不写类比列。
6. **案例**:真实、前后对比、有出处;厂商宣称标〔厂商口径〕,媒体报道标〔公开报道〕。
7. **数字**:通俗层也写精确值并注明期间(「2Q26 净收入留存率 157%」),不写「约」「常年」「左右」;口径和页码写在来源行;两层的数必须一致。
8. **图题**写结论,用通俗、书面的说法(「光器件逐步靠近芯片,功耗下降、维修难度上升」)。
9. **不写写作标签**:页面上(正文、标题、图题)不出现「白话」「一句话:」「打个比方:」「举个例子:」这类字样;验收查段首前缀和标题。
10. **买方用语**:不写口语化、问句式表述(「钱怎么来」「钱往哪里流」「技术怎么一步步变过来」「最该盯的一件事」「它像什么」「有什么不同」「是怎么回事」「往哪走」「差在哪」「说白了」),改用买方说法(价值流向、技术演变、跟踪指标、业务本质、与 XX 的差异、技术解析);对照表见 `plain_language_guide.md` §6。验收查这些表述。
11. **语言规范**:以 buyside-voice 的 `references/voice-rules.md` 为准(破折号全篇 ≤8、判断性警句 ≤8 且只放结论位、禁词 0、FACT / 估算 / 判断三档语气、至少一处明示不确定、至少一处反方观点)。本机装有 buyside-voice 时,交付前对合并后的 MD 跑 `scripts/voice_scan.py`,可数项须 PASS。
12. 通俗不是营销腔:不许夸张、不许比数据说得满。
13. **精炼**:每段只讲一件事;表能说清的不再用段落复述;零章讲过的,正文只引用不重述;技术章每对方案的差异一两句,细节进表。

## 6 渲染器语法(`scripts/render_report_v32.py` 文件头有全字段)

- 零章速览版式:章题含「速览」的一章自动排成摘要区 + 编号分节(见 §2),作者照常写 `[!lead]`、`kpis`、`###` 即可。
- `> [!plain] …`、`> [!analogy] …`、`> [!example] …`:**页面上不显示任何标签字样**,正文字号、左侧细线,不用底色;零章内与正文同样式。以「投资含义:」开头的块自动加浅灰底和深蓝左线,首句加粗。
- ```` ```roadmap {JSON} ````:技术演变路线图,计入示意图(图表目录记为「路线图」);徽标为「当前主流」「尚未量产」,行名为「解决的问题 / 代价 / 受益与受损方」,分岔为「成立条件 / 验证信号」;手机宽度自动竖排。
- ```` ```flow ```` 的 `lanes`(每行一种方案)适合画方案结构对比;`"legend": false` 关掉自动图例。
- ```` ```chain ```` 的 `"legend"`:默认图例是「虚线 = 钱的流向」;虚线表示别的含义时写成自定义文字,或 `false` 隐藏。
- ```` ```glossary 术语 | 含义 | 投资相关性 ```` :词典表(三列;旧的四列「可以理解为」格式仍可渲染),行锚点 `gl-N`;正文悬停释义由此生成(离线 JS,无外部请求)。
- 语法样例:`assets/fixture/fixture.md` 末节;完整样例:`examples/pm/`。

## 7 评审 C:外行复述

在评审 A(版式深度)、评审 B(数字核对)之外加一路:子代理扮演「懂财务、不懂这门技术的基金经理」,**只读通俗层**(零章、各章 lead 与通俗解释块、技术章),不看证据层,用自己的话复述六件事(**与前代 / 同类产品的差异**、工作原理(只看文字和产品图)、客户与付费方、价值流向、技术演变、跟踪指标),并逐条列出卡住的词句、像模板标签或口语化的表述。主线对照原文判定复述「对 / 偏 / 错」;有「错」或卡住的地方 >5 处,改通俗层后换新子代理重评。协议见 `references/review_protocol.md` §3,记录写 `work/reader_test.md`,结论进评审处理记录。
