# 踩过的坑(阳光电源、德科立、诺基亚 DCI、CPO、宏和、泡泡玛特等卡累积)

## 口径与页码
- **页码**:A 股招股书常见「印刷页码 = PDF 页码 − 1」。全卡统一写 PDF 页码,按页文本的 `=== pN ===` 就是 PDF 页码。
- **两套分部口径**:年报第三节「主营业务分产品」(主营收入,有同比与毛利率)与附注「营业收入、营业成本的分解信息」(营业收入口径,
  含其他业务;半年报只有这一口径)数字不同。Wind 的分部数可能取附注口径。底座里两口径分开列,每张图写明用哪套。
- **分类改版**:公司常中途改口径(泡泡玛特 2025 中报改地区口径、2023 年 IP 并档、2026 中报 MEGA 并入衍生品;德科立 2023 年
  起按应用分类)。改版前后要回拆或分段画,对不齐的年份写明。
- **管理层讨论数 ≠ 附注按性质数**;**说明会口径 ≠ 短信注记口径**(F&LC 分部利润 royalty 前后差约 3%)。
- **目标 ≠ 实绩**:英文版常误译(F&LC「340 店」是期末目标)。**合同上限 ≠ 已拨付 ≠ 收入**。**bookings ≠ revenue**。
- **单位经济分母**:发货量、确收量、滞后口径差很大(阳光储能每瓦时收入 0.87 / 1.05 / 1.18 元),并列写。
- 周转天数按全年 360 天、半年 180 天;有息负债写明是否含长期应付款与租赁负债,并与 Wind 带息债务对照。
- 研报原图日期取报告封面,AlphaPai 入库日可能晚 1 天。

## 取数工具
- **AlphaPai**:`recall` 全文召回积分不足(code 400000),不要调;`image` 可用,pageIndex 从 0 起,页码 = pageIndex + 1。
- **Wind** 按次计费:只取历史财务与细分业务,一张卡最多 1 次(以用户当次规则为准),结果落盘进底座,子代理一律不许再调。iFind 不用。
- **FMP** 只做定点核对,不批量。
- **EDGAR** 必须 `curl --noproxy '*'`;User-Agent 用非个人联系串,不要用用户邮箱。
- **科创板问询回复**:`query.sse.com.cn` 的 `sqlId=GP_GPZCZ_SHXXPL&stockAuditNum=<项目号>` 列全部回复 PDF,要带 Referer `https://kcb.sse.com.cn/`。
- **卖方 PDF 字体编码**:银河证券 PDF 数字抽出来是乱码,「眻眼眽眾眿着睁睂睃睄」依次 = 0–9,先解码再用(存 `*_decoded.txt`)。
- **Q4 / Notified 托管的 IR 站**被 Akamai 挡,curl 与页面内 fetch 都 403;请用户用真实浏览器下载,或找 EDGAR 8-K 附件与 IR 补充材料直链。
- 国内官网 ajax 型号卡 curl 只见 banner,走浏览器路径(`fetch_visuals.py` 的 BROWSER_SNIPPET)。
- 港股公司常不发业绩演示 PDF;内地人民币零售价网页常拿不到(电商要登录),写「数据不可得」或用港币官网价并写明。

## 版式与渲染
- 专题章(上游、客户与认证、股东与治理、IP 与设计师体系、渠道与会员等)的 h3 **不要**用「行业规模 / 竞争格局 / 具体产品 / 核心竞争」,
  否则渲染器按主业章要求 ≥12 张图。
- **不要堆图**:德科立首稿 153 张被评审判为重复堆砌,删到 119 张。目标 55–70,同一信息不重复出图。
- 图片 alt 必须带类别前缀(研报原图 / 招股书原图 / 年报原图 / 官方图 / 官网 / 实物图 / 流程图 / 示意图 / 结构图 / 作者自绘)。
- 半角标点、交叉引用链接、宽图压缩、并排图等高由渲染器处理,不必手改;有序列表起始编号渲染器已支持。
- 截图:页面 CSS 有平滑滚动,`scripts/shots.py` 已关掉并按 h2 定位;验收看 `shots.json` 的 `chapters[].ok`。
- 内置浏览器面板打不开 `file://`;预览服务读不了 iCloud 同步的 `~/Desktop` 时,把 HTML 复制到会话 scratchpad 再起服务。

## 写法
- **页头用途行**:写「买方内部研究 · 不含估值、目标价与评级」会被照抄检查判中(与参考报告 3 字片段重合 ≥0.30),整卡 gate 不过;用「供内部投研使用 · 本卡不写估值、目标价与评级」(诺基亚 DCI 卡用过)。
- 「锚定」是 buyside-voice 禁词表里的词,章题要用时改成「对照」。
- 不写估值、目标价、评级、卖方盈利预测;含这些内容的研报原图整张不用。
- 用户嫌「AI 味」:判断先行、推理看得见、少警句少比喻少破折号;标题即结论;框架术语不摊开。

## 编排
- workflow 的核验阶段曾撞 session limit 全部失败:关键数字主线自己 grep 一手文本复核一遍,不要只信子代理的「已核对」。
- 子代理写完一节就落盘(防网络中断);回主线的摘要 ≤300 字。
- 主线上下文守 18%:不读参考 HTML、样例 MD、PDF、按页文本、渲染后 HTML 的全文,只 grep / head。
- 交付习惯:HTML 另存「公司科普-YYMMDD.html」(日期用当天),上传用户飞书云空间根目录(lark-drive skill);
  交付时一句话报图数(交互 / 图片 / 自绘)、表数、汉字数(渲染器口径与纯叙述)和数据缺口。

## 基金经理版(2026-09-29 两轮反馈后加)
- **反馈原话**:「一上来都是专业术语,没有基础背景的人可能比较难读明白」「少一些用简要通俗的语言来解释技术和技术变化路径的部分」「Palantir 没看明白公司业务」。
  v3.2 卡片在懂行的评审眼里合格,在基金经理眼里不合格:评审 A 自己懂术语,查不出这个问题,所以加了评审 C(外行复述)。
- **总览第一段不是白话**:「本质是一家大功率电力电子变换平台」「按利润来源看,是一家卖功率变换设备和储能系统的公司」对分析师是白话,对基金经理仍是术语。零章的「一句话」要过「把公司名换成『这家公司』,外行能不能说出它属于哪类生意」这个测试。
- **括注也是术语**:「SST(用碳化硅器件和高频变压器替代工频变压器)」括注里又有三个术语。括注只许用通俗说法。
- **技术内容散在各章**:型号、参数、时间轴分布在各业务章 x.3 / x.4,没有一处讲「为什么一代代这样变」。技术章集中讲路径,业务章只讲本业务的参数。
- **路线图只写好处**:每一代都写「更省电、更快」,不写代价和受损方,读者看不出产业链格局为什么会变。`cost` 与 `who` 两格必填。
- **平台型、新物种公司**:产品名本身是黑话(Gotham / Foundry / Apollo / AIP、Ontology)。先用类比建立画面,再给名字;用「与 XX 的差异」一节把读者最可能套错的类别(普通 SaaS、数据平台、咨询外包)逐项比清。
- **例子要前后对比**:「空客用了 Foundry」没有信息量;「以前一架飞机卡在工位上要很久才能追到原因,现在按每架飞机 × 每道工序看到哪里缺件」才让人看懂产品做了什么。
- **通俗层数字过多**:零章塞进 74.2%、+137%、5.07 亿美元这类精确值会把读者拉回证据层。零章 ≤5 个数,取整写。
- **词典凑字数**:术语词典章不计入 10,000 字门槛(渲染器自动扣除);也不要把正文该写的解释挪到词典里,正文首现处仍要括注。
- **重评换人**:评审 C 不通过时,重评必须换一个新子代理;看过上一版的子代理已经懂了,不再是外行。
- **旧卡升级**:已有 v3.2 卡片改成基金经理版时,正文证据层可以保留,新写零章、技术章、各业务章开头的通俗解释和各章 NN_terms.md,card.json 加 `edition: "pm"` 与 `plain`,out_stem 改名,重跑 merge_card.py;原 9.x 名词表并入词典(改成 glossary 块或拆进 NN_terms.md)。
- **(第二轮)标签外露**:第一稿样例用「白话」徽标、「打个比方:」「举个例子:」「一句话:」前缀标出每一块,基金经理说「『白话』这样的标签不要直接写上去」。
  现在零章用问题式小标题分块,类比 / 例子用块类型只改底色,渲染器不再显示徽标;`--pm` 查段首标签前缀和标题里的「白话」。
- **(第二轮)只讲份额不讲差别**:v3.2 的竞争格局讲份额和排名,读者仍不知道「Palantir 和普通 SaaS 有什么区别」「CPO 和可插拔、和 NPO 的区别」。
  零章与技术章必须各有一节「与 XX 的差异」:先分类 → 结构对比图 → 每对方案的差异与代价 → 逐项对比表 → 投资含义。
- **对比对象选错**:和行业内部的细分对手比(Palantir 对 C3.ai),读者一个都不认识。先和读者脑子里已有的那一类比(普通 SaaS),再在证据层讲细分对手。
- **对比表只写优点**:本公司那一列全是好处,读者不信。每个优点写出对应的代价(卖得慢、客户集中;维修难、厂商少)。
- **(第三轮)零章版式与用语**:第二稿零章是一列提示块,小标题是「它像什么」「钱怎么来」「技术怎么一步步变过来」「最该盯的一件事」这类问句,基金经理认为版式不好看、表述 AI 化。
  现在零章由渲染器排成速览版式(摘要面板 + 编号卡片),小标题用买方用语(业务本质 / 客户案例 / 与 XX 的差异 / 价值流向 / 技术演变 / 跟踪指标);`--pm` 查口语化表述。
- **(第三轮)口语化句式**:「麻烦在于」「这件事要紧,是因为」「有两面」「不是 X 而是 Y」「说白了」这类句式在通俗层里显得随意;按 `plain_language_guide.md` §6 换成书面说法。语言规范以 buyside-voice 的 voice-rules 为准。
- **v3.2 样卡的图题**:`examples/sungrow/card_v32.md` 里有「钱怎么流」这类图题,基金经理版不要照搬,写「价值流向」。
