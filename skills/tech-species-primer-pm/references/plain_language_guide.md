# 白话写法指南(基金经理版)

> 给章节 agent 和主线用。规格(放在哪、写多少、验收什么)在 `references/DESIGN_pm.md`;这里讲**怎么写**。
> 读者:懂财务报表、估值和行业比较,不懂这门技术的基金经理。检验标准只有一个:**他读完能不能用自己的话讲给别人听**。

## 1 三条总原则

1. **先画面,后概念。**读者脑子里先要有一个能「看见」的场景(一个工厂厂长查不到订单为什么晚交;数据从芯片走十几厘米铜线到面板),再给这个场景起名字(本体、CPO)。v3.2 的顺序是反的:先给定义,再解释。
2. **先问题,后方案。**任何技术和产品都先讲「客户原来的麻烦是什么、旧办法为什么不够」,方案才有意义。没有问题的方案,读者记不住。
3. **先结论,后证据。**每一段、每一节的第一句是白话结论;数据、口径、页码跟在后面。读者读完第一句就可以跳走。

## 2 句子级规则

| 规则 | 反例 | 正例 |
|---|---|---|
| 主语是人或东西,不是概念 | 交付模式偏重,边际成本下降空间有限 | 每签一个客户就要派一队工程师驻场几个月,所以收入涨一分,人也要加一分 |
| 不堆名词 | 新能源电源设备的研产销服一体化平台 | 做电站、电网和数据中心里「变换电」的设备,自己研发、生产、销售和维修 |
| 不用术语解释术语 | CPO(将光引擎与交换 ASIC 共封装的技术) | CPO(共封装光学:把电转光的零件和交换芯片封在一起) |
| 缩写首现:中文名 + 缩写 + 一句白话 | LPO 方案去掉 DSP | 线性驱动模块(LPO)拿掉了专门修信号的芯片(DSP),由交换芯片自己把信号处理好 |
| 一段新术语 ≤2 个 | 一段里连出 SerDes、DSP、LPO、NPO、ELS | 拆成两段,或把后几个留到技术白话章的路线图里逐代讲 |
| 数字白话化(白话层) | 美国收入占比 74.2% | 美国收入约占四分之三(精确值 74.2% 留在证据层) |
| 动词具体 | 赋能客户数字化转型 | 让厂长在一个屏幕上看到每张订单卡在哪个零件,并直接改排产 |
| 说清因果 | AIP 驱动美国商业高增长 | 5 天训练营取代了 1–3 个月的试点,同样的人手能接触多得多的客户,所以美国企业客户数加速增长 |

## 3 零章六块怎么写

对照 `examples/pm/pltr_plain_sample.md` 与 `examples/pm/cpo_tech_path_sample.md` 的零章读。

- **一句话**:「卖什么东西 + 帮谁解决什么问题」。写完做一个测试:把公司名换成「这家公司」,一个外行能不能说出它大概属于哪一类生意。不能,就是还不够白。
- **打个比方**:四步——客户原来的麻烦 → 用熟悉的东西类比产品做的事 → 说清类比在哪里不成立 → 把公司自己的叫法对上(「公司把这层叫 Ontology(本体)」)。类比只选一个,选结构对得上的,不选听起来漂亮的。
- **举个例子**:必须是真实客户或真实场景,写成前后对比。好例子有三个要素:**谁**(空客、某家医院)、**以前怎么样**(一架飞机卡在工位上,要花很多时间追原因)、**现在怎么样**(按每架飞机 × 每道工序看到哪里缺件)。厂商宣称的效果标〔厂商口径〕;找不到公开的真实例子,就写一个行业里的典型场景,并明写「典型场景,非特定客户」。
- **钱怎么来**:谁付钱、按什么收费、为什么会重复买或越买越多、收入最大的一块、成本大头。平台软件要讲清「先小后大」;制造业要讲清「按件卖、价格跟什么走」;消费品讲清「谁买单、在哪买、为什么复购」。
- **技术怎么变**:3–5 步,每步一句「解决了上一代什么麻烦」。只写阶段名和一句话,不写型号。
- **要盯的一件事**:写成可以去查的东西:「看什么数、多久能看到一次」。

**「是什么、不是什么」表**:先想读者最可能把这家公司套进哪个熟悉的格子(数据库?咨询?大模型?光模块厂?),逐一说明哪里像、哪里不像。这张表对平台型、新物种公司特别有用。

## 4 技术白话章怎么写

- **x.1 问题**:从用户的用户讲起(GPU 在等数据;厂长在等报表)。一个类比即可。
- **x.2 原理图**:按「东西流动的顺序」画(信号、物料、数据、钱),每个方框一个名词 + 一句白话;把下一代要改动的环节标 hot。图后用一段话点出决定成本和性能的两三个环节。
- **x.3 路线图(roadmap 块)怎么填**:
  - `name` 写成「代际名:一句话作用」(「AIP:让大模型在本体上干活」),不要只写型号。
  - `gist` 一句白话:这一代长什么样。
  - `solves` / `cost` / `who` 每格 ≤40 字。`cost` 一定要写,**技术演进从来不是免费升级**,基金经理最关心的正是代价落在谁身上。`who` 写「受益:…;受损:…」。
  - 当前出货主力标 `now`,未量产标 `future`;`fork` 写 2–3 个方向,每个写 `if`(赢的条件)和 `signal`(看什么信号)。
  - 3–6 代为宜;代际划分按「解决的问题变了」,不按型号更新。
- **代际对比表**:列用白话(「电信号要走多远」「坏了怎么修」「谁说了算」),不用参数名(「pJ/bit」「插损」)。参数对标留在业务章 x.4。
- **x.5 对公司意味着什么**:技术变化 → 卖的东西(量、价、形态)→ 份额与话语权 → 成本与毛利率,每处一两句,指向后面章节。

## 5 类比库(拿来改,不要照搬;每个类比都写上「不同的是」)

| 领域 | 概念 | 类比 | 类比的边界(不同的是) |
|---|---|---|---|
| 半导体 | 晶圆代工 | 印刷厂:客户出设计稿,代工厂负责印 | 印一次的「制版」成本极高,只有量大才划算 |
| 半导体 | 制程(几纳米) | 印刷精度:线越细,同一张纸上能印越多字 | 数字已不对应真实线宽,只是代际名 |
| 半导体 | 良率 | 一炉面包里能卖的比例 | 芯片是整片烤,坏一处可能整颗报废 |
| 半导体 | 先进封装 | 把几个小房间打通成一套大户型 | 打通后坏了一间,整套都要换 |
| 半导体 | EDA 设计软件 | 芯片的建筑设计软件 | 设计错了没法「现场改」,要重新流片 |
| 光通信 | 光模块 | 电和光之间的翻译器 | 翻译本身就耗电发热 |
| 光通信 | 交换机 / 交换芯片 | 路口与路口的指挥中心 | 路口越大,进出的「车道」越多 |
| 光通信 | 速率(800G / 1.6T) | 一条路有几条车道 | 车道翻倍,路面(铜线)质量要求也翻倍 |
| 电力电子 | 逆变器 | 电的「换币种」:把直流换成电网用的交流 | 换的同时还要管电压、频率和电网安全 |
| 储能 | 储能系统 | 电网的充电宝 | 按兆瓦时计,要管几十年的安全和寿命 |
| 储能 | 电芯 → 电池包 → 系统 | 砖 → 墙 → 房子 | 房子的价值在设计和集成,不只在砖 |
| 企业软件 | 订阅收费 | 按年交房租 | 房东(软件商)要持续装修(更新)才续得上约 |
| 企业软件 | 实施 / 部署 | 装修 | 装修越深,换房东越难 |
| 企业软件 | 数据仓库 | 档案馆:存和查 | 档案馆不负责据此做决定 |

| 医药外包 | CRO / CDMO | 药企外包的研发团队 / 代工厂 | 要按药监规范留全套记录,换供应商很慢 |

## 6 改写前后对照

**① 公司一句话(平台软件)**

- 改前:Palantir 是一家以 Ontology 为核心,通过 Gotham、Foundry、Apollo、AIP 四大平台为政府与商业客户提供数据整合与 AI 决策能力的软件公司。
- 问题:一句话里 6 个读者不认识的词;「数据整合与 AI 决策能力」是抽象名词,读者看不见画面。
- 改后:Palantir 卖的是一套软件,把一个大机构散落在几十个系统里的数据接到一起,按「现实里的东西」重新摆好,让人(现在也让 AI)在同一个界面上看清情况、做出决定,再把决定直接发回原来的系统去执行。(接着用工厂厂长的比方,再用空客的例子。)

**② 技术定义(产业链)**

- 改前:CPO 将光引擎与交换 ASIC 共封装,缩短电互连距离,降低 SerDes 功耗,相比可插拔方案每比特能耗显著下降。
- 问题:用术语解释术语;「显著下降」没有画面。
- 改后:CPO 是把「电转光」的零件从交换机前面板挪到交换芯片旁边、和芯片封在同一个封装里。数据原来要在电路板上走十几厘米铜线,现在只走几毫米,原本用来「修」信号的芯片大多可以省掉,所以更省电。

**③ 业务章章首(储能)**

- 改前:> [!lead] 储能系统:PCS + 电池舱 + EMS 一体化集成,2025 年收入 372.9 亿元,同比 +49.4%,毛利率 36.5%。
- 改后(lead 保留关键数,后面加白话块):
  > [!plain] 白话:储能就是给电网造「充电宝」:光伏发电多的时候把电存起来,用电高峰时再放出去。公司卖的是整台充电宝:电池主要外购,自己做的是控制充放电的「闸门」(储能变流器)和整套系统的设计集成。看这块业务,关键看两件事:每瓦时卖多少钱、电池涨价时毛利率守不守得住。

**④ 技术演进(时间轴 → 路线图)**

- 改前(时间轴,示意):第一代产品(2019)→ 第二代(2022,容量更大)→ 第三代(2025,电芯更大、能量密度更高)。
- 问题:只有代际名和参数,读者不知道每一代「为什么要换」、换了之后谁吃亏。
- 改后(roadmap 的一格,示意,不对应具体公司):`{"era":"第二代","name":"工厂预装:电池舱出厂前装好测好","gist":"整舱在工厂装好、测好再运到现场。","solves":"现场施工周期长、质量不稳","cost":"运输和吊装要求高,舱体规格被锁定","who":"受益:大型电站客户、有整舱制造能力的集成商;受损:现场集成服务商"}`

## 7 常见偏差

- **太啰嗦**:白话不是多写,是换写法。零章超过 1,800 字,通常是把证据层的数塞进来了,删数字,留画面。
- **白话变夸张**:「彻底改变」「无人能敌」照旧不许写;白话层的说法必须能在证据层找到对应的数。
- **类比过多**:每处只用一个;一段里出现第二个比喻,删掉较弱的那个。正文证据层仍按 v3.2「少比喻」。
- **把读者当小学生**:基金经理懂财务、懂估值、懂行业比较;不解释毛利率、同比、市占率,只解释技术和行业黑话。
- **样例照抄**:`examples/pm/` 的句子是写法示范,新卡的类比和例子要从本卡材料里找。

## 8 交付前自检(主线逐条过)

1. 只读零章,能不能说出:卖什么、卖给谁、怎么赚钱、技术怎么变、最该盯什么?
2. 零章有没有第一次见、却没解释的词?
3. 「打个比方」有没有说清边界?「举个例子」是不是真实、有出处、前后对比?
4. 技术白话章的路线图,每一代都写了「代价」吗?
5. 每个业务章 lead 之后都有白话块吗?第一句是不是白话结论?
6. 各章 `NN_terms.md` 都登记了吗?词典条目的「对投资意味着什么」是否具体(不是「很重要」)?
7. 白话层的数和证据层能对上吗?
8. `merge_card.py`(`--gate --pm`)通过了吗?评审 C 的复述有没有「错」?
