# 通俗写法指南(基金经理版)

> 给章节 agent 和主线用。规格(放在哪、写多少、验收什么)在 `references/DESIGN_pm.md`;这里讲**怎么写**。
> 读者:懂财务报表、估值和行业比较,不懂这门技术的基金经理。检验标准只有一个:**他读完能不能用自己的话讲给别人听**。

## 1 三条总原则

1. **先画面,后概念。**读者脑子里先要有一个能「看见」的场景(一个工厂厂长查不到订单为什么晚交;数据从芯片走十几厘米铜线到面板),再给这个场景起名字(本体、CPO)。v3.2 的顺序是反的:先给定义,再解释。
2. **先问题,后方案。**任何技术和产品都先讲「客户原来的麻烦是什么、旧办法为什么不够」,方案才有意义。没有问题的方案,读者记不住。
3. **先结论,后证据。**每一段、每一节的第一句是通俗的结论;数据、口径、页码跟在后面。读者读完第一句就可以跳走。

## 2 句子级规则

| 规则 | 反例 | 正例 |
|---|---|---|
| 主语是人或东西,不是概念 | 交付模式偏重,边际成本下降空间有限 | 每签一个客户就要派一队工程师驻场几个月,所以收入涨一分,人也要加一分 |
| 不堆名词 | 新能源电源设备的研产销服一体化平台 | 做电站、电网和数据中心里「变换电」的设备,自己研发、生产、销售和维修 |
| 不用术语解释术语 | CPO(将光引擎与交换 ASIC 共封装的技术) | CPO(共封装光学:把电转光的零件和交换芯片封在一起) |
| 缩写首现:中文名 + 缩写 + 一句话解释 | LPO 方案去掉 DSP | 线性驱动模块(LPO)拿掉了专门修信号的芯片(DSP),由交换芯片自己把信号处理好 |
| 一段新术语 ≤2 个 | 一段里连出 SerDes、DSP、LPO、NPO、ELS | 拆成两段,或把后几个留到技术章的对比表和路线图里逐个讲 |
| 数字取整(通俗层) | 美国收入占比 74.2% | 美国收入约占四分之三(精确值 74.2% 留在证据层) |
| 动词具体 | 赋能客户数字化转型 | 让厂长在一个屏幕上看到每张订单卡在哪个零件,并直接改排产 |
| 说清因果 | AIP 驱动美国商业高增长 | 5 天训练营取代了 1–3 个月的试点,同样的人手能接触多得多的客户,所以美国企业客户数加速增长 |

## 3 零章怎么写

对照 `examples/pm/pltr_plain_sample.md` 与 `examples/pm/cpo_tech_path_sample.md` 的零章读。**排版是一段加粗 lead + 六个问题式小标题,页面上不出现「白话」「一句话:」「打个比方:」「举个例子:」这类标签字样**;类比放 `[!analogy]` 块、例子放 `[!example]` 块,块类型只决定底色。

- **开头(lead)**:「卖什么东西 + 帮谁解决什么问题」,加粗。写完做一个测试:把公司名换成「这家公司」,一个外行能不能说出它大概属于哪一类生意。不能,就是还不够通俗。
- **它像什么**:四步——客户原来的麻烦 → 用熟悉的东西类比产品做的事 → 用「不同的是……」说清类比在哪里不成立 → 把公司自己的叫法对上(「公司把这层叫 Ontology(本体)」)。类比只选一个,选结构对得上的,不选听起来漂亮的。
- **一个真实的例子**:小标题直接写客户或场景名(「一个真实的例子:空客 A350」)。必须真实,写成前后对比,三个要素:**谁**、**以前怎么样**、**现在怎么样**。厂商宣称的效果标〔厂商口径〕;找不到公开的真实例子,就写行业里的典型场景,并明写「典型场景,非特定客户」。
- **和 XX 有什么不同**:XX 是读者最可能拿来套的那一类(Palantir → 普通 SaaS;CPO → 可插拔光模块和 NPO;品牌消费 → 同价位的竞品)。两三句说清差别 + 一张 5–6 行的对比表 + 一两句「对投资意味着什么」。写法见 §5。
- **钱怎么来**:谁付钱、按什么收费、为什么会重复买或越买越多、收入最大的一块、成本大头。平台软件讲清「先小后大」;制造业讲清「按件卖、价格跟什么走」;消费品讲清「谁买单、在哪买、为什么复购」。产业链卡可以改成「钱会流向谁」。
- **技术怎么一步步变过来**:3–5 步,每步一句「解决了上一代什么麻烦」。只写阶段名和一句话,不写型号。
- **最该盯的一件事**:写成可以去查的东西:「看什么数、在哪看、多久能看到一次」。

## 4 技术章怎么写

- 章题写「XX 是怎么回事、往哪走」,不写「技术白话」。
- **x.1 问题**:从用户的用户讲起(GPU 在等数据;厂长在等报表)。一个 `[!analogy]` 块即可。
- **x.2 原理图**:按「东西流动的顺序」画(信号、物料、数据、钱),每个方框一个名词 + 一句通俗说明;把下一代要改动的环节标 hot。图后用一段话点出决定成本和性能的两三个环节。
- **x.3 和替代方案比,差在哪**:见 §5,这是基金经理最常问的一节。
- **x.4 路线图(roadmap 块)怎么填**:
  - `name` 写成「代际名:一句话作用」(「AIP:让大模型在本体上干活」),不要只写型号。
  - `gist` 一句通俗说明:这一代长什么样。
  - `solves` / `cost` / `who` 每格 ≤40 字。`cost` 一定要写,**技术演进从来不是免费升级**,基金经理最关心的正是代价落在谁身上。`who` 写「受益:…;受损:…」。
  - 当前出货主力标 `now`,未量产标 `future`;`fork` 写 2–3 个方向,每个写 `if`(赢的条件)和 `signal`(看什么信号)。
  - 3–6 代为宜;代际划分按「解决的问题变了」,不按型号更新。
- **表格的列用通俗说法**(「电信号要走多远」「坏了怎么修」「谁说了算」),不用参数名(「pJ/bit」「插损」)。参数对标留在业务章 x.4。
- **x.6 对公司意味着什么**:技术变化 → 卖的东西(量、价、形态)→ 份额与话语权 → 成本与毛利率,每处一两句,指向后面章节。

## 5 怎么讲清「和竞品 / 替代方案差在哪」

基金经理第二轮反馈的原话:「要说清楚这个技术和竞品的区别,比如 Palantir 的产品和普通的 SaaS 有什么区别,CPO 和可插拔、和 NPO 的区别。」v3.2 的竞争格局讲份额和排名,**没讲做法有什么不同**,读者看完仍不知道它和同类产品差在哪。

**五步写法**(零章写精简版,技术章 x.3 写完整版):

1. **先选对比对象**:选读者脑子里已有的那个格子,不选行业内部才懂的细分对手。Palantir 的对比对象是「普通 SaaS」(再加数据平台、咨询外包),不是 C3.ai;CPO 的对比对象是「今天插在面板上的光模块」和「折中方案 NPO」,不是某家光引擎厂。
2. **先分类,再比较**:用一两句话把几种方案分成两三类,读者先有框架。例:「这四个名字其实分两类:LPO 只改模块里面;NPO 和 CPO 改的是光器件放的位置。」「普通 SaaS 管一个部门的一类流程;Palantir 不管固定流程,而是架在各系统上面。」
3. **画一张结构对比图**:把「差在哪」画成位置或层次的差别。光器件放在哪、信号走哪条路 → flow 块分泳道(每行一种方案);在客户 IT 里处在哪一层 → chain 块分层。图题直接写结论(「四种方案里,光器件离交换芯片有多远」)。
4. **每对相邻方案写一段,段首加粗一句差别**:「**NPO 和可插拔的差别在光器件搬到了哪。**」「**普通 SaaS 按人头收费,Palantir 按平台谈价。**」然后讲这个差别带来的好处和代价,两者都要写。
5. **逐项对比表 + 投资含义**:行是「比什么」,列是各方案。常用的比较维度:

| 维度 | 适合谁 | 例 |
|---|---|---|
| 解决什么 / 做什么 | 所有 | 一个部门的一类流程 vs 跨部门的具体问题 |
| 放在哪 / 处在哪一层 | 硬件、软件架构 | 面板插口 / 主板插座 / 同一封装;数据层 / 业务软件层 / 操作层 |
| 怎么上线 / 坏了怎么修 | 软件 / 硬件 | 开账号几周 vs 建本体几个月;拔下来换 vs 开箱换 vs 难单独换 |
| 怎么收费 / 谁付钱 | 所有 | 按人头 vs 按平台谈价;按件 vs 按系统 |
| 谁说了算 / 价值落在谁手里 | 产业链 | 模块厂 vs 芯片厂与封装厂 |
| 代价或短板 | 所有 | 卖得慢、客户集中;维修难、厂商少 |
| 今天到了哪一步 | 新技术 | 大规模出货 / 小规模试用 / 样品 |

表后放一个 `[!plain]` 块,一两句话说这些差别对投资意味着什么:**该看的指标不同**(普通 SaaS 看付费用户数,Palantir 看单客户收入和加购),或**价值落在谁手里不同**(从模块厂移向芯片厂和封装厂)。

**三条纪律**:说差别不说好坏(好坏留给证据层和数据);每个优点都写对应的代价;单元格用通俗短语,不用参数名。收费方式、市场阶段这类说法写明出处或标「常见做法」。

## 6 类比库(拿来改,不要照搬;每个类比都写上「不同的是」)

| 领域 | 概念 | 类比 | 类比的边界(不同的是) |
|---|---|---|---|
| 半导体 | 晶圆代工 | 印刷厂:客户出设计稿,代工厂负责印 | 印一次的「制版」成本极高,只有量大才划算 |
| 半导体 | 制程(几纳米) | 印刷精度:线越细,同一张纸上能印越多字 | 数字已不对应真实线宽,只是代际名 |
| 半导体 | 良率 | 一炉面包里能卖的比例 | 芯片是整片烤,坏一处可能整颗报废 |
| 半导体 | 先进封装 | 把几个小房间打通成一套大户型 | 打通后坏了一间,整套都要换 |
| 半导体 | EDA 设计软件 | 芯片的建筑设计软件 | 设计错了没法「现场改」,要重新流片 |
| 光通信 | 光模块 | 电和光之间的翻译器 | 翻译本身就耗电发热 |
| 光通信 | 交换机 / 交换芯片 | 路口与路口的指挥中心 | 路口越大,进出的「车道」越多 |
| 光通信 | 速率(800G / 1.6T) | 一条路有几条车道 | 车道翻倍,路面(铜线)质量要求也翻倍 |
| 电力电子 | 逆变器 | 电的「换币种」:把直流换成电网用的交流 | 换的同时还要管电压、频率和电网安全 |

| 企业软件 | 实施 / 部署 | 装修 | 装修越深,换房东越难 |

| AI | 大模型 | 读过海量书、但不认识你公司的聪明新人 | 它会一本正经地说错,需要有人把关 |
| AI | 训练 vs 推理 | 上学 vs 上班 | 上学一次性花大钱,上班按量持续花钱 |

| 医药外包 | CRO / CDMO | 药企外包的研发团队 / 代工厂 | 要按药监规范留全套记录,换供应商很慢 |
| 消费 | IP | 角色的版权 | 版权会过气,要不断出新角色 |

## 7 改写前后对照

**① 公司一句话(平台软件)**

- 改前:Palantir 是一家以 Ontology 为核心,通过 Gotham、Foundry、Apollo、AIP 四大平台为政府与商业客户提供数据整合与 AI 决策能力的软件公司。
- 问题:一句话里 6 个读者不认识的词;「数据整合与 AI 决策能力」是抽象名词,读者看不见画面。
- 改后:Palantir 卖的是一套软件,把一个大机构散落在几十个系统里的数据接到一起,按「现实里的东西」重新摆好,让人(现在也让 AI)在同一个界面上看清情况、做出决定,再把决定直接发回原来的系统去执行。(接着用工厂厂长的比方,再用空客的例子。)

**② 技术定义(产业链)**

- 改前:CPO 将光引擎与交换 ASIC 共封装,缩短电互连距离,降低 SerDes 功耗,相比可插拔方案每比特能耗显著下降。
- 问题:用术语解释术语;「显著下降」没有画面。
- 改后:CPO 是把「电转光」的零件从交换机前面板挪到交换芯片旁边、和芯片封在同一个封装里。数据原来要在电路板上走十几厘米铜线,现在只走几毫米,原本用来「修」信号的芯片大多可以省掉,所以更省电。

**③ 业务章章首(储能)**

- 改前:> [!lead] 储能系统:PCS + 电池舱 + EMS 一体化集成,2025 年收入 372.9 亿元,同比 +49.4%,毛利率 36.5%。
- 改后(lead 保留关键数,后面加一段通俗解释;不写「白话:」前缀,直接从内容写起):
  > [!plain] 储能就是给电网造「充电宝」:光伏发电多的时候把电存起来,用电高峰时再放出去。公司卖的是整台充电宝:电池主要外购,自己做的是控制充放电的「闸门」(储能变流器)和整套系统的设计集成。看这块业务,关键看两件事:每瓦时卖多少钱、电池涨价时毛利率守不守得住。

**④ 技术演进(时间轴 → 路线图)**

- 改前(时间轴,示意):第一代产品(2019)→ 第二代(2022,容量更大)→ 第三代(2025,电芯更大、能量密度更高)。
- 问题:只有代际名和参数,读者不知道每一代「为什么要换」、换了之后谁吃亏。
- 改后(roadmap 的一格,示意,不对应具体公司):`{"era":"第二代","name":"工厂预装:电池舱出厂前装好测好","gist":"整舱在工厂装好、测好再运到现场。","solves":"现场施工周期长、质量不稳","cost":"运输和吊装要求高,舱体规格被锁定","who":"受益:大型电站客户、有整舱制造能力的集成商;受损:现场集成服务商"}`

**⑤ 和竞品的区别(产业链)**

- 改前:CPO 相比可插拔方案功耗更低、带宽密度更高;NPO 为过渡方案,可维护性优于 CPO。
- 问题:只给结论,没说差别从哪来;读者不知道三者在物理上差在哪,也不知道「可维护性」具体指什么。
- 改后:三种方案做的是同一件事,**差别只在光器件放在哪、离芯片多远**。可插拔插在前面板,芯片到光器件要走十几厘米铜线,坏了拔下来换;NPO 把光引擎挪到芯片旁边的主板插座上,铜线缩到几厘米,坏了开箱拔下单个换;CPO 把光引擎和芯片封在一起,铜线只剩几毫米,最省电,但光引擎坏了难单独换。(接一张四行的结构对比图和逐项对比表。)

**⑥ 和竞品的区别(平台软件)**

- 改前:Palantir 与 Snowflake、Databricks、C3.ai 及云厂商在企业 AI 平台市场竞争,差异化在于 Ontology 与 FDE 模式。
- 问题:对比对象选成了行业内部的细分对手,读者一个都不熟;「差异化在于 Ontology」是用术语解释差别。
- 改后:普通 SaaS 一个产品管一个部门的一类流程(Salesforce 管销售,Workday 管人事),开账号就能用,按人头收费;**Palantir 不替代这些系统,而是架在它们上面**,把各系统的数据接起来解决跨部门的问题,要先把客户业务建模再上线,按平台谈价、签多年合同。(接一张「各自处在客户 IT 的哪一层」的分层图和逐项对比表。)

## 8 常见偏差

- **太啰嗦**:通俗不是多写,是换写法。零章超过 2,200 字,通常是把证据层的数塞进来了,删数字,留画面。
- **通俗变夸张**:「彻底改变」「无人能敌」照旧不许写;通俗层的说法必须能在证据层找到对应的数。
- **标签外露**:第一稿样例用「白话」徽标和「打个比方:」「举个例子:」前缀标出每一块,基金经理嫌像模板。分块用小标题或块类型,页面上不写写作标签。
- **只说好处**:对比表里本公司那一列全是优点,读者不信。每个优点写出对应的代价(卖得慢、维修难、厂商少)。
- **类比过多**:每处只用一个;一段里出现第二个比喻,删掉较弱的那个。正文证据层仍按 v3.2「少比喻」。
- **把读者当小学生**:基金经理懂财务、懂估值、懂行业比较;不解释毛利率、同比、市占率,只解释技术和行业黑话。
- **样例照抄**:`examples/pm/` 的句子是写法示范,新卡的类比和例子要从本卡材料里找。
