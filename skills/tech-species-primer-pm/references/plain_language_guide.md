# 通俗写法与买方用语指南(基金经理版)

> 给章节 agent 和主线用。规格(放在哪、写多少、验收什么)在 `references/DESIGN_pm.md`;这里讲**怎么写**。
> 读者:懂财务报表、估值和行业比较,不懂这门技术的基金经理。检验标准只有一个:**他读完能不能用自己的话讲给别人听**。

## 1 三条总原则

1. **先画面,后概念。**读者脑子里先要有一个能「看见」的场景(一个工厂厂长查不到订单为什么晚交;数据从芯片走十几厘米铜线到面板),再给这个场景起名字(本体、CPO)。v3.2 的顺序是反的:先给定义,再解释。
2. **先问题,后方案。**任何技术和产品都先讲「客户原来的麻烦是什么、旧办法为什么不够」,方案才有意义。没有问题的方案,读者记不住。
3. **先结论,后证据。**每一段、每一节的第一句是通俗的结论;数据、口径、页码跟在后面。读者读完第一句就可以跳走。
4. **精炼、准确。**第五轮反馈:「字还是有点多,不够精炼;UI 不够严肃、不够准确」。每段只讲一件事,能进表的进表,表后不复述;数字写精确值并注明期间,不写「约」「常年」;类比至多一处,不用生活化比喻。

## 2 句子级规则

| 规则 | 反例 | 正例 |
|---|---|---|
| 主语是人或东西,不是概念 | 交付模式偏重,边际成本下降空间有限 | 每签一个客户需派驻一支工程团队数月,收入增长与人员投入基本同步 |
| 不堆名词 | 新能源电源设备的研产销服一体化平台 | 生产电站、电网和数据中心使用的电能变换设备,研发、生产、销售与运维自营 |
| 不用术语解释术语 | CPO(将光引擎与交换 ASIC 共封装的技术) | CPO(共封装光学,把光电转换器件与交换芯片封装在一起) |
| 缩写首现:中文名 + 缩写 + 一句话解释 | LPO 方案去掉 DSP | 线性驱动模块(LPO)去掉了模块内的信号处理芯片(DSP),由交换芯片承担信号处理 |
| 一段新术语 ≤2 个 | 一段里连出 SerDes、DSP、LPO、NPO、ELS | 拆成两段,或把后几个留到技术章的对比表和路线图里逐个讲 |
| 数字写精确值并注明期间 | 美国收入约占四分之三;毛利率常年约八成 | 美国收入占比 81%(2Q26,15.73 亿美元);毛利率 85%(GAAP,2Q26) |
| 厂商口径写发布时间 | 英伟达称能效提升约 3.5 倍 | 英伟达称网络能效为可插拔方案的 3.5 倍〔厂商口径,2025-03 发布〕 |
| 动词具体 | 赋能客户数字化转型 | 管理者在同一界面定位每张订单的缺件环节,并直接调整排产 |
| 说清因果 | AIP 驱动美国商业高增长 | 5 天训练营替代了 1–3 个月的试点,同等人力可覆盖的客户数大幅增加,美国企业客户数因此加速增长 |

## 3 零章「业务速览」怎么写

对照 `examples/pm/pltr_plain_sample.md` 与 `examples/pm/cpo_tech_path_sample.md` 的零章读。版式由渲染器生成(研报首页式:导语与关键数据 + 编号分节),作者只写:一段加粗 lead、一个 `kpis` 块、六个 `###` 小节。**篇幅**:全章 400–1,200 字(不含图内文字与来源),导语 ≤90 字,每节正文 ≤160 字,验收硬查。**页面上不出现「白话」「一句话:」「打个比方:」「举个例子:」这类标签字样,也不用「它像什么」「钱怎么来」这类问句式小标题**(用语见 §6)。

- **开头(lead + 关键数据)**:加粗一句话写公司做什么、为谁解决什么问题。写完做一个测试:把公司名换成「这家公司」,外行能不能说出它属于哪一类生意。关键数据 3–4 项,选读者最先会问的:收入与增速、收入结构、地区或客户占比、毛利率;产业链卡写厂商口径的性能数据与量产节点。**写精确值,标签或注释写期间与口径**(验收查「约」「常年」和期间)。
- **先比后讲**:人理解一项新技术,通常先拿它和来源、或上一代解决同一需求的技术作对比。所以零章第一节固定是「与 XX 的差异」,第二节才是「工作原理」。
- **与 XX 的差异(第一节)**:XX 是读者已熟悉的前代技术或同类产品(Palantir → 普通 SaaS;CPO → 可插拔光模块,NPO 作为折中一并列出)。一句点明参照物(「理解 Palantir 最直接的参照是普通 SaaS」「CPO 要替代的是当前的可插拔光模块」)+ 一张 5–6 行的对比表(单元格用短语)+ 一句「投资含义:」。表前后不再写段落复述表。写法见 §5。
- **工作原理(第二节)**:一段通俗说明(≤160 字):产品在客户那里做什么、关键环节怎么运作、与参照物差在哪一步;最后对上公司自己的叫法。优先用商业或技术参照(「与报表工具的区别在最后一步」),不用生活化比喻。**紧接一张产品图,图下不再写解释文字**:图本身要能看懂(界面截图标出关键区域,实物图或结构示意标出关键部件或层级);示意图不虚构界面文字和数据。来源顺序与自绘兜底见 DESIGN_pm §2「产品图」。
- **典型案例**:第六轮反馈要求「案例多放一点,尤其是典型案例」。写法是**详写一个 + 表列三个左右**:详写最有代表性的一个(≤160 字,三个要素:**谁、何时、可核对的效果**,如「空客称 A350 生产节奏加快 33%」);表 0-2 列其他典型客户,列为「客户 / 时间 / 用途 / 规模或效果」,选法是让读者看到**客户类型的广度**(政府与企业、不同行业)和**规模的量级**(合同上限、年数、效果数字)。每行都要有出处,厂商宣称标〔厂商口径〕,媒体报道标〔公开报道〕;不列只有客户名、没有用途和效果的行。产业链卡写推进最快的厂商,表里列客户验证、量产与部署。验收查案例 ≥3 个。
- **价值流向**:付费方、计费方式、复购或扩容来源、收入结构、主要成本项。平台软件写清「先落地、再扩张」;制造业写清「按件销售、价格随什么变动」;消费品写清「谁付费、在哪买、复购来源」;产业链卡写价值在各环节之间如何分配、谁有定价权。
- **技术演变**:一句话概括方向,再用 `timeline` 块列 3–5 个阶段,每个阶段一句「解决了上一代的什么问题」。只写阶段名和一句话,不写型号。
- **跟踪指标**:写成表 0-2(2–3 行:指标 / 最新值与期间,或看什么 / 看点或来源与频率);表后一句市场的主要担心、我们的把握程度和验证信号(voice-rules §5 对手盘意识)。

## 4 技术章怎么写

- 章题:公司卡「技术与产品:原理、差异与演变」,产业链卡「技术解析:原理、方案差异与演变路线」。不写「技术白话」「是怎么回事」「往哪走」。
- **x.1 要解决的问题**:从用户的用户讲起(GPU 在等数据;厂长在等报表)。两三句,不必再放类比。
- **x.2 原理**:按「信号、物料、数据、资金」的流向画,每个方框一个名词 + 一句说明;把下一代要改动的环节标 hot。图后用一段话点出决定成本和性能的两三个环节。
- **x.3 与替代方案的差异**:见 §5,这是基金经理最常问的一节。
- **x.4 技术演变(roadmap 块)怎么填**:
  - `name` 写成「代际名:一句话定位」(「AIP:大模型接入本体」),不要只写型号。
  - `gist` 一句话说明这一代的形态。
  - `solves` / `cost` / `who` 每格 ≤40 字。`cost` 一定要写,**技术演进从来不是免费升级**,基金经理最关心的正是代价落在谁身上。`who` 写「受益:…;受损:…」。
  - 当前出货主力标 `now`(徽标「当前主流」),未量产标 `future`(徽标「尚未量产」);`fork` 写 2–3 种下一阶段的可能路径,每个写 `if`(成立条件)和 `signal`(验证信号)。
  - 3–6 代为宜;代际划分按「解决的问题变了」,不按型号更新。
- **表格的维度用书面说法**(「芯片到光器件的走线」「故障处理」「主导方」),不用参数名(「pJ/bit」「插损」)。参数对标留在业务章 x.4。
- **x.6 对公司经营的影响**:产品形态与量价、份额与定价权、成本与毛利率,每处一两句,以「投资含义:」收尾。

## 5 怎么讲清「与竞品 / 替代方案的差异」

基金经理第二轮反馈的原话:「要说清楚这个技术和竞品的区别,比如 Palantir 的产品和普通的 SaaS 有什么区别,CPO 和可插拔、和 NPO 的区别。」v3.2 的竞争格局讲份额和排名,**没讲做法的差异**,读者看完仍不知道它和同类产品的区别在哪里。

**五步写法**(零章写精简版,技术章 x.3 写完整版):

1. **先选对比对象**:选读者已经熟悉的那一类,不选行业内部才懂的细分对手。Palantir 的对比对象是普通 SaaS(再加数据平台、咨询外包),不是 C3.ai;CPO 的对比对象是当前插在面板上的光模块和折中方案 NPO,不是某家光引擎厂。
2. **先分类,再比较**:用一两句把几种方案分成两三类,读者先有框架。例:「四种方案可分为两类:LPO 只改变模块内部;NPO 和 CPO 改变的是光器件的位置。」「普通 SaaS 覆盖一个部门的一类流程;Palantir 不针对固定流程,而是架在各系统之上。」
3. **画一张结构对比图**:把差异画成位置或层级的差别。光器件放在哪、信号走哪条路 → flow 块分泳道(每行一种方案);在客户 IT 中处在哪一层 → chain 块分层。图题直接写结论(「四种方案中光器件与交换芯片的距离」)。
4. **每对相邻方案一两句,段首加粗差异**:「**NPO 与可插拔:差异在光器件的位置。**」然后写这一差异带来的收益和代价,两者都要写;细节进表。
5. **逐项对比表 + 投资含义**:行是维度,列是各方案。常用维度:

| 维度 | 适用 | 例 |
|---|---|---|
| 定位 / 功能 | 所有 | 部门级标准软件 vs 跨系统的决策与执行层 |
| 位置 / 所处层级 | 硬件、软件架构 | 前面板插口 / 主板插座 / 同一封装;数据层 / 业务软件层 / 决策层 |
| 上线方式 / 故障处理 | 软件 / 硬件 | 开通账号数周 vs 建模数月;拔出更换 vs 开箱更换 vs 难以单独更换 |
| 收费方式 / 付费方 | 所有 | 按用户数 vs 按平台议价;按件 vs 按系统 |
| 主导方 / 价值归属 | 产业链 | 模块厂 vs 芯片厂与封装厂 |
| 代价或短板 | 所有 | 获客周期长、客户集中;维修难、供应商少 |
| 产业化阶段 | 新技术 | 大规模出货 / 小规模试用 / 样品 |

表后放一个以「投资含义:」开头的 `[!plain]` 块,一两句写差异对投资的影响:**跟踪指标不同**(普通 SaaS 看付费席位,Palantir 看单客户收入和扩容),或**价值归属不同**(从模块厂转向芯片厂和封装厂)。

**三条纪律**:只写差异不写优劣(优劣留给证据层和数据);每个优点写出对应的代价;单元格用短语,不用参数名。收费方式、产业化阶段这类说法写明出处或标「常见做法」。

## 6 买方用语

通俗讲清技术,不等于口语化。基金经理第三轮反馈指出零章「一些 AI 化的表述需要更加买方化」,具体点名把「钱往哪里流」「技术怎么一步步变过来」改成「价值流向」「技术演变」。语言规范的唯一出处是 buyside-voice 的 `references/voice-rules.md`(破折号 ≤8、判断性警句 ≤8 且只放结论位、禁词、FACT / 估算 / 判断三档语气、明示不确定、对手盘意识);本节只列本 skill 常见的替换。`--pm` 会报表中左列的说法。

| 口语化 / 问句式(不用) | 买方用语 |
|---|---|
| 一分钟看懂 XX | 业务速览:XX |
| 它像什么 | 工作原理(配产品图) |
| 一个真实的例子 | 典型案例 |
| 和 XX 有什么不同 / 到底差在哪 | 与 XX 的差异 |
| 钱怎么来 / 钱怎么流 / 钱往哪里流 / 钱会流向谁 | 价值流向 |
| 技术怎么一步步变过来 / 一代代怎么变 | 技术演变 |
| 最该盯的一件事 | 跟踪指标 |
| XX 是怎么回事、往哪走 | 技术与产品:原理、差异与演变 / 技术解析 |
| 今天在这 / 还没到 | 当前主流 / 尚未量产 |
| 赢的条件 / 看什么信号 | 成立条件 / 验证信号 |
| 放在投资上,这张表的意思是 | 投资含义: |
| 麻烦在于 | 瓶颈在于 / 难点在于 |
| 这件事要紧,是因为 | 删去,直接写结论与原因 |
| 有两面 | 分列收益与代价 |
| 说白了 / 相当于给……建一个 / 可以理解为 | 删去,直接陈述 |
| 不是 X,而是 Y(通篇反复) | 直接陈述 Y;确需对比时一处即可 |
| 卖法是「先小后大」 | 获客采用「先落地、再扩张」 |
| 成本的大头不是服务器,而是人 | 费用以人力为主 |

另外三条:**判断句只放在结论位**(lead、各节的「投资含义」、章末),证据句平叙;**披露数保留原精度并写期间**,估算数在正文加「约」并写口径(零章关键数据只放披露数或厂商口径数);**全卡至少一处明示不确定**(「这一点我们把握不高」)和一处反方观点(「市场的主要担心是……」)。

## 7 参照物库(优先用读者熟悉的商业或技术参照,不用生活化比喻)

第五轮反馈要求表述更严肃。「翻译」「充电宝」「按年交房租」这类生活化比喻读起来不专业,也容易失真。讲原理时优先找读者已经熟悉的商业模式或上一代技术作参照,并写明差异点。

| 领域 | 概念 | 参照物 | 差异点 |
|---|---|---|---|
| 半导体 | 晶圆代工 | 电子产品代工(按订单生产) | 建线投资大、制程代际决定定价权,客户切换周期以年计 |
| 半导体 | 制程(几纳米) | 产品代际名 | 数字已不对应真实线宽 |
| 半导体 | 先进封装 | 传统单芯片封装 | 多颗芯片高密度互连,良率相乘,测试难度上升 |
| 光通信 | 光模块 | 可插拔外设(网卡、硬盘) | 速率翻倍后功耗与散热成为瓶颈 |
| 光通信 | 交换芯片带宽 | 网络设备代际(51.2T → 102.4T) | 约两年翻倍,单通道速率随之翻倍 |
| 电力电子 | 逆变器 | 变频器等电能变换设备 | 要满足并网标准与电网安全要求 |
| 储能 | 储能系统 | 光伏电站的设备集成 | 价值在系统集成、安全与寿命管理,电芯多为外购 |
| 企业软件 | 平台订阅 | 按席位收费的 SaaS | 按平台议价、多年合同,单笔金额大 |
| 企业软件 | 本体 / 语义层 | 数据仓库与报表工具 | 定义可执行的动作,决策写回业务系统 |
| 企业软件 | 净收入留存率 | 零售的同店销售增长 | 统计对象是一年前已有的客户 |
| AI | 大模型 | 通用搜索引擎 | 生成内容可能出错,企业场景需权限控制与人工审核 |
| AI | 训练 vs 推理 | 一次性资本开支 vs 按量运营开支 | 推理随使用量持续增长 |
| AI | 智能体 | 流程自动化软件(RPA) | 可处理非结构化任务,授权范围决定风险 |
| 医药外包 | CRO / CDMO | 电子产品代工 | 受药监规范约束,换供应商需重新申报,周期长 |

## 8 改写前后对照

**① 公司一句话(平台软件)**

- 改前:Palantir 是一家以 Ontology 为核心,通过 Gotham、Foundry、Apollo、AIP 四大平台为政府与商业客户提供数据整合与 AI 决策能力的软件公司。
- 问题:一句话里 6 个读者不认识的词;「数据整合与 AI 决策能力」是抽象名词,读者看不见画面。
- 改后:Palantir 为政府和大型企业提供决策软件:整合客户分散在各系统的数据,在统一的业务模型上决策,再把指令写回原系统执行。(接「与普通 SaaS 的差异」表,再接工作原理与平台结构图。)

**② 技术定义(产业链)**

- 改前:CPO 将光引擎与交换 ASIC 共封装,缩短电互连距离,降低 SerDes 功耗,相比可插拔方案每比特能耗显著下降。
- 问题:用术语解释术语;「显著下降」没有画面。
- 改后:CPO 是把光电转换器件从交换机前面板移到交换芯片旁、与芯片封装在一起的技术。信号原来要在电路板上经过十几厘米铜线,现在只需几毫米,原本用于补偿信号衰减的 DSP 大多可以省去,功耗相应下降。

## 9 常见偏差

- **太啰嗦**:通俗不是多写,是换写法。零章超过 1,200 字或某节超过 160 字,通常是表后又用段落复述一遍,或把正文细节搬进来;能进表的进表,删复述。
- **数字模糊**:「约四分之三」「常年约八成」「前后」读起来像没核对过。关键数据写精确值与期间;年份拿不准就写阶段名(过渡方案、研发阶段)。
- **图不准确**:示意图里画虚构的界面、客户数据或按钮,读者会当真。没有官方原图时只画结构(部件、层级、走向),并标明示意。
- **通俗变夸张**:「彻底改变」「无人能敌」照旧不许写;通俗层的说法必须能在证据层找到对应的数。
- **标签外露**:第一稿样例用「白话」徽标和「打个比方:」「举个例子:」前缀标出每一块,基金经理嫌像模板。分块用小标题或块类型,页面上不写写作标签。
- **只说好处**:对比表里本公司那一列全是优点,读者不信。每个优点写出对应的代价(获客慢、维修难、供应商少)。
- **口语化与问句式小标题**:第二稿零章用「它像什么」「钱怎么来」「技术怎么一步步变过来」「最该盯的一件事」,基金经理认为 AI 化、不够买方。改用 §6 的买方用语;`--pm` 会报这些说法。
- **警句均匀**:每节都以一句格言收尾,读起来像模板。判断句只放在 lead、「投资含义」和章末,其余证据句平叙(voice-rules §2)。
- **类比过多或过于生活化**:零章至多一处;「翻译」「充电宝」「房租」这类比喻改用 §7 的商业或技术参照。正文证据层仍按 v3.2「少比喻」。
- **把读者当小学生**:基金经理懂财务、懂估值、懂行业比较;不解释毛利率、同比、市占率,只解释技术和行业黑话。
- **样例照抄**:`examples/pm/` 的句子是写法示范,新卡的类比和例子要从本卡材料里找。
