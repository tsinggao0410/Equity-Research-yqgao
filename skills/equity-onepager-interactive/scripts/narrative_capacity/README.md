# 概念/产业链 → 可交易容量

不需要 API key。走本机 Chrome 拦截网站自己的 XHR。

```bash
python radar.py 巨星科技 4         # 个股 → 它挂在哪些叙事和题材下
python radar.py 跨境电商           # 题材词 → 这个池子被拆成哪几条叙事
python chain_demo.py 巨星科技      # 只看叙事
python demo.py 兆易创新 4          # 只看题材
```

入口自动识别：参数在 A 股名册里就走个股模式，否则按题材词处理。
题材词模式下如果问财有同名概念，会和韭研的叙事并排出，并算**成分重合度**——
这是两套口径之间唯一的硬桥。跨境电商的例子：

```
── 叙事 ──
Shopify概念(260805)      8只     703亿   MIX 6.01%  86分位偏高
AI电商/跨境电商(240527)   17只   2,961亿  MIX 4.99%  86分位偏高
跨境电商/东南亚(251224)   17只   1,849亿  MIX 3.57%  70分位
中美降税(260416)         23只   8,351亿  MIX 2.88%  35分位
── 题材 ──
跨境电商                339只  36,591亿  MIX 3.33%  61分位

跨境电商/东南亚 ∩ 跨境电商  16/17（94%）  ← 几乎完全被题材包住
中美降税       ∩ 跨境电商  10/23（43%）  ← 另一条故事，只是蹭到了这个池子
```

一个 339 只、3.6 万亿的题材，拆开是六条 8~23 只的叙事，冷热差到 86 分位 vs 35 分位。
重合度高（94%/88%）说明这条叙事就是题材的核心；重合度低（43%）说明它讲的是别的事。

## 第一性原理：股价 = 资金 ÷ 筹码

**叙事决定钱往哪去，容量决定钱摊多薄，我的份额决定我分到多少。**
所以单看容量没有决策含义——8,347 亿这个数不配上「钱有多少」和「我占多少」，推不出任何东西。
三个量必须凑齐：

| 量 | 指标 | 回答什么 |
|---|---|---|
| **分子** 叙事势能 | 换手强度 = Σ成交额÷Σ自由流通市值，及其三年分位；催化时间轴 | 钱来了没有？上一次为什么来？ |
| **分母** 容量 | 自由流通市值加总 | 钱要摊在多大盘子上？我的仓位放不放得进去？ |
| **份额** 我的位次 | 篮子内自由流通排名 + 占比；各阶段相对篮子的强弱 | 钱来了会不会买到我？我是龙头还是跟风？ |

**容量大 ≠ 需求大**，正好相反：容量大＝吸收力强、单位资金推力小。储能篮子 105,957 亿自由流通，
3,412 亿成交额也就换手 3%，推不动；外贸出口篮子 880 亿，来 50 亿就是暴力行情。
真正有赔率的形态是**失配**——叙事级别高但篮子小。

**为什么不用日振幅分位**（v3 用过，已废弃）：波动低有两种相反解释——没人玩（冷）、
或筹码锁死蓄势（要爆），方向不单调，做不了决策输入。换手强度是单调的：钱进来就抬、没来就低。

实测巨星科技最锋利的一行：**储能换手强度第 76 分位（钱确实来了），但巨星排第 98/895、
只占 0.2%——钱来了也买不到我**。这直接解释了阶段⑤储能篮子 +8.4% 而个股 −23.1%。

## 叙事 ≠ 题材

**叙事**（韭研公社产业链）：人工梳理、事件驱动、带建链日期和逻辑要点，
成分点名给出（20~30 只）。回答**"市场在讲什么故事"**。

**题材**（问财所属概念）：机器打标、覆盖全 A 股，成分是筛出来的（几十到上千只）。
回答**"资金会往哪个池子里找票"**。

两者口径一致（容量三口径 + MIX 日内波动 + 三年分位），可以直接横比。
一只票的叙事篮子通常只有两三千亿、几十亿成交额，题材篮子动辄十万亿、上千亿成交额——
差的那一个量级就是"故事讲给谁听"和"钱实际能进多少"的区别。

## 题材的关联度怎么排

问财自带 `诊股概念分类贴合度`，但只吐贴合度最高的一条，拿不到完整排名
（试过"贴合度排名小于20""按贴合度排名排序"都不给）。所以 `relevance.py` 自己算，
三个信号全部免费——公司画像那一次调用里已经带回主营产品和两套行业分类：

| 信号 | 权重 | 含义 |
|---|---|---|
| `biz` 主营匹配 | 0.55 | 概念名在主营产品/行业文本里能命中的最长片段占比 |
| `narrow` 窄度 | 0.30 | 成分股数取对数，越窄越具体 |
| `order` 原序 | 0.15 | 问财自己的排序，经验上靠前的更贴身 |

**命中片段会一起打印**，谁高谁低看得见，不做黑箱。两个坑：

- **通用片段要停用**。"智能物流""智能家居"只因为主营里有"智能工具"就拿 0.5 分，
  是纯噪音。`STOP_FRAGMENTS` 把智能/概念/经济/产业/通用这类挡掉。
- **伞形一刀切会误伤**。巨星科技的"储能"有 895 只成分，按宽度该滤掉——
  但它主营产品里明写着 `powerstations`（便携储能电源），是实打实的主业。
  `BIZ_OVERRIDE=0.8`：主营匹配够强就放行，只把宽度标出来让人自己判断容量可读性。

## 两条概念来源，先选对来源再谈容量

| | 问财「所属概念」 | 韭研公社「产业链」 |
|---|---|---|
| 来源 | 机器打标，沾边就挂 | 人工梳理，点名给成分 |
| 巨星科技（手工具出口商）出来的是 | 芯片概念、军工、储能、机器人概念 | **中美降税、越南工厂、外贸出口** |
| 成分规模 | 单概念 55~1215 只 | 单链 20~30 只 |
| 附带信息 | 无 | 建链日期、逻辑要点、更新时间 |
| 覆盖 | 全 A 股都有标签 | 只有被研究过的题材 |
| 一次运行 | 28.9s / 18 POST | **14.2s / 4 POST** |

问财那条路胜在覆盖全、无死角；韭研那条路胜在准。**先看韭研，没有再退回问财。**

韭研的搜索接口不用登录（详情页要登录，但成分股已经在列表响应的 `keyword` 字段里）。
`token` 按 timestamp 派生，脱离浏览器直调会被拒（errCode 110），所以走 Playwright
让页面自己带签名——和问财那条腿同样的思路。

## 调用量

| | 优化前 | 优化后（冷缓存） | 优化后（热缓存） |
|---|---|---|---|
| 问财 | 13 次页面导航 ≈ 130s | 3 导航 + 31 POST | **2 导航 + 18 POST ≈ 28s** |
| 日 K | 439 次请求，被 WAF 拦 | ~240 只，一只一次 | **0 次**，全缓存命中 |
| 总耗时 | 跑不完 | ~43s | **29s** |

三层缓存，全部落盘、跨公司共享：`.klinecache/`（日 K，10 天）、
`.concept_sizes.json`（概念成分数，7 天）、浏览器 profile（cookie / hexin-v）。

五条优化：

**1. 免导航直发。** 页面导航要 ~10s（加载 + 等 JS 渲染），而 `get-robot-data`
就是个普通 form POST。首次导航拿到 cookie + `hexin-v` 后，把请求当模板改 `question`
直接重发，单次 0.8s。**12 倍**，而且不多占问财一分钟资源。

**2. 历史 K 线永久缓存。** 历史 bar 不会变，抓过就不再抓（超过 `STALE_DAYS=10` 天才重拉）。
**今天的振幅不从 K 线源取——问财截面里已经有了**，零额外请求。所以日 K 是一次性成本。

**3. KlineStore 跨概念共享。** 几个概念成分重叠极多，union 去重后只抓一次。

**4. 只拉用得上的字段。** 换手率被成交额覆盖、概念解析问财在成分股查询里从不返回，
都从问句里删掉——多写一个指标问财就多算一列。

**5. 先探大小再决定拉不拉。** `perpage=1` 探成分数只要 0.35s，一次探测就能省掉
一个伞形概念十几轮翻页。成分数再落盘缓存（7 天），重复运行和跨公司都不再探。
概念在不同公司之间大量重复，这个缓存越用越省。

## 概念选取：剔机制 → 剔伞形 → 跨面各取一个

`select_concepts()` 三道闸，缺一个都会选出没法用的概念。

**闸一：机制标签。** 融资融券、沪深股通、中报预增、**参股银行**——不描述主业。
"融资融券"覆盖两千多只，"参股银行"说的是资产负债表上的股权而不是经营。

**闸二：伞形标签（`UMBRELLA_MIN=500`）。** 成分股过多的标签对单个公司没有定位信息：
巨星科技挂着"芯片概念"（915 只）和"机器人概念"（1215 只），你不会因为芯片概念有
34.5 万亿市值就说巨星科技的赛道有这么大。它们还是调用量大头——1215 只要翻 13 轮。
`probe_sizes()` 用 `perpage=1` 先花 0.35s 探出成分数，再决定要不要花大代价拉。
跳过的会列出来，不是静默丢掉；窄概念凑不满时才回补，并标明「伞形回补」。

**闸三：跨面各取一个。** 按问财原序取前三，兆易创新会得到存储芯片/汽车芯片/MCU芯片，
**三个都是产品面**。改成每个面先各取一个，再回头补第二个。

八个面：客户生态 / 产品技术 / **渠道模式** / **消费场景** / 下游应用 / 主题叙事 / 区域属性 / 未分类。
渠道和消费场景是后加的——原来只按半导体产业链写词表，巨星科技的
**跨境电商**（出口渠道）和**露营经济**（户外场景）全掉进了未分类，
而这两个恰恰是它的本体。规则在 `FACETS`，纯正则，觉得哪个概念归错面直接改。

```
巨星科技  伞形跳过: 机器人概念1215 / 储能895 / 芯片概念915 / 军工606
         → 跨境电商[渠道模式·339]、露营经济[消费场景·55]
           智能物流[下游应用·250]、智能家居[消费场景·290]
```

公司画像一次调用还带回**申万行业**（另一套分类）、**主营产品名称**、**注册地** ——
免费搭车的面，不额外花调用。

## 口径

容量三个，从松到紧：`total_mktcap` 名义盘子 / `float_mktcap` 真正能换手的（**「可交易容量」看这个**）/ `amount` 今天实际吃得下多少钱。

MIX 日内波动率 = 日振幅 `(最高−最低)/前收`，与问财「振幅」字段同定义。
横截面聚合给四个口径：等权中位数、自由流通市值加权、成交额加权、等权均值。

**两个篮子别混**：容量用全部成分股；分位用自由流通前 60 只，因为历史序列只对这 60 只建。
输出里分开标了，分位那行永远和历史同篮子。加权序列用**当前**自由流通市值回溯套用，
成分和权重都会漂，是近似；中位数序列没这个假设，分位以它为准更稳。

## 四个坑（都已处理，改代码时别踩回去）

**1. 科学计数法。** 问财把成交额返回成字符串 `"3.1685751922E8"`，正则漏掉指数部分就差
1 亿倍，而且静默——加总看着像 0。

**2. `page` 参数是假的。** `meta.page` 恒为 1，改 page 每次返回同一批，`perpage` 硬顶 100。
靠总市值游标翻页绕开。**排序必须放进第一条查询**——游标是"已取到的最小市值"，
首批若是无序样本，最小值会落得很低，后面 `小于该值` 几乎捞不到新名字
（实测漏成 101/200、104/375）。永远拿 `meta.extra.code_count` 校验行数。

**3. 单一 K 线源会被拦。** 腾讯 gtimg 会返回 `waf.tencent.com/501page.html` 而不是 JSON。
`SOURCES` 是新浪 → gtimg 的失败转移，任一拿到就落盘。加了熔断：连续 12 次失败判定上游
不可用、整批放弃——不熔断的话 200 个失败 × 4 轮退避 = 白烧 400 秒。

**4. 覆盖不足别硬算。** `basket_history()` 返回 `coverage` 和 `reliable`，
低于 60% 时输出"数据不可得"。7 只股票算出来的分位是废数。

**5. 问句有 ~200 字符硬上限。** 超了返回 `status_code=-9138「免费版question字段长度过长」`。
25 个 6 位代码 + 指标尾巴就会超（实测 203 被拒）。`chunk_codes()` 按**长度**切块，
不是按个数——按个数切会时灵时不灵。服务端错误码一律进 `notes`，
绝不能当成"空结果"：那样调用方会以为这批标的真的不存在，
而实际发生的是 25 只全被吞掉、加总印出个 49 亿。

**6. 韭研的成分股要精确过滤。** `keyword` 字段把成分股和题材词混在一起
（"工具五金 工程机械 宠物 跨境电商 巨星科技 欧圣电气 …"），
而问财的多标的查询里只要掺进一个题材词，整条查询就返回 0 条。
`roster.py` 拉一份全 A 股名册（5239 只，一次性 115s，缓存 30 天）做精确匹配，
模糊规则不行。港股成分（泉峰控股、创科实业）会被同时排除并单独列出——
币种不同，混进人民币加总就是错的。

**7. 按代码查，不按名字。** "龙头股份""大叶股份"这类含修饰词的名字有被问财
当成筛选条件的风险；代码没有歧义。名册里本来就有代码，不额外花调用。
