## 0 · 定位与形态

**它要解决什么**：前四章解决「是什么 / 值多少 / 盯什么」，但读者合上报告能复述的只有一段话。这一章就是那段话，两个硬要求：①**能直接讲出去**——不看图不看表，念出来别人就听懂赌的是什么、算的是多少；②**把算账倒过来解一次**——正着算是「假设→利润→市值」，倒过来问三个买方真正关心的问题（第四点三块）：市场已经认下多少利润、落在哪一年（利润兑现期限）→ 之后还想要弹性只能换什么范式（估值范式上界）→ 靠什么事把前提证实（潜在催化）。

**位置**＝正文最前（概览之后、「一、基本面图谱」之前），与「概览 / 参考文献」同为不编号章。**写作顺序与阅读顺序相反——四章都定稿了才写得出它**（Phase 6.5）。PM 打开报告先读它，后四章是支撑材料。

**小节固定**：第一点 公司类型 · 第二点 核心投资逻辑 · 第三点 算账 · 第四点 利润兑现期限 · 估值范式上界 · 潜在催化（一个 h2、三个 h3，每块下从 `1.` 起编号）。章内编号三级 `1.` → `(1)` → `①`，悬挂缩进；页面与「⧉ 复制为文本版」用同一套编号，改一处同步另一处。

**形态硬约束**：只用文字 + 编号，不用卡片、色块、刻度尺、进度条——这一章是要直接讲出去/粘进备忘录的，越素越严肃越普适。唯一例外是「利润兑现期限」下的逐年表（数字矩阵用文字叙述不可读），且必须是无底色细线表。别再往这一章加视觉件（历史上做过卡片阵+刻度尺+圆圈序号阶梯，被明确否掉）。

**数据键**：`page_model.summary`（不是 `part5`）。渲染入口 `renderSummary(pl)` 挂在 `recompute()` 里，所以第四点「利润兑现期限」随第三章假设滑块实时联动。缺 `summary` 键整章自动隐藏。

**形态锚**：用户给的 `总结1-jahb.txt`（嘉澳环保 SAF）：`公司类型 → 一句话逻辑 → 需求/供给/公司三层 → 分档算账 → 市值空间`，末尾加第四点三块。**内容锚**：8/8 北方华创 002371（`research-materials/北方华创-002371/onepager/page_model.json`）——钩子体系的第一个完整实例。

## 2 · 第一点 公司类型 ＝ 钩子体系（★本章核心）

### 2.1 三块各答什么、title 是结论句

| 块 | 回答的问题 | title 例（结论句） |
|---|---|---|
| ① 生意本身 | 这门生意到底卡在哪 | 「半导体设备平台商，周期成长股（不是纯成长也不是纯周期）」/「把华为的产品定义权租下来，自己出产能和资产负债表」 |
| ② 盘子 | 多大、什么位置、筹码怎么锁、钱进得来吗 | 「沪深300 大盘股，但国资锁仓一半，真实可流通盘只有账面的一半」 |
| ③ 股性 | 这票怎么交易、谁在定价、跟哪条线 | 「曾经的游资票，现在是没人玩的机构票」 |

三块顺序固定，每块 ≥3 个 (k,v) 子项。**title 必须是判定，不是块名**——读者只读三个 title 也要能拿走结论。

### 2.2 钩子是什么、怎么用

`k` 那一列不是排版，是**提问框架**。每个钩子四件套：**该问的**（问题本体）· **去哪挖**（前四章哪个字段 / RAG 检索词 / AlphaPai 探针）· **合格答案的形状**（一个句式，逼出「所以你会怎么看错」那一步）· **不合格样例**（同行业照抄也成立的那种）。

- **必答**：每块固定几条，闸门逐条查覆盖（`hook` id 优先，缺则按 k 关键词回退）；**条件必答**：A股默认写、有 1.7 数据时写、2.2 里 ≥2/3 段主因子同一时写。**选答**：按标的挑，不适用就不写，**不许硬凑**——空钩子比错钩子好，但必答钩子答不上来不是「不适用」，是没挖到（见 §2.6）。
- `points[].hook` 填登记表 id（机器版在 `scripts/summary_hooks.json`，`node scripts/check_summary.js --hooks` 可打印）；`k` 是给读者看的短问句，措辞随意（8/8 写「收入怎么来」、8/16 写「收入在哪一刻确认、被谁挟持」，都对）。
- 每条 `v` ≥15 字、带数字、`tag∈FACT/EST/DNA`；**全章 ≥2 个 DNA**（纯 FACT 堆砌＝只搬了数字没写 knowhow）；≥1 处挂 `ev`（逐字原句 id，来自 part3 `evidence[]`）。
- **密度纪律：少而狠。** 每条 `v` 只说一件事：**FACT ≤100 字、EST/DNA ≤150 字**（闸门按 +10% 容差拦：110/165）；**选答每块 ≤2 条**；公司类型三块 `v` 合计**目标 ≤3,000 字、硬上限 4,000 字**（闸门 b9 拦）。这一章是要念出来的——8/8 华创 14 条约 2,300 字、用户原稿 12–15 条约 1,600 字，都能讲清；24 条 4,400 字就不是「一段话」了。多出来的深度不是删掉，是**下沉**：细节留在第三章 driver_chain/calibers，开篇只留「结论 + 关键数字 + 所以你会怎么看错」那一句。
- 开篇是**收口**：钩子答案九成在 page_model 里，**不为钩子重跑数据管线**；只有标 🔎 的钩子允许补一次外部检索。

### 2.3 块① 生意本身 —— 这门生意到底卡在哪

| id | 该问的 | 层 | 去哪挖 | 合格答案的形状 | 不合格样例 |
|---|---|---|---|---|---|
| `industry` | 行业与位置：上游是谁的 capex、下游景气由什么决定 | 必答·FACT | `part1.revenue.caliber/segments`；02 分部；RAG「上下游 景气」 | 「半导体设备；上游是晶圆厂 capex，下游景气由存储/逻辑扩产节奏决定」 | 只写行业名 |
| `products` | 主要产品与收入结构：分部金额、排位变化 | 必答·FACT | `part1.revenue.segments` 最新年、`part3.segments[].hist.rev` | 「储能 372.9 亿(+53%) 已反超逆变器成第一大分部」 | 罗列产品名不带数 |
| `rev_recognition` | **收入在哪一刻确认、节奏被谁挟持**（客户验收 / 自己的交付排期 / 渠道批发 / 项目融资批复） | 必答·DNA | `part3.segments[core].model.driver_chain` 末步、`logic`、`evidence[]` 里「验收/确认/交付」原句；RAG「确认收入 验收 交付节奏」 | 「X 才确认 → 节奏在 Y 手里 → 所以 Z 领先/滞后 N 季；这个位置上需求再上修也变不成收入」 | 「项目制卖设备：招标→交付→验收确认收入」 |
| `moat_where` | **壁垒在链条的哪一步**（不在造得出，在…） | 必答·DNA | `calibers`（口径差本身常就是壁垒所在：存量 10% vs 新建 65%）、`evidence`、`part4.items` 主动矛盾；RAG「份额 认证 导入 切换成本 替代」 | 「不在 A，在 B；证据是两个数字的差：…」 | 「技术领先、客户粘性强、护城河深」 |
| `price_or_mix` | **单价涨的是价还是结构**（提价 / 机型·产品占比 / 复合口径） | 必答·EST | `part3.segments[].hist.p`、`assume.p_growth`、`p_anchors`、ASP 的 `calibers` | 「ASP a→b(+x%) 但年提价只 y% ⇒ 结构变量不是价格变量；把它当涨价看会把弹性来源找错」 | 「产品结构升级带动 ASP 提升」 |
| `good_biz_bad_pnl` | **什么情况下生意好但报表不好**（产能顶死 / 研发前置 / 原料涨价存量锁价 / 少数股东 / 汇率）；也问反面：报表好但生意不好？ | 必答·DNA | `driver_focus.verify`、`fragile`、`opex` 假设、`part4` 从动矛盾（物理/要素型）、`cost_structure`；RAG「成本 传导 库存 锁价」 | 「当 X 发生时量/订单在涨但报表 Y；已在发生的迹象是 Z」 | 不写；或「存在成本上涨风险」 |
| `cycle_or_growth` | **周期还是成长——收入曲线与利润曲线分开说，决定用哪把尺子** | 必答·DNA | `part1.dupont/cost_structure` 年序列、`part3.hist_actual`、`part2.phases[].factor_quant`、`fwd_pe.loss_metric`（负利润周切 PS 本身就是周期证据） | 「收入口径是 A、利润口径是 B ⇒ 判定＝…；量的部分用 X 范式、利润部分按峰值-谷底看」（赛力斯：成长股的收入曲线 + 周期股的利润曲线，所以不能用 PEG 一把尺子量到底） | 「周期成长股」四个字 |
| `cost_pass_through` 🔎 | 成本端谁说了算、涨价能不能传导（最大成本项占比、库存月数、合同锁价、传导时滞） | 选答 | `cost_structure`、`calibers`、`evidence`；RAG「原材料 占比 调价 传导」 | 「最大成本项 X 占 y%；库存 n 月；存量单锁价/新单可传导 ⇒ 成本每涨 1 单位 → 毛利率 −z pp」 | 「原材料价格波动影响毛利率」 |
| `cash_vs_profit` 🔎 | 利润是不是现金（应收/合同负债/存货/资本开支吞不吞利润） | 选答 | iFind `fin` 现金流；`part1.snapshot`；RAG「经营现金流 合同负债 应收」 | 「经营现金流/归母＝x；合同负债 y 亿领先 z 季；capex w 亿/年吞掉 v% 利润」 | 「现金流健康」 |
| `capacity_headroom` | 供给弹性：产能离天花板多远、扩一次要多久多少钱（当供给是**当前绑定约束**时另立；否则并进 `rev_recognition`） | 选答 | `driver_chain` 的 min(需求,产能) 钳制、`assets_note`、`anchor_check`；RAG「产能 扩产 投产 爬坡」 | 「利用率 x%；扩 y 单位需 z 个月 ⇒ 20xx 前需求上修变不成收入」 | 「产能充足」 |
| `growth_decomp` | 增长来源分解：量/价/份额/并表/新品类各贡献多少，相乘还是相加 | 选答 | `part3.segments[].hist` q/p YoY、`revenue.milestones`、`narrative_map` | 「+31% ＝ 量 +x% × 价 +y%…；两项相乘 ⇒ 上行双击 / 相加 ⇒ 不双击」 | 「多点开花」 |
| `customer_power` 🔎 | 客户集中与议价：前五大占比、账期、谁能换掉谁、被绑定方的诉求 | 选答 | `revenue.customers/milestones.cust`；RAG「前五大客户 占比 账期」；AlphaPai | 「前五大 x%；账期 n 天由客户定；能换掉我们的是…／我们离不开的是…」 | 「客户资源优质」 |
| `reporting_trap` | 报表最容易被读错的一处（复合口径 / 并表少数股东 / A-H 股本 / 会计政策） | 选答 | `calibers` 决策卡（chosen vs rejected）、`meta.currency`、CK-8 双口径 | 「X 是复合口径（分子含…分母只有…）；按它算会高估 y 倍」 | 不写 |

### 2.4 块② 盘子 —— 多大、什么位置、筹码怎么锁、钱进得来吗

### 2.7 knowhow 判据与分层

**一句话判据：这句话同行业任何一家公司照抄都成立 → 不合格，删了重写。**
❌ 「项目制卖设备：晶圆厂招标 → 交付进厂 → 客户验收后确认收入；后续有备件与服务」——任何设备公司都能这么写。
✅ 同一条改写：「设备进厂不算收入，过客户工艺与良率验收才确认——**收入节奏握在客户爬坡进度手里，公司自己控不了**；2026 更反直觉的是产能已顶死（隐含 3,048 台 vs 产能 3,100 台，利用率 98%），**这个位置上需求再上修也变不成收入**」。
差别不在信息量，在**有没有「所以你会怎么看错」那一步**——k 列的钩子逼出来的正是这一步；散文可以绕过任何一条，而且绕过了看不出来。

- **每条要有估值/交易含义**：「小市值」→ 弹性大/流动性折价；「平台型」→ 估值锚是平台不是单机。纯形容词（优质、稀缺、龙头、护城河深）一律不进。
- **FACT / EST / DNA 分层**：财报与公告数＝FACT；卖方/自算/AlphaPai＝EST；我的判断（「所以你会怎么看错」）＝DNA。三块合计 ≥2 个 DNA。
- **数字必须回得到前四章**：口径不一致以第三章为准并回头改这里，不是反过来。

## 5 · 第四点 利润兑现期限 · 估值范式上界 · 潜在催化

### 5.1 利润兑现期限（`backsolve()`，活的）

```
implied  = 现市值 ÷ anchor_pe                       ← 市场已经认下的利润体量
兑现年份  = implied 在（历史上行尾巴 + 预测）归母序列上的线性插值落点   ← 小数年，如 2027.4
逐年表：  现价隐含PE = 现市值 ÷ 该年归母
         该年目标市值 = 该年归母 × anchor_pe
         折现回今日   = 目标市值 ÷ (1+r)^(该年 − base_year)
         赔率        = 折现回今日 ÷ 现市值 − 1
```

利润序列优先取第三章模型（`recomputePL().byYear[].netProfit`），所以拖任一假设滑块，兑现年份与整张表即时刷新——**这是本章唯一活的部分，别写死**；没有第三章模型才回落到 `backsolve.profits` 手填。`anchor_pe` 与 `anchor_pe_basis`（≥20 字为什么用这档）必填；`r` 缺省 0.09、硬边界 0.08–0.10。

四种落点，各说各的话（页面自己会说，正文别靠 `anchor_pe_basis` 手写找补）：

| 分支 | 含义 | 该说的话 |
|---|---|---|
| `inHist` + `belowHist` | 现价连历史已实现利润都没认全 | 深度错杀或市场认为盈利不可持续，回第四章找是哪条从动矛盾 |
| `inHist` | 未来那一段一分钱没付（落点回溯历史的**单调上行尾巴**插值；周期股旧峰值不参与） | 上行靠的是「兑现」不是「超预期」，赔率来源最干净 |
| 落在预测段中部 | 市场付到第 N 年 | 买入靠的是那一年之后的部分 |
| `beyond` | 全部预测利润都不够解释现价 | 缺口只能靠换范式或上修假设填——往往是全篇最重要的一句 |

读法（页面已印在表下，正文别重复）：现价隐含 PE 越靠后越低＝越需要等；赔率转正那一年之前，买入靠的是估值扩张不是业绩。

### 5.2 估值范式上界（`ladder`）

- **每档两个数字**：`(2) 现参数下`＝该范式当前参数读数（能挂第三章 `key` 的取实时值）；`mcap_if_yi`＝**前提成立后**能给到多少。必须分开填：前提未成立的档（终局份额、对标大哥）用当前参数算会**系统性低估其空间**（002371 终局档：现参数 4,182 亿 −24%，份额与净利率取上沿后 9,400 亿 +71%）；只写现参数会得出「换范式也没用」的错误结论，而这恰恰是本节存在的意义。
- **排序＝五档估值等级**（05 §0.5，`tier:1-5`，页面渲「第N档」chip）：第一档 PB/重置 → 第二档 静态/Forward PE·EV/EBITDA → 第三档 PEG/N+1 → 第四档 PS·单位利润/N+2·SOTP → 第五档 终局/五年规划/对标大哥。越往下档位越高、升档赔率越大（二 20–50% / 三 30–50% / 四 50–100% / 五 100–300%），前提越强、证伪回撤越快。`status` 成立/待验/不成立，`current` 标当前档。
- **只列上界**：一档若「现参数下」与「前提成立后」**都够不到现价，整条不渲**（托不住现价的范式说的是下行，归 5.3 的 `kill`）；页面末尾只补「另有 N 档已隐去」不列档名。数据层仍写全所有档（供文本版与复核），**别在 page_model 里删负档**。若所有档都够不到现价，页面渲一句「当前参数下没有任何估值范式能给出高于现价的市值」——那是结论本身，不是没算出来。

### 5.3 潜在催化（`switches`）

每条是一次**范式跃迁**，不是普通催化（普通催化归第二章 2.3）。判据：这件事发生后，市场给这家公司**估值的方法**会变，而不只是把同一方法的参数调高。四格必填：`catalyst`（什么事）·`watch`（盯哪个可观测指标）·`when`（时间窗）·`elasticity`（切过去市值弹性，用升档赔率区间标定）；`kill` 强烈建议——**反向跃迁同样存在且更快**（增速掉档 → PEG 失效 → 切回低档 PE），**至少留一条向下**。
`prob` **必填、(0,1] 的数**，不许 `'—'` 占位——赔率没有概率就不是赔率。**升档 switch 与第四章上行 Case 讲的是同一件事**（「第二档 Forward PE → 第四档 SOTP」的催化＝「年报分部表新增 AIDC/SST 行」＝ `ai_paradigm` 那条 Case），所以升档 prob 合计 ≈ 第四章上行 Case prob 合计（±10pp），两处不许各说各的。

## 6 · 写作纪律

1. **只做收口，不新增分析**：每个数字都能在前四章找到出处；口径不一致以第三章为准并回改这里。
2. **每条 point 带数字 + FACT/EST/DNA**；没有数字的 claim 是口号，删掉或降进 `note`。
3. **knowhow 判据**（§2.7）：同行业照抄成立就重写；每条至少一处别人不会说的判断。
4. **`thesis` 含机制**；**黑话不进正文**（archetype / STP / R-M-V / Forward 翻成买方白话）。
5. **脚手架语句一律不进正文**——判据：它讲的是「结论是什么」还是「我怎么做的」，后者删。五类高发：

   | 类型 | 反面例子（都真出现过） | 怎么改 |
   |---|---|---|
   | 分类体系注解 | 半导体设备**（申万：电子—半导体—半导体设备）** | 直接写「半导体设备」 |
   | 方法论/口径解释 | 沪深300 成分股 → 大盘股**（A股通行分层：沪深300＝大盘…）** | 只留结论 |
   | 样本量/窗口 | 近 3 年**（725 个交易日）**涨停 6 次 | 删括号 |
   | 内部章节交叉引用 | 电子工艺装备**（按第三章 SOTP）** / **证据在本页 1.7 与 2.2** | 删；读者会自己往下读 |
   | UI 操作与自指 | **拖动任一假设滑块本表即时刷新** / **本模型**的终局假设 / **本案** | 删操作说明；自指改直陈 |

   不算脚手架、必须留：`FACT/EST/DNA` 标记、`[En]` 原句角标、`[n]` 参考文献、信源、**跨章节的结论性互证**（「与隐含 Forward 读数互为印证，同样指向 price-in ~2028」是发现不是脚手架）。
6. **「反算」等内部叫法不出现在任何用户可见标题/正文**。
7. **文本版是一等公民**：「⧉ 复制为文本版」的 `summaryText()` 与页面同一套编号，改契约时同步改它。
8. **写任何用户可见正文前读 `buyside-voice/references/voice-rules.md`**（SKILL.md 加载顺序 11），逐字引用（`ev[].quote`）豁免。

## 8 · 已知坑

- **引擎字段名**：`byYear` 里是 `netProfit`（不是 `np`），`year` 是带 E 的字符串——取数用 `parseInt`；写错表渲成空。
- **阶梯活值 ≠ 上限**：`mcap_if_yi` 与现参数读数差 <2% 时页面自动不渲那一行（两个一样的数并排＝噪音），填了没显示通常不是 bug。
- **正文不渲三处元叙述**：`meta.note`、`part1.snapshot.note`、`summary.note` 都不进页面；有结论性内容的必须挪进开篇章，否则等于丢了。
- **缺 `summary` 键整章隐藏**（`display:none`）不报错——「页面上没看到这一章」通常是没填 `summary`。
- **`inHist` 时页面自己会把话说出来**（「落点在历史段：市场认下的利润还停在 2025 年已经赚到的那个水平，一分钱未来都没付」）；若你觉得还要在 `anchor_pe_basis` 里手写解释，说明引擎没算对，不是文字没写够。
- **`esc()` 字段里不许有 HTML**：`v`/`claim`/`conclusion` 写 `<b>` 会原样印出尖括号，加粗用 `**`。
