## 1. 为什么放最后

前三章的产物是**认知**，第四章是**行动**。分界线：
- 第三章的结论是「按我的假设，隐含市值 X 亿」——那是一个点估计
- 第四章的结论是「这个点估计里，**哪几格还没定、定下来值多少钱、什么时候能定**」

所以第四章不是新增分析，是**把前三章已有的东西重新按「未定」排一次序**：
`q/p/gm_anchors` 的离散度 → 分歧；滑块弹性 + 取期敞口 → 赔率；`driver_focus.verify` + 催化 → 可证伪性。
**原料前三章全有，第四章只做判定。**

## 2. 三个坐标（本 session 实证定稿）

| 坐标 | 定义 | 数据来源 | 是否可自动 |
|---|---|---|---|
| **赔率 F** | 该矛盾从最悲观到最乐观解决，隐含市值区间宽度 ÷ 现市值 | `scripts/tornado.js`（参数弹性）＋取期敞口 | ✅ 全自动 |
| **分歧度 D** | **市场上各家口径的方差**——几家给了数、极差多少、单峰还是双峰 | **research-rag 逐条取证**（见 §4） | 半自动 |
| **可证伪性 V** | 12 个月内有无明确公开事件能判定它，且落在你有信息优势的节奏上 | 催化日历 + `verify` + 财报节奏 | 人工打分 |

### 2a. 三个坐标是三道闸，不是三个可相乘的分数
**乘积形式会误导**（暗示高赔率可以补偿零分歧）。正确用法：**每闸设硬下限，过闸后才排序**。
- 赔率不过闸 → 无关（研究对了也不值钱）
- 分歧不过闸 → 已定价（研究对了也赚不到）
- 可证伪不过闸 → 等不到（在持仓周期里等于没发生）

### 2b. 可证伪性是**非单调**的
- 太低（范式切换没有公告、事后才认得出）→ 等不到，只能定价不能跟踪
- **太高**（日度现货价、板块强弱）→ 公开即定价，你没有时间优势，那是交易 alpha 不是研究 alpha
- **最优是季度级**——你能算出来，市场要等财报确认。这解释了为什么「量价拆解＋季度跟踪」是买方主流赚钱方式

### 2c. 分歧度的三种形态（含义完全不同，必须在 `dispersion_basis` 里写清）
| 形态 | 判据 | 动作 |
|---|---|---|
| **双峰/极化** | 几家聚在 A、几家聚在 B，中间空 | **最好的猎场**——必有一派会错 |
| **单峰宽** | 各家散开但无聚集，或都说「不确定」 | 信息不存在 → 要折价，别做功课 |
| **零覆盖** | **没人发表 → 方差≈0** | 读财报即可，最便宜的 alpha；页面用**虚线圈**标出 |
| 单峰窄 | 各家收敛、极差<20% | 已定价，**不是矛盾**，不进图 |

> ⚠️ **零覆盖会落在图的下半区（低分歧），这是对的**——没人发表就没有方差。
> 但它不等于没价值，虚线圈就是在说「便宜」。下半区因此分两种：**虚线＝没人看，实心＝真已定价**。

## 3. 五层归类（`layer`，决定颜色）

**叙事 / 估值 / 收入 / 利润率 / 费用率** —— 后三者合称 P&L 层。

- **叙事**：技术路线、终端需求故事、主线归属。改的是「市场愿不愿意给这套现金流估值」
- **估值**：取期、范式、可比集合、定价权/筹码。改的是「同样的盈利值多少钱」
- **收入 / 利润率 / 费用率**：直接挂在 `part3` 的 `q_growth / gm / opex.*_rate` 上

**归类纪律**：能挂到 `part3` 某个可调参数上的，一律归 P&L 三层之一，并在 `hooked` 字段写明挂哪个参数——
**挂不上参数的必须归叙事或估值**，不许含糊。「主要矛盾是国产替代」这类挂不上数的，不是矛盾，不进图。

### 3b. `layer` 之外还要定 `role` / `subtype` / `clock`（见 13）

`layer` 管颜色（打在 P&L 哪一层），**`role` 管因果方向**（主动＝生成上行 / 从动＝限制上行、决定节奏），两者正交。
`role` 也与 `dir` 正交——一条从动矛盾完全可以是 `dir:"up"`（约束比预期更硬 → 价格更高）。

三条硬纪律，细则全在 `13-contradiction-typology.md`：

1. **`role` 两类各 ≥1**。只列一类＝这一章没做完（只有主动矛盾＝不知道会被什么洗出去；只有从动矛盾＝不知道为什么值钱）
2. **主导 = 持有期内时钟最短的那条，不是最重要的那条**。`clock(从动) < 持有期 < clock(主动)` → 你按主动定持有期、市场按从动交易，必被洗
3. **从动矛盾必须走排除链**（13 §2a），把走过的步骤记进 `ruled_out[]`。纪律型是残差，只能最后判，且要过升格三条件

## 4. ★分歧度必须走 research-rag 取证（本章最硬的一条纪律）

**不许凭印象给分歧度。** 每一条矛盾的 `dispersion_basis` 必须来自对语料库的实际检索：

```bash
cd ~/.claude/skills/equity-onepager-interactive
python scripts/rag_query.py <ticker> search "<标的> <该矛盾的关键词> 预测 假设 口径" --top 6
python scripts/rag_query.py <ticker> get_doc <doc_id> --text        # 要全文时
```

检索完按三步落 `dispersion_basis`：
1. **列出每一家给的数**（机构 + 日期 + 原样数字）
2. **算极差**（绝对值与相对现价/中位的百分比）
3. **判形态**（双峰 / 单峰宽 / 零覆盖）

并把逐字原句落进 `items[].ev[]`（`{quote, src, doc_id}`），页面浮窗直接渲。

### 4a. 覆盖密度 `coverage` —— 零覆盖是最高价值信号
`coverage` = **有几家在模型或报告里显式处理了这一格**。
- `coverage: 0` → 页面画**虚线圈**，并在浮窗写「零覆盖」
- **0 家在看 + 数据公开可得 = 性价比最高的 alpha**（不需要预测未来，只需要比别人多读一页财报）

AlphaPai 在这一步的正确定位是**覆盖密度测量仪**，不是观点来源。提问模板：
> 「有没有任何报告或纪要讨论过 X？如果有请给原文；**如果没有任何一家讨论过，请明确回答"没有"，不要推测、不要用行业常识补齐**」

这条提示词纪律实测有效——它会老实答「无」。它答「无」的那一格，就是 `coverage: 0`。

> ⚠️ **一个例外：`subtype:"纪律型"` 的条目不适用本条。**
> 纪律型是靠反事实定义的（能扩、扩了能赚、认证过得去，仍不扩，见 13 §2c），
> `coverage:0` 在这一型上意味着**你在没有任何人证的情况下推断了别人的意图**——那是危险信号不是价值信号。
> 这一型强制 `coverage>0` 且 `ev[]` 必填，且要有**厂商自己的原话**（纪律是九型里唯一会被当事人亲口说出来的约束）。

### 4b. RAG 会推翻你的假设，这是它的主要价值
实测（002371）：原以为「产能瓶颈」零覆盖，RAG 查出长江证券 2026-07-01 明确覆盖了交付能力，
且**结论方向相反**（他们说交付垄断是壁垒，模型说产能是钳制）——**同一事实两个相反解读＝真双峰**，
分歧度从 20 上调到 55，位置从盲区搬到对手盘区。

## 5. 赔率必须走 tornado，不许手估

```bash
node scripts/tornado.js --model _workspace/<ticker>/page_model.json          # 人读
node scripts/tornado.js --model _workspace/<ticker>/page_model.json --json   # 进 part4
```

产出三样：
1. **参数弹性 bar**：每个 `segments[].assume.{q_growth,p_growth,gm}` 在**它自己的锚离散区间**内摆动 → Δ加权市值/现市值
   （锚 <2 个时退化为相对区间并标 `[FALLBACK]`，**这些 bar 只能排序参考，不能当赔率结论**）
2. **取期敞口**：对 `link:true` 的腿沿 `forecast_years` 扫 `year_offset`（PE 折现 n 同步）
3. **弹性传导率**：`link` 腿权重占比。**引擎不活链静态腿**（05 §9.5 的 relinkAll 只在页面 JS 层），
   所以 bar 是**下界**，上界 ≈ 下界 ÷ 传导率。002371 传导率 50%、688521 仅 20%——**必须按上界读**。

### 5a. 取期敞口通常压倒参数弹性 —— 这是普遍规律不是特例
实测：002371 轴A上界 15% vs 取期敞口 **49%**；688521 轴A上界 45% vs 取期敞口 **90%**。
**连有明确盈利、PE 权重最高的标的也一样。** 所以 `part4` 必须有一条「市场定价期限」类矛盾，归**估值层**。

### 5b. 取期敞口 ≠ 范式风险 ≠ 利润预测分歧，三者要分开报
卖方的 PE 法通行做法是「**远年 EPS × 高倍数 → 折现回来**」（实测 688521：高盛 2029E×60x、
某外资 2030E×50x 折现至 2027E）。所以同一个「PE 范式」下，取 2028E 和取 2030E 能差 5 倍以上。
`odds_basis` 必须写清用的是哪一层的敞口。

### 5.5a 先划边界：和开篇章「一段话说清楚」（10）不是一回事

| 形态 | 纯文字＋编号，无卡片色块（10 的硬约束） | 表 + R/M/V 堆叠条，可交互 |
| 用途 | 讲出去、粘备忘录 | 定仓位、设触发价 |

**跨章一致性硬闸**：开篇总结那条主线必须在场景表里有对应行——`summary.main_scenario` 指名某个 `scenarios.items[].key`，
指不上说明两章在讲不同的故事。

### 5.5b 场景不许自由创作 —— 它是「主动 × 从动」的解方向叉乘

第四章的原则是**不新增分析、只重排前三章**，所以场景必须从已有矛盾生成，否则它就变成报告里第二个编故事的地方。

**场景 = 某条主动矛盾的解方向 × 某条从动矛盾的解方向**，剪枝到 3–5 条：

| 主动 | 从动 | 场景形态 | 方向 |
|---|---|---|---|
| 兑现 | 维持 | 超级周期：利润率上台阶 + 范式切换 | 上，赔率最大 |
| 兑现 | 松开 | **量升价崩**（最常见的亏钱方式，也最容易被漏掉） | 下 |
| 不兑现 | 维持 | 阴跌：约束还在但没需求去撞，**没有认错时点** | 下 |
| 不兑现 | 松开 | 戴维斯双杀 | 下 |
| 任一 | **类型切换/绑定环漂移** | 范式重定价（弹性↔纪律、stack 前进一位） | 双向，通常无人覆盖 |

每条场景必须 **`from` 指名**它是哪两条矛盾的什么解方向（`from.active` / `from.passive` 指向 `items[].id`）——
场景表与坐标图因此强耦合，改矛盾会牵动场景，不会各写各的。

> **从动是系统协同型时**（13 §2d），「从动松开」必须细分到**哪一环松**——绑定环、下一环、纪律环各是一个独立场景，
> 赔率与 R/M/V 构成完全不同。stack 结构在这里第二次付费。

### 5.5c 解锁条件按时钟分两层，不是详略关系

- **中期叙事 `story`**（年级）＝**主动矛盾的相位迁移**：从"只能用源领域技术语言说"走到"进了公司披露口径"。观测的是相位，不是数字
- **短期催化 `catalysts[]`**（季度级）＝**从动矛盾当前绑定环的判定事件**：良率数据、认证名单、capex 指引、配额发放、并网批次。
  每条必须带 `when`（日期）+ `watch`（观测量），且**优先 `ref` 引用第二章已有催化**（`part2.catalysts` 的 id），不另起一套编码
- **`unlock[].status`**：已发生 / 进行中 / 未发生

**不给概率。** 概率是拍的，解锁进度是可观测的——与本章全篇的取证纪律一致。

### 5.5d ★赔率不许手写：场景 = 第三章模型的一个存档点

每个场景必须给 `knobs`（一组参数存档），跑引擎得市值：

```
knobs → 深拷贝 MODEL → 按路径覆盖 → EONE.recomputePL() → EONE.runValuation()
      → mcap_yi = blend.mcap → odds = mcap_yi / base_mcap_yi − 1
```

**`knobs` 是路径 → 值的字典，键空间覆盖 P&L 与估值两侧**（估值腿**按 key 寻址，不用下标**，下标会随增删腿漂移）：

```jsonc
"knobs":{
  "segments[0].assume.q_growth": 0.45,        // P&L 假设
  "segments[1].assume.gm":       0.38,
  "splits.<key>":                0.30,        // 拆分滑块
  "valuation.pe.params.pe":        35,        // 估值腿参数（按 paradigm key）
  "valuation.pe.params.year_offset": 1,       // 取期
  "valuation.peg.weight":           0,        // ★范式切换 = 权重重分配
  "valuation.endgame.weight":     0.4
}
```

**下行场景同样必填 `knobs`**（2026-08-14 用户定）。下行常常要改的不是假设参数而是估值范式本身——
**范式切换用 `weight` 表达即可，不需要动估值腿结构**：「从 PEG 掉回 PE」＝ `valuation.peg.weight:0` + `valuation.pe.weight:1`。

`odds_band` 用 `tornado.js` 的**弹性传导率**修正：bar 是下界，上界 ≈ 下界 ÷ 传导率（§5）。

**页面因此得到一个真正的交互**：点场景名 → 第三章滑块跳到那组值 → 估值实时重算。
它也逼你把场景写实——**写不出一组参数的场景不是场景，是感想**。

### 5.5e R/M/V 分解：同一把尺子，一次回看一次前瞻

沿用 `03-part2-price-review.md §2f-q` 的**对数三因子**（R＝收入层、M＝利润率层、V＝估值层，单位 pp，Σ≈涨幅），
从现状算到场景终点。降级链同 §2f-q：一致预期缺→用 TTM；连 TTM 都拆不出→退两因子（ΔEPS→R+M 合并、ΔPE→V，`m_pp` 填 0 并注明）。

**自查**：`Σ(r_pp+m_pp+v_pp)` 对 `odds` 差 ≤3pp，超了说明起终点取数不一致，回查。

**★免费红利 `rmv_check`**：把场景的 R/M/V 与**第二章历史各阶段 `factor_quant` 放同一尺度对照**。
若场景里 V 的贡献超过历史任何一段的 V，必须显式说明靠什么范式切换支撑——这条直接接上开篇总结的「估值范式上界」。
页面在每根场景条下方叠一根历史最强段的同尺度条。

### 5.5g ★概率与期望值（2026-08-14 阳光电源实跑固化 · CK-6 S8）

**赔率没有概率就不是赔率，是情景标价。** 阳光 v3.1 五条 Case 摆着
+77.4 / +56.5 / −15.7 / −12.9 / −18.3，两上三下，`switches[].prob` 全是「—」，
读者合不出一个 EV 来。这是全章最后一公里。

三个数一起摆，缺一个都读不出结论：

| 数 | 怎么来 | 回答什么 |
|---|---|---|
| **我的 EV** | `Σ prob × odds` | 这单按我的判断值不值 |
| **我给上行的概率** | `Σ prob`（dir≠down） | 我押的是哪一边 |
| **现价隐含上行概率** | 令 EV=0 反解 `p_up`：`−下行均值 ÷（上行均值−下行均值）` | 市场押的是哪一边 |

**落点是第三个减第二个。** 阳光按上表填完：EV +20.9%、我给上行 45%、现价隐含 19.4%、
**差 +25.6pp**——这 26 个点就是下注理由的全部量级。差不到 10pp 就没有边际，
这时要么改概率、要么填 `thin_edge_why` 说清为什么还下注（比如赔率不对称、比如仓位是期权型）。

**隐含概率只解一个自由参数**：组内相对权重沿用你自己填的 `prob` 归一，
所以它问的不是「市场怎么想」，而是**「在我认可的上行/下行分布形状下，市场给上行留了几成」**。
这个口径要写进页面，不许简化成「市场认为只有 19% 概率涨」。

`prob` 怎么填才不是拍脑袋——三条：
1. **串联条件要连乘**。「UL 认证 → CSP 首单 → 分部表单列行」三步各 60% 且非独立，
   给 20% 而不是 60%；`prob_basis` 里把步数写出来。
2. **下行不许集体低估**。三条下行加起来低于 40% 的，回去看是不是把「什么都不发生」
   漏成了一条 Case——「叙事延后」这种「不需要任何新坏消息」的路径通常是概率最高的一条。
3. **和解锁进度对齐**。`unlock[]` 里已发生条数最多的那条，概率应该最高；
   排序对不上就是概率没跟着证据走（阳光 margin_fix 已修到 2026Q1 毛利率约 30%，所以给 25% 最高）。

### 5.5h ★历史对照＝跨公司/跨叙事（2026-08-17 石英股份读者反馈固化 · CK-6 S9）

读者原话：「历史对照不是要和自己历史上对照，而是和历史上其他公司或者其他叙事对照」。
scenCard 原来在 R/M/V 条下面画的那根灰条是**本股历史最强段**的同尺度分解（S6 的量纲对照，现已改名「本股历史最强段（同尺度）」，
不再叫历史对照）。它回答「这个 V 在本股历史上出现过没有」，回答不了读者真正要问的：**别家走过这条路时发生了什么**。

每条 Case 必填 `analog{case, period, what, diff, src}`：`case` 是**另一家公司或另一条叙事**（+年份），`what` 写当时的幅度与时长，
`diff` 写与本例的关键差异（≥15 字）——**没有 diff 的对标是装饰不是判据**，与 §6c 的 `core.*.deepdive.analog` 同一纪律。
锚先查 `13 §6` 案例库，没有再走 RAG/AlphaPai；对照的是**范式跃迁那件事**（估值年份后移 / PE→PS / 平台溢价被承认 / 周期股降档），
不是行业相同。上行 Case 与下行 Case 都要有：下行的 analog 往往更有说服力（「多晶硅 2023 量升价崩」比任何形容词都硬）。

## 6. 双槽位核心矛盾（`part4.core`）—— 本章的结论

**核心矛盾有两条，而且结构性地不是同一条。** 实证：赔率与可证伪性负相关（合池 −0.28，
控制可及性后偏相关 −0.05），**赔率最大的那条几乎必然验不了**（14 条高赔率项里最大可证伪性只有 55）。

| 槽位 | 怎么选 | 回答什么 | 动作 |
|---|---|---|---|
| **定价核心矛盾** `core.pricing` | 低可证伪区里赔率最大的那条 | 这只股票**为什么值这个价** | 控仓位 / 要折价 / 画敞口，**不是研究** |
| **可操作核心矛盾** `core.actionable` | 高可证伪区里赔率最大、且**过了证伪**的那条 | 这个季度**该跟踪什么** | 读财报 / 调研 / 季度跟踪 |

两条都必须写 `why`（为什么是它）和 `action`（据此做什么）。**只给一条 = CK-6 不过。**

### 6c. `analog` —— 历史对标是**查表**，不是生成

**为什么必须查表**：让 agent 每次现想对标，它给的永远是最著名的那几个，而且会编数字（同 §10 第一坑）。
锚全部来自 `13-contradiction-typology.md §6` 的单维案例库，按 `subtype` 命中；**命中不了就明写「无同类锚」，不许用行业常识补齐**。

```jsonc
"analog":{
  "case":"多晶硅 2021→2023",
  "pair":"采用/可及型 × 弹性型",                          // 主动子类 × 从动子类
  "then":"装机需求连续超预期兑现，致密料 60→300→60 元/kg",
  "outcome":"量升价崩，龙头股价腰斩",
  "tell":"在建工程同比领先价格拐点 12–18 个月，2021 年即可从投产排期数出",
  "diff":"本例从动是纪律型不是弹性型，点不出第四家边际供给者 → 不直接套用",   // ★必填
  "src":"13 §6b · 硅业分会周报口径"
}
```

**`diff` 必填，而且是这个块的全部价值。** 对标最大的风险不是找不到，是找到了就套用。
没有 `diff` 的对标是装饰；有 `diff` 的对标才是判据——它逼你说清"我这条为什么不会走成那样"，说不清就说明你根本没弄清自己这条是哪一型。

页面渲成一根窄带（案例 / 配对 / 结局 / 当时的 tell / **与本例的关键差异**），放在 `ruling` 判定表之后。

## 7. 叙事链拆解与次级矛盾下钻（4.5 节）

每条 `narratives[]` 要有：

1. **`chain[]` 逻辑链**：从最外层外部驱动（下游 capex / 政策 / 技术节点）一步步推到公司收入或利润，

2. **`weakest`**：整条链**最先断的是哪一环**（点名第几环）、为什么 —— 页面红字高亮
3. **`subs[]`**：这条链上还没定的地方拆成 4–6 条次级矛盾，字段同 `items[]`
   → 页面渲成**明细表**，口径同 4.1.2。从 4.1 主图的该叙事气泡**超链接**跳入锚点 `#nar-<key>`。

### 7a-2. ★叙事链的可读性硬规矩（同一轮反馈）

用户后半句才是要害：「**说的内容也很 ai，即使没有用禁词，也很难去阅读和理解。**」
——**禁词表治不了这件事**。让链读不动的是三种结构性毛病，都可机检：

| 毛病 | 长相 | 判据（`check_part4.js`） |
|---|---|---|
| **一环里没有数** | 「下游需求持续释放带动价值量提升」——四条链可以共用，换个标的照抄也成立，等于什么都没说 | **CK-6f2** 每环 `claim` 必须含阿拉伯数字 |
| **一环写成一段** | 60 字以上就不是「一环」，是把推导过程原样倒出来 | **CK-6f2** 每环 `claim` ≤60 字 |
| **一条链十几环** | 环越多越像在凑传导，真正有关节的通常 4–6 个 | **CK-6f3** `chain.length ≤ 6` |
| **空口标「已证实」** | 证实与否是这一节唯一的产出，不挂原句等于白送结论 | **CK-6f3** `status==='已证实'` 必须有 `ev` |
| **weakest 说不清是哪一环** | 「最弱的是需求端」——没法跟踪，也没法证伪 | **CK-6f4** `weakest` 必须点名第几环 |

写法上再补三条（人工，规范全文在 `buyside-voice`）：
**① 每一环要有主语**——谁做了什么，主体是公司/客户/竞争对手/监管，不是「行业」「需求」这类没有行为能力的词；
**② 不许自造代号**（「环节 A」「链路①的第二跳」这类只有作者知道指什么）；
**③ 上一环的宾语＝下一环的主语**，接不上就说明中间漏了一环或这两环本来无关。

> 结尾零覆盖闸**——写进一个自包含问题里即可，效果与原探针等价。下面 §7b.1–§7b.5 的方法论全部照旧，
> 只是执行方式从「跑脚本」变成「拼一个问题」。
>
> **阳光实测这一步的价值**：一次 challenge 抓回摩根士丹利的 SST 渗透率 15% / 单价 1.3 元/W /
> 份额 20% / 美国收入 10.1 亿，与内资东吴的「远期 160 亿利润」差 4–40 倍——**直接推翻本页原假设，
> 模型据此下修 40%**。它也会老实答「没有」（CSP 自建电源比例、之江实验室订单规模、
> 阳光在 NV 800V 架构中的份额三项全是零覆盖），零覆盖闸是有效的。
> **但它的历史叙述会串日期**（把 2026-04 的年报爆雷说成 2025-04）：只采信 `rival_numbers`
> 与引用清单，**时间线一律回 K 线／公告核**。

**为什么必须加这一层**：用户原话「次级叙事拆解得不够好」。根因是——`subs[]` 靠 agent 自己想，
写出来的永远是**我已经知道的那几环**；而次级矛盾的全部价值在**我没想到的那一环**。
本地 research-rag 也补不上这个缺口：它只覆盖用户给的那一包料（688825 实测 555 篇，
以韭研工社/AceCamp 纪要为主，**几乎没有正式研报的盈利预测表、零篇外资研报**）。

AlphaPai 是一台**卖方共识测量仪**——它读过全市场的研报/点评/纪要/公告/外资研报。
把主叙事和已有的 chain 喂给它，拿回来的是**候选**，不是结论。

### 7b.1 三种探针（各自一次独立调用）

> AlphaPai 是**静态三段式 RAG（Plan→Retrieve→Answer）+ 问题感知检索 + 多轮记忆弱**，
> 所以**一次一个自包含问题**，不要用 `--context` 做多轮细化。

| 探针 | 底层 | 回答什么 | 落到哪一格 |
|---|---|---|---|
| `challenge` | agent mode 9 观点Challenge | 这条链哪一环最先断、反方给的数是多少 | `narratives[].weakest` · `chain[].status` · 新 `subs[]` |
| `decompose` | qa `--mode Think`(Wide Search) | 我没列出来的环节还有哪些 | 新 `subs[]` 候选 |
| `coverage` | recall `--type report,foreign_report,comment,roadShow,ann,qa` | 这一格有几家在看 | `items[].coverage` · `dispersion_basis` 形态 |

```bash
python scripts/narrative_probe.py challenge --ticker 688825 --name 长鑫科技 \
  --claim "2027年归母净利润可达2900亿元，按13倍PE对应3.6万亿市值合理" \
  --concern "DRAM周期高点定价;少数股东权益扣减比例;2028年供给释放节奏" \
  --since 2026-01-01 --until 2026-07-31

python scripts/narrative_probe.py decompose --ticker 688825 --name 长鑫科技 \
  --narrative "存储超级周期" --chain-file _workspace/688825/probe/chain_cycle.txt

python scripts/narrative_probe.py coverage --ticker 688825 \
  --topic "长鑫 DDR位元占比 产品结构 服务器与手机产能分配"
```
产物 `_workspace/<ticker>/probe/<probe>_<slug>.{json,md}`。

### 7b.2 提示词设计（三条硬规则，实测有效）

1. **观点必须带数字**。AlphaPai 是问题感知检索，问题里的数字决定它捞到哪些盈利预测表。
   写「长鑫估值合理吗」→ 捞回一堆定性话；写「2027年归母2900亿、13倍PE、3.6万亿」→
   捞回华西/国金/中泰的逐年预测表。
2. **`--concern` 是第二个检索入口**，塞「这条叙事的关键前提清单」（分号分隔），不是塞情绪。
3. **每条模板结尾都要写死那句零覆盖闸**：「如果某一项在你的资料里没有任何一家讨论过，
   请直接回答『没有』，不要用行业常识补齐」——实测它会老实答「零覆盖」，
   这正是 §4a 要的 `coverage:0` 信号。`decompose` 模板还要求它逐环给
   「(a)机制 (b)谁给了什么数+极差 (c)12个月内能判定它的公开事件」，直接对齐 `subs[]` 字段。

### 7b.3 ★真正的产出不是它的结论，是它引用的别家数字

脚本把 `references[]` 里**含 ≥2 个数字的句子**抽成 `rival_numbers[]`
（机构 + 日期 + 原样数字 + 逐字原句 + URL）。**这才是 `dispersion_basis` 的原料**，
可以直接进 `items[].ev[].quote`。它的 answer 正文只当索引用。

688825 实测：一次 challenge 抓回 **7 家具名机构 / 38 条带数字原句**，
其中 2027E 归母的四个口径（华西 1821 亿、某点评 2055 亿、东北 2800 亿、本模型 2912 亿）
把本页 TENOR 条的分歧从「三家市值口径」补成「四家逐年盈利口径」，
并直接暴露出**本模型比卖方中枢高 42–60%** 这一原先没测出来的偏离。

### 7b.4 铁律：provisional → 复核 → 才进图

脚本在每份产物里写死 `provisional:true` 与 `usage_rule`。**回填三步**：
1. 逐条回 `rag_query.py search/get_doc` 或 page_model 复核（§10 第一坑：数字没回原文核）；
2. 核得上 → 进 `items[].ev[]`／`subs[]`，标真实 doc_id 或 AlphaPai URL；
   核不上 → 丢弃，或降级成 `coverage:0` 并写明检索过什么词；
3. **它推翻你的假设时不要护着模型**。688825 实测：challenge 查出「明年新增产能很多在体外
   ……北京二期、上海一期等很多都已经在体外了」，直接推翻本页
   「少数股东占比随产能摊薄而下降 24.5%→13.7%」的基准假设——那一条只好从「基准」
   降级成「需验证的路径」并单列成次级矛盾。**这就是这一层的价值。**

### 7b.5 什么时候不用跑

标的冷门、AlphaPai 召回 <3 家具名机构时，它的 answer 会开始用行业常识补齐（幻觉高发区）——
此时只取 `rival_numbers`，丢弃 answer 正文。`coverage` 探针返回 `n_inst_named==0` 即
直接落 `coverage:0`，不必再看正文。

## 9. CK-6 闸门（第四章验收）

### 9-S · 4.1 场景（`scenarios`，2026-08-14 新增）
- **S1** 场景 3–5 条，**至少一条 `dir:"down"`**（只有上行场景＝不是投资结论）
- **S2** 每条 `from.active` / `from.passive` 指向 `items[].id` 里真实存在的条目，且方向词已填
- **S3** **每条都有 `knobs`（含下行场景）**，且 `knobs` 跑引擎得出的市值与 `mcap_yi`、`odds` 自洽（容差 ±1pp）；
  估值腿键按 paradigm key 寻址，不许用下标
- **S4** `Σ(r_pp+m_pp+v_pp)` 对 `odds` 差 ≤3pp；`rmv.basis` 写明降级链走到哪一级
- **S5** 每条 `catalysts[]` ≥1，且每条催化 `when`+`watch` 齐全
- **S6** `rmv_check` 已与第二章 `factor_quant` 对照过；V 贡献超历史最强段时写明靠什么范式切换支撑
- **S7** `summary.main_scenario` 指向某个真实 `scenarios.items[].key`（跨章一致）
- **★S8 概率与期望值（2026-08-14 阳光固化，见 §5.5g）**：每条有 `prob` 且 `prob_basis` ≥10 字；
  `Σprob = 100%±2pp`、`prob ∈ [0,1]`；现价隐含上行概率可解；**「我给上行」与「现价隐含」
  差 <10pp 时须填 `scenarios.thin_edge_why`**——差不到 10 个点就没有边际，得说清为什么还下注
- **★S9 历史对照＝跨公司/跨叙事（2026-08-17 石英固化，见 §5.5h）**：每条 Case 有 `analog{case,period,what,diff}`，
  `case` 不是本股自己（不含本股名）、`diff` ≥15 字；本股历史最强段的同尺度条保留但不叫历史对照

### 9-T · 分型（`role`/`subtype`/`clock`，见 13）
- **T1** 每条 `role` 与 `subtype` 已填且取值合法；**主动/从动各 ≥1**
- **T2** `clock` 偏离子类默认值时填了 `clock_override_why`
- **T3** 从动型条目有 `ruled_out[]`（排除链走过哪几步、各步依据）
- **T4** `subtype:"纪律型"` 必须 `coverage>0` + `ev[]` 非空 + `discipline_upgrade_test` 三条齐全带证据
- **T5** `subtype:"系统协同型"` 必须 `stack[]` ≥2 环且 `binding_now.link` 在 stack 里
- **T6** `subtype:"制度/权利型"` 必须填 `sub_right` 五支之一
- **T7** `co_kill` 互指的两条，加总赔率时已扣重复（`odds_basis` 写明）

### 9-D · 深度研究（`core.*.deepdive`，见 §6b）
- **D1** 两个槽位都有 `deepdive`，且 `understanding` / `plan` / `ruling` 齐全
- **D2** `plan.blind_spot` 非空（写明它仍然验不了什么）
- **D3** `analog.diff` 非空——没有 `diff` 的对标是装饰不是判据

### 9 · 原有各条
- **a** 矛盾 8–12 条，每条 `label` 5–8 字、`one_liner` 一句、`detail` 30–50 字带数字
- **b** **每条 `dispersion_basis` 必须有具体数字**（谁给了什么数、极差多少），且至少半数条目挂了 `ev[]` 逐字原句；

- **d** P&L 三层的条目必须填 `hooked`（挂到具体可调参数）；挂不上的归叙事/估值
- **e** `core.pricing` 与 `core.actionable` **两条都在**，且不是同一条；各自 `why`+`action` 齐全
- **f** 每条叙事有 `chain[]`（每步带 status）+ `weakest`+ `subs[]`；4.1 气泡到 4.5 叙事锚点的超链接可点。

  **★ 每条叙事必须跑过 `narrative_probe.py challenge`（§7b），且 `subs[]` 里至少 1 条来自探针

- **g** 图面体检（用 §10 的脚本）：气泡两两不重叠、标签不压气泡不互压、浮窗不越界不溢出底板、浮窗层在最上；
