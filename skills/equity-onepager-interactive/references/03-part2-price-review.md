## 1. 阶段划分（phases）

把周线路径切成 **3–6 个持续性阶段**，每段满足三条硬约束：**≥6 周** · **单一 regime**（一个方向趋势） · **边界有明确转折点**。**阶段间的剧本切换本身是最重要的信号**。

### 1a. 每阶段叙事块（九字段，全填）
| 字段 | 落在 | 内容 |
|---|---|---|
| 叙事剧本 | `narrative` 开头 | 九类标签之一（见 1b） |
| 一句话主线 | `narrative` | 发生什么 → 哪个变量持续改善 → 为什么市场愿加价 |
| 主因子 | `main_factor` | **R/M/V 单选**（纪律：一段只能一个主因子） |
| 次因子 | `sub_factor` | R/M/V，一句话 |
| 估值锚 | `anchor` | PE / PS / EV-EBITDA / EV-FCF / 终局份额 |
| 领先指标 | `narrative` 或 accounting | 1–2 个可量化的先行量 |
| 硬证伪 | `narrative` 或 accounting | 什么数据出来 = 这段逻辑钝化 |

> `narrative` 是一个字符串，把「剧本+主线+领先指标+硬证伪」压进去；`main_factor/sub_factor/anchor` 单独成字段（app.js 给 main_factor 上色）。

### 1b. 叙事剧本九类（label → 外推逻辑 → 典型主因子 → 典型 K 线）
1. 供需缺口双击 — 订单+价格持续 — R(量×价双升) — 顺趋势
2. 周期反转修复 — 利润率谷底恢复 — M(利润率台阶) — 低位收敛→趋势化
3. 产品周期渗透 — 渗透率爬坡 — R(量) — 拉→震荡→兑现
4. 平台渗透扩张 — 用户/时长增长 — R(用户×ARPU) — 阶梯式回撤深
5. 平台变现跃迁 — 变现效率提升 — R→M — 财报验证后趋势化
6. 提价与订阅升级 — 利润+现金流质量 — M(ARPU+留存) — 收敛→主升→高位箱体
7. 效率革命扭亏 — 利润率改善 — M→V
8. 商业模式进阶 — 估值体系重塑 — V(PS→PE/FCF 切换) — 估值先行、分子后验
9. 重资本扩张循环 — 产能×融资约束 — R 但 V 压制 — 大单涨/融资跌交替

### 1c. 三因子纪律
每段 exactly 一主一次。**禁**「收入也好、利润率也好、估值也好」（=无判断）。合法句式：「R 主导 M 跟随」/「M 主导 V 放大」/「V 主导，分子不恶化即可」。

### 1d. 阶段末三条切换信号（放进阶段末尾 narrative 或算账 headline）
- **指标钝化**：上修变小 / ARPU 边际弱 / 利润率上不去。
- **投票钝化**：利好不涨 / 超预期冲高回落。
- **结构破坏**：跌破关键结构 + 回抽不过。

【规则】**两条同现 = 主线进入 price-in 尾声，下段应换剧本**。

## 2. Forward 算账（每阶段 `accounting`）

### 2a. 核心公式
```
市值 = Forward净利润 × PE倍数        （赔率=目标市值/当前市值−1）
净利润严格自下而上 + 桥接，禁"大差不差"加总：
Step A 各板块毛利 = 板块收入 × 板块毛利率
        板块收入 = TAM×份额  或  ASP×出货量×份额
        ⚠️ 用财报披露的分产品/分行业毛利率[FACT]，不用净利率代替
Step B 合计毛利 = Σ板块毛利  →  对财报合计毛利，差>5% 查因
Step C 费用桥（每层带数字）：
        合计毛利 −销售 −管理 −研发 +其他收益(补助)
        = 营业利润 +投资收益/公允价值 +营业外净收入
        −所得税(有效税率×利润总额) −少数股东损益 = 归母净利润
Step D 验算：推导归母 vs 财报/consensus，差>10% 逐项排查
        （常见偏差源：投资收益/汇兑/资产减值/股份支付）
```

### 2b. 隐含 forward 年限
对 FY0/FY1/FY2/FY3 的 consensus 净利逐一算 `隐含PE(FYn)=当前市值÷FYn净利`，取最接近「合理 PE 区间」的 FYn = 市场隐含 forward 年限。
例：市值 500 亿，FY1 20 亿(→25x)、FY2 35 亿(→14.3x)，合理 20x → 隐含 ~1.5yr forward。

### 2c. PE 三档（锚定 4 维：渗透率 S 曲线位置 + 可比 PE + PEG + 历史 PE Band 中枢）
| 档位 | PE | 适用 | 判定要点 |
|---|---|---|---|
| 周期/Sigma | 8–12x | 大宗/航运/重化工/强周期 | 看周期位置非绝对值；利润高点给低 PE、低点给高 PE 或看 PB；用产能利用率替代 S 曲线 |
| 正常中枢 | 18–22x | 稳定增长消费/制造/科技，渗透>30% | PEG≈1–1.5；20% 增速给 20x |
| 高成长 | 28–35x | 渗透<15%、TAM 大、份额快升 | 看 forward 2–3yr、PEG<1 买；渗透<5% 用 PS/EV-Rev |

**渗透率 S 曲线 → PE 档 → price-in 年限**：
```
<5%  导入期  PE无意义→PS/EV-Rev   price in 3–5yr
5–15% 加速期  PE 28–35x           price in 2–3yr
15–30% 成长期 PE 22–28x           price in 1–2yr
30–50% 成熟前 PE 18–22x           price in 1yr
>50%  成熟期  PE 15–20x           当年/次年
```

### 2d. PE>30 三范式（算账前先判，写进 headline）
```
当期PE>30x?
 ├ 范式1 Forward线性：FYn隐含PE<25x → 正常Forward，标"price in FYn"；校验隐含CAGR vs 历史/行业
 ├ 范式2 范式切换：FY3隐含PE仍>25x → 切PS/终局份额/对标大哥；必答隐含终态OPM?终局份额?对标谁?
 └ 范式3 非线性阶跃：FY0→FY1增速 >> FY1→FY2 → 标阶跃机制+阶跃前后PE+核心非线性变量(价格/利用率/渗透/政策)
```

### 2e. 隐含 vs 实测 差异规则
`隐含市值=归母净利×PE` → 对实测市值。**差>15% 必须解释**：实测>隐含 → market 定价更远期，调 forward 年限重算；实测<隐含 → 折价（风险/流动性/治理）。**关键检查：是否漏算某板块（亏损业务也要计入）**。

### 2f. 主涨段 ΔPrice 归因（涨幅>30% 或 ≥12 周的段，写进 headline/steps）
```
ΔPrice = ΔEPS × ΔPE
 起点(e0,m0)→终点(e1,m1)：ΔEPS贡献=e1/e0−1  ΔPE贡献=m1/m0−1  交叉项=gear
 → 结论：R业绩上修≈?% / V估值扩张≈?% / 交叉≈?% → {R主导 / V主导 / RMV共振}
```

### 2f-q. ★每段必填 `factor_quant` —— 阶段涨幅量化分解到 R/M/V（2026-08-12 用户需求固化）

「主因子 R 次因子 M」只是定性；**每个阶段还要给一份可横向比较的量化分解**，渲在 2.2 该阶段列内（三根 R/M/V 水平条，**全部阶段共用同一坐标尺度**，条长跨列直接可比）。

**算法（对数三因子分解，恰好对应 9 维的三层）**：
```
股价 = fwd收入 × fwd净利率 × fwdPE
ln(P1/P0) = ln(Rev1/Rev0) + ln(NM1/NM0) + ln(PE1/PE0)
R_pp = ln(Rev1/Rev0)/ln(P1/P0) × 段涨幅pp     ← 收入层（fwd 一致预期收入变化）
M_pp = ln(NM1/NM0)/ln(P1/P0) × 段涨幅pp      ← 利润率层（fwd 净利率 = fwd净利/fwd收入 变化）
V_pp = ln(PE1/PE0)/ln(P1/P0) × 段涨幅pp      ← 估值层（fwd PE 变化，与 2.1b 曲线同源）
恒等：R_pp + M_pp + V_pp ＝ 段涨幅(pp)（对数分解无交叉项残差）
```
- **取数**：段起点/终点的 fwd 收入、fwd 净利，取 `part1.consensus.years[]` 当时可见财年的财报前一致预期（与 2.1b Forward PE 带同一口径）；fwdPE=当期市值÷fwd净利。
- **降级链**（每降一级 `basis` 里写明）：一致预期缺 → 用 TTM 实际（滞后但可算，R=ΔTTM收入、M=ΔTTM净利率、V=ΔTTM PE）；连 TTM 都拆不出 → 退回 §2f 两因子（ΔEPS→R+M 合并、ΔPE→V），`m_pp` 填 0 并注明「利润率层并入 R」。
- **符号**：跌幅段照样分解（负 pp）；`basis` 必须写清用了哪档口径 + 起终点数字。

**落法（phases[] 每段追加）**：
```jsonc
"factor_quant":{ "ruler":"PE",                             // ★必填，见 §2f-q2
  "r_pp":38, "m_pp":-6, "v_pp":36,                         // 单位=百分点，Σ≈段涨幅(+68%)
  "basis":"fwd口径：收入 58→81亿(一致预期FY1)、净利率 18.5%→17.3%、fwdPE 21x→29x" }
```
app.js `renderPhasePanel` 自动算全阶段共用的 `fqMax` 定尺度；缺 `factor_quant` 的段渲 ⚠️ 提示（CK-2 不过）。**自查**：Σ(r+m+v) 对段涨幅差 >3pp 说明起终点取数不一致，回查。

### 2f-q2. ★★ 尺子选择闸 —— 底部没有利润的段不许用 PE 做 V 层（2026-08-18 用户改制）

> 用户原话：「如果底部没有利润、或者用第一档估值的公司，在底部 R/M/V 归因的时候就不应该再用 PE 了，
> 可以用 PB 或者其他，否则 PE 的扰动就太大了。」

**这不是精度问题，是定义问题。** 三因子分解的每一项都是对数比：

```
R = ln(Rev₁/Rev₀)   M = ln(NM₁/NM₀)   V = ln(PE₁/PE₀)
```

盈利趋零时 `NM→0`、`PE→∞`，**`ln` 在这两处不是「很大」，是没有定义**。
硬算的后果是可预测的、而且每次长得一样：**V 吃掉整段涨幅，R 与 M 被挤成两根看不见的短条**，
读者据此得出「这一段全是估值在动」——而真相通常是**「这一段根本没有盈利这把尺子可用」**。
两句话的仓位含义完全相反：前者说市场在重估，后者说市场当时只能按资产或按收入定价。

**判据（逐段独立判，起点或终点任一端触发即降级）**

| # | 触发 | 说明 |
|---|---|---|
| 1 | 任一端 归母（或 FY+1 一致预期归母）**≤ 0** | PE 无定义 |
| 2 | 任一端 **\|净利率\| < 2%** | 分母趋零，`ln(NM₁/NM₀)` 对微小重述极度敏感 |
| 3 | 任一端 **PE > 150x 或 < 0** | 已经不是在给盈利定价 |
| 4 | 该段市场用的是**第一档估值范式**（PB / 重置成本 / 单位市值法，见 05 §0.5：景气度最差、当期亏损） | 尺子本身就不是 PE |

**降级链（每降一级都要在 `ruler_why` 里写明为什么）**

| ruler | 恒等式 | R 层 | M 层 | V 层 | 什么时候用 |
|---|---|---|---|---|---|
| **PE**（默认） | 市值＝收入×净利率×PE | 收入 | 净利率 | PE | 两端盈利都为正且有意义 |
| **PS** | 市值＝收入×PS | 收入 | **—**（`m_pp:0`，写明「无盈利可拆，已并入 V」） | PS | 收入仍是定价锚：成长股、第四档（PS/高利润假设）公司 |
| **PB** | 市值＝净资产×PB | 净资产 | **—**（同上） | PB | 收入也不构成定价锚：周期底部、重资产、第一档重置成本思维 |
| **EV/EBITDA** | EV＝收入×EBITDA率×倍数 | 收入 | EBITDA 利润率 | 倍数 | 折旧吃掉净利但 EBITDA 为正（重资产扩张期） |

**两条使用纪律**

1. **允许逐段换尺子，但换了必须让读者看见。** 三根 R/M/V 条的全部意义建立在
   「全阶段共用同一坐标尺度、条长可跨列直接比」上——PB 段的 V 与 PE 段的 V **不是同一个量**，
   横着比就是错的。页面已做三件事：每段印**尺子徽章**（含三层的新含义）、全页不止一把尺子时在
   条带下渲一条黄色提示、4.1 场景卡的「本股历史最强段」条上补标尺子。
2. **`m_pp` 归零不许静默。** PS/PB 口径下利润率层无处安放，`m_pp` 填 0 并在 `basis` 里写
   「利润率层在本段无定义（起点归母 −3.2 亿），已并入 V」——**不写就与「利润率恰好没变」无法区分**。

**落法**
```jsonc
"factor_quant":{ "ruler":"PB",
  "ruler_why":"起点 2023-10 与终点 2024-02 两端 TTM 归母均为负（−3.2 / −1.1 亿），PE 无定义；该段卖方一致按 PB 0.8–1.1x 给价，属第一档重置成本范式",
  "r_pp":-12, "m_pp":0, "v_pp":-31,
  "basis":"PB 口径：净资产 86→79 亿（−8.1%）、PB 1.06→0.74x（−30.2%）；利润率层在本段无定义，已并入 V" }
```

**机器闸 CK-8 g5**（`check_charts.js`）：某段 `calibers.ttm.pe` 与 `fwd.pe` **都给了 `na`**（或算出的
起终点 PE ≤0 / >150），而 `factor_quant.ruler` 仍是 `PE` → 不过；换了尺子却没写 `ruler_why` → 不过。
`phase_valuation.py` 会把它探测到的结论落在 `calibers.ruler_suggest` 里，直接抄。

### 2f-s. ★`factor_signature` —— main_factor 单选会把结论压没（2026-08-14 阳光电源固化）

`main_factor` 取「|pp| 最大的那一个」，而 PE 的波动天然压倒 R 与 M。
阳光 v3.1 **六段的 main_factor 全是 V**，这个字段的判别力等于零：

| 段 | R_pp | M_pp | V_pp | main | 真正的形态 |
|---|---|---|---|---|---|
| ② 长熊 | +75.0 | +61.3 | −172.8 | V | **基本面对、标签错**——收入利润率都在涨，市场按光伏 beta 杀 |
| ⑤ 主升浪 | +22.3 | +13.9 | +211.0 | V | **换尺子不换数字**——85% 的涨幅来自 PE |
| ⑥ 下跌 | −7.4 | −11.9 | −22.5 | V | **三因子同负**——量、利、尺子一起塌 |

三段的仓位含义完全不同，`main_factor` 却给出同一个字母。
所以每段再填一个 `factor_signature`（一句 ≤20 字的形态判定），渲在 R/M/V 三条下方：

| 形态 | 判据 | 一句话 |
|---|---|---|
| **基本面对、标签错** | R>0 且 M>0 且 V<0 | 数字在改善，尺子在收——最经典的错杀，也是后来主升浪的起跳台 |
| **换尺子不换数字** | \|V\| > \|R\|+\|M\| 且 V>0 | 涨的是范式不是业绩，要回第四章问「这把尺子还给不给」 |
| **三因子同负** | R<0 且 M<0 且 V<0 | 没有一层在托，通常伴随基本面拐点被证伪 |
| **量升利跌** | R>0 且 M<0 | 卖得多但赚得少，往往是价格战的报表长相 |
| **纯戴维斯双击/双杀** | R、M、V 同号且三者量级接近 | 三层共振，最不需要解释的一种 |

**≥4/6 段落在同一个 `main_factor` 上时，这件事本身就是结论**，必须写进开篇章「核心投资逻辑」：
「这只票的定价 ≈ 尺子，不是数字——过去 N 段里 M 段的涨跌主要由 PE 解释。」
阳光 6/6 都是 V，那么第三章那些量价小数点的精度，对解释股价的边际贡献是很低的，
真正决定赔率的是第四章 `PARADIGM` 那条从动矛盾。这句话不写出来，读者会以为模型精度就是结论精度。

### 2g. `accounting` 落法（3 字段）
`accounting = {headline, steps:[], pe_tiers}`。**渲染语义（现状）**：横向面板每列的正式算账走 `valuations[i].{cap,pe,body,consensus}`（§4e）；`accounting` 三字段是 **fallback**——`core_conflict` 缺时 headline 顶上、`v.body` 缺时 steps 顶上、`v.cap` 缺时 pe_tiers 顶上。两套都写全最稳；算账内容规范如下。
每个数字带 **[FACT]财报 / [EST]卖方或自算 / [I]行业 / [J]进门 / [T]iFind**。示例：

## 3. 催化编码（catalysts）

**逻辑链**：`时间点 → Driver(日期+数字+术语脚注) → G1–G5(1–3码) → 9维扫描 → 主导子维度编号 → R/M/V复合码 → ≤40字summary`。

### 3a. 五大催化剂 G1–G5（★用户口径，取代旧 D/E/S/O/L；第一层，1–3 码/节点，≥1 必选）
| 码 | 名称 | 判定 | 典型出处/例 |
|---|---|---|---|
| **G1** | 数据高增长 | 最近数据**环比明显提速** 或 达 **20%+** 或 **超预期**（比之前预期更好） | 业绩点评 / 月度数据 / 公司交流更新 |
| **G2** | 接到大订单 | 主要针对 **2B 制造**：刚接大客户订单、**进入产业链**（如进特斯拉链） | 大客户导入、多年采购、进供应商名录 |
| **G3** | 有大佬站台 | **卖方强推** / **政策扶持(大佬=国家)** / 行业知名人物站台发言 / **官媒背书** | 生育政策引导、马斯克撑腰、麦角硫因企业家宣传出圈 |
| **G4** | 传播面出圈 | **新增筹码**：① 非消费/跨界研究员开始关注、市场追捧该概念；② 密集行业催化（展会、头部企业超预期进展） | 新消费、机器人概念 |
| **G5** | 公司有诉求 | 发**回购** / **股权激励高目标** / 董事长近期出来交流 / 即将组织大调研(董总出面) / **指引上修** / 之前不交流近期交流频繁积极营业 | |

**要点**：G1–G5 是**催化剂类型**（做什么），与 **R/M/V 复合编码**（打到 收入/利润率/估值 哪一层）正交——每节点先标 1–3 个 G 码，再走 9 维扫描定 R/M/V。旧 D/E/S/O/L 中：财报/业绩并入 **G1**（数据高增长，出现在业绩点评）、叙事并入 **G3/G4**、订单归 **G2**、大佬归 **G3**；新增 **G4 出圈 / G5 公司诉求** 两类。页面 `catalysts[].codes` 用 `["G1","G3"]` 形式（数据键仍用 G 码）。
**★展示纪律（2026-07-21 用户反馈）**：页面上**一律显示原始类型名**（数据高增长/接到大订单/有大佬站台/传播面出圈/公司有诉求），**不露 G 代号**——图例、弹卡徽章、2.3 清单「催化剂类型」列、统计条 全部用 `CAT_LABEL` 原名（app.js 已实现）。纯流动性/回吐类负面节点不属五类，`codes:[]`，清单显示 `—`。
**★每条催化必填 `rationale`（原始材料逻辑推演）**：一小段「原文摘句/数据 → 推论」的推理链（≤80字，带信源角标，材料可信度分层：公司披露>专家纪要>卖方报告>内部段子须注明），渲在 ▲ 弹卡（driver 之下）与 2.3 清单每行下方的 `↳` 小字行。只给结论不给推演 = CK-2 不过。

### 3b. 三层 9 维扫描（第二层，逐维 ✓/—）
核心恒等式 `股价=EPS×PE=(收入×利润率)×(情绪×叙事×筹码×范式)`：
- **[1] 收入**：`1.1 行业量价`（量:渗透/替换/新场景；价:供不应求/升ASP/降价；量价方向一致?）· `1.2 公司份额`（增速 vs 行业?靠产品/渠道/品牌?竞对退出?）
- **[2] 利润率**：`2.1 财报披露`（毛利/OpM/净利同环比?beat/miss?guide）· `2.2 供给侧`（扩产/出清/利用率?原材料成本）· `2.3 供需差`（供不应求/过剩?库存周期?交期lead time）
- **[3] 估值市场**：`3.1 情绪筹码`（VIX/put-call、机构/融资/short、北向/外资/ETF流向）· `3.2 叙事`（政策/展会/大厂/中标/战投/指数纳入；主线vs边缘）· `3.3 板块筹码`（板块成交占比、龙头→中军→补涨传导、ETF净流入）· `3.4 范式转移`（定价框架变?周期PE→成长PEG?估值中枢永久移?可比集合变?）

【落法】`catalysts[].dims` 是 9 维全量对象；**命中的值必须含 `✓`**（app.js 靠 `indexOf('✓')` 判定 hit 并展开详情），未命中给 `"—"`。`lead` 写主导子维度编号（如 `"3.1+3.2+3.3"`）。

### 3c. 复合码 R/M/V（第三层，7 组合判定）
| 码 | 规则（主导子维度落在哪几层） |
|---|---|
| R | 全在 [1]，不含 [3] |
| M | 全在 [2]，不含 [1][3] |
| V | 全在 [3]，不含 [1] |
| RM | 含 [1]+[2]，不含 [3] |
| RV | 含 [1]+[3] |
| MV | 含 [2]+[3]，不含 [1] |
| RMV | [1]+[2]+[3] 三层共振 |

判定原则：多因素常态(命中 2–4 维)；分主导 vs 辅助；拿不准 web_search；**警惕归因谬误**——股价涨≠基本面改善，3.x 驱动的估值别误标 1.x/2.x；标了 R(收入驱动) 则收入增量应能解释市值变化主体。`code` 字段决定散点颜色（app.js 内置色表）。

### 3d. 催化筛选（密度优先，目标 15–25，CK-2 门槛 ≥15）
满足任一入选：周涨跌 ≥3% | 成交额>20 周均值×1.5 | 振幅>中位数×2 | 关键日历事件 | 阶段转折点。术语脚注**内联在 driver 括号里**（例：「光模块(数据中心光电转换器件)出货翻倍」），无独立脚注区。

### 4e-2. ★★ 双口径估值算账 `valuations[i].calibers`（2026-08-16 读者反馈固化，必填）

> 读者原话：「这里不仅要用 TTM 的估值口径算一遍，**如果有的话还要用 Forward 口径算一遍**」。

**先说病灶，因为它比这条需求本身重要——这是 schema 降级的第二个实例（第一个是 company_type 掉回散文）。**
上面 §③ 的规范里其实早就写了「…→PE 档→隐含→**Forward** 年限→ΔPE vs 上段」，
但算账是一坨 **prose HTML（`body` 字段）**：散文里少写一段，**没有任何东西会报错**，
「写了」和「没写」在机器看来一模一样。赛力斯 v3.2 阶段①②③ 的 Forward 腿就是这么消失的——
**而 Forward 数据当时就躺在同一份 page_model 的 `part2.fwd_pe.ciq.rows` 里，阶段① 全程覆盖**。
不是没数据，是没人去拿。**治法与 company_type 从 `{label,note}` 升到 `{title,points[{k,v}]}` 完全同构：
把必答项拆成字段，让「漏掉」这件事本身可被机器看见。**

生成：`python3 scripts/phase_valuation.py --model <page_model> [--q-series <q_series.json>] --write`
（试跑不加 `--write`）。机器闸：`check_charts.js` CK-8 g / g2 / g3 / g4。

```jsonc
"calibers":{
  "numerator":{ "caliber":"Capital IQ 市值（= Forward P/S × Forward 收入，与其 PE 分子同源）",
                "mcap_start_yi":2802.5, "mcap_end_yi":904.4 },   // ★两把尺子共用同一个分子
  "ttm":{ "ok":true, "src":"q_series.json", "q_asof":{"start":"2025-09-30","end":"2026-03-31"},
          "caliber":"按公告日可见的滚动 4 个单季，非期末日（避免前视）",
          "denom":{"rev_start":…,"np_start":…,…},
          "pe":{"start":38.6,"end":15.2,"delta":-23.4},          // 算不出时给 {"na":"…理由"}
          "ps":{…} },
  "fwd":{ "ok":true, "asof":{…}, "fy":{"start":2025,"end":2026},
          "pe":{"start":28.8,"end":31.1,"delta":2.3}, "ps":{…},
          "decomp":{ "d_mcap_pct":-69.0, "d_earn_pct":-71.3, "d_mult_pct":8.0, "lead":"盈利预期",
                     "identity":"市值变动 -69.0% ＝ 前瞻盈利 -71.3% × 前瞻PE +8.0%（恒等式，非估计）" },
          "snap_note":"起点吸附：2022-12-02 → 2022-12-16（CIQ 首个可得日，不外推）" },
  "read":"…两把尺子摆一起该读出什么，见下表…"
}
```

**四条口径纪律**
1. **分子共用同一个市值**（取 CIQ 自己的 mcap = `ps1×rev1`，与它算 `pe1` 的分子同源）。
   共用分子之后，两个读数的差异**只可能来自分母**，才可比。
2. **TTM 分母按公告日可见取，不按期末日**：2023-06-09 那天能看到的最新报告是 23Q1（2023-04-29 公告），
   不是 23Q2。不做这一步就是前视偏差。
3. **窗口外的边界吸附不外推**，实际用的日期写进 `asof`/`snap_note`。
4. **哪一栏算不出，必须给 `na` 理由**（「FY+1 一致预期归母为负，PE 无定义」），不许静默省略——
   「当时根本没有这把尺子」本身就是那一段的定价机制。

**为什么两把都要算（不是凑格式）——`read` 那一句才是产出：**

| 两把尺子的关系 | 读数 |
|---|---|
| 同向且量级接近 | 倍数变化是真的，不是口径错觉 |
| TTM 压、Forward 不压 | 市场在给还没进报表的东西买单（抢跑） |
| Forward 压、TTM 不压 | 预期在下修而报表还没反映——两者里更危险的那一种 |
| 一把能算一把算不出 | 「当时没有这把尺子」＝这一段的定价机制（赛力斯①：两个 PE 都无定义，只能用 P/S） |

**★`fwd.decomp` 是恒等式不是估计**：`市值 ≡ 前瞻盈利 × 前瞻PE`，两边都是 CIQ 当天读数，乘起来就是市值本身。
所以「这一段跌的是盈利还是倍数」在前瞻口径下有**唯一答案**，不像 TTM 口径的 R/M/V 要靠每股拆分与假设。
**两者打架时以恒等式为准**——TTM 的 E 装的是过去四个季度**已经赚到**的钱，拐点上天然滞后。

> **实测（赛力斯阶段⑥，这条闸救回来的结论级错误）**：v3.2 原稿只用 TTM 算，得到「PE 40.9→15.5x，
> 尺子换了，这才是跌 70% 的机制」，并把「PE 失效→改用 PS」一路写进 `summary.thesis` 与第四章从动矛盾。
> 前瞻口径的恒等式说的完全相反：**−69.0% ＝ 前瞻盈利 −71.3% × 前瞻PE +8.0%**，
> FY+1 一致预期从 100.2 亿被砍到 28.8 亿，而前瞻 PE 至今 31.1x 有定义、**不降反升**。
> 也就是说这一段**杀的是盈利预期，范式根本还没切**；TTM 把「盈利塌了」误读成「倍数塌了」，
> 因为它的 E 里全是 2025 年的好日子。**一把尺子算不出自己错在哪，两把才行。**

- `body`/`consensus` = **skill 生成的可信 HTML**（原样注入不转义）→可放 `<br>/<b>/<sup class=cite>`；source 内联标 `[F]财报 /[E]测算 /[R]研报 /[N]纪要`。
- **★散文里的倍数读数必须对得上某一个口径**（CK-8 g4，±20%）。赛力斯阶段① 实证：结构化的
  `factor_quant.basis` 写「P/S 2.70→1.18x」（TTM，对的），而同一列的散文写「P/S 从 1.6x 压到 0.6x」
  （那是 Forward 的 1.73，终点也对不上 0.87）——**同一列里两个数打架，没有任何东西会去对一遍**。
- 算账口径 = §2 全套：Step A 分部毛利(用财报分部毛利率非净利率)→Step B 合计对财报 ±5%→Step C 费用桥→归母(对 consensus ±10%)→PE 档(四锚)→隐含 vs 实测→Forward 年限→**ΔPE vs 上段**(标范式切换/再评级)。RAG 有库时每卡带 `[doc_id]`。
- 与 Part3 区别：**2.2 的算账是回溯**（还原市场当时定价，静态卡）；Part3 是前瞻交互模型，不重复。

### 4g. ★ fwd_pe —— 2.1b Forward PE 带的数据契约（2026-08-12 新增；同日第二轮改制为「时点一致预期」）

**主口径（A 股必跑）：`scripts/fetch_fwd_pe.py` 由逐份券商研报重建时点一致预期**——用户打回原因：FMP 财年快照每年只有一份≈财报前的最终值，整年铺平线=**有前视偏差**，且合成区间/负利润断线；「Forward PE 肯定要历史的预测」。
```
python3 scripts/fetch_fwd_pe.py --ticker <裸代码> --market A \
  --kline _workspace/<ticker>/kline_weekly.json \
  --out _workspace/<ticker>/fwd_pe.json [--lookback 180] [--min-brokers 3]
```
- **数据源**：东财研报原始接口 `reportapi.eastmoney.com/report/list` 的**相对年字段**（每份研报的 `predictThisYearEps/NextYearEps/NextTwoYearEps` + publishDate）。⚠️ **勿用 akshare `stock_research_report_em`**——它把相对年字段错标成固定年份列（2026/2027/2028），老研报的 FY1 整列丢失（实测 603766：43 份老报告仅 14% 有值）。
- **重建口径（连续性两招，脚本已实现）**：① 每周取窗口（缺省 180 天）内**各券商最新一份**研报 → 各自然年跨券商**中位数**（研报未过期前持续有效 → 有覆盖处天然连续）；② **NTM 混合消除财年换挡跳变**：`NTM_EPS = w×FY1 + (1−w)×FY2`，w=当年剩余天数/365；forward+1 右移一年。`PE = 周收盘 ÷ NTM_EPS`。
- **诚实边界**：零覆盖周=当时真没有卖方覆盖；<min-brokers 家标 `thin`（页面渲虚线段+悬浮显示覆盖家数）；EPS≤0 不出 PE；覆盖率 <50% 脚本会提示「该标的卖方覆盖本来就薄」。次年预测缺失退化纯 FY1（`basis:'fy1_only'`，同渲虚线）。
- **★负利润/无覆盖不留白（2026-08-12 用户追加「负利润改成 PS 或者 PB」）**：脚本同步产 trailing **PS**（周收盘×期末股本÷TTM 营收）与 **PB**（周收盘÷每股净资产）——财务摘要按报告期取数，可见日=真实公告日（`--earnings`）或法定披露截止日（1231→次年04-30/0331→04-30/0630→08-31/0930→10-31），**无前视**。页面对 `pe=null` 的周（`pe_gap:'loss'|'no_coverage'`）画替代虚线，`--loss-metric ps|pb` 选口径（缺省 ps；周期底部重资产建议 pb，对齐五档系统第一档）；**替代线走独立左轴**——PE 与 PS/PB 量纲不同，两段不可直接比高低，图注写明切换原因。整条带因此全窗口连续。
